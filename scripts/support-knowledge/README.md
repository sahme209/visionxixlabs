# Bounded offline simulation composition

Ordinary command: `node scripts/support-knowledge/cli.cjs --root ROOT --catalog RELATIVE --version EXACT --audience public --question SAFE`. It always refuses with `catalog_unconfirmed` and exit 1. There is no established genuine editorial authority, clock, current-generation verifier or designated launcher. No caller trust/status/clock object or flag can enable customer results. Internal inspection through this command also refuses. This is an intentional security boundary, not a completed public integration.

Simulation: `node scripts/support-knowledge/evaluate.cjs --root SNAPSHOT --suite RELATIVE_SUITE --sha256 EXACT_SUITE_DIGEST`. The supplied root is the explicit immutable local release snapshot, never an implicit moving worktree. A suite has exactly `schema:1,cases:[{id,input,expected}]`. Input contains catalogPath, context, exact version, audience and safe synthetic question; root is supplied by the evaluator. Expected is an independently specified complete envelope. Stdout reports suite/core-code digests, Unicode identity, actual/expected and pass; nonzero exit on any mismatch. All output is simulationOnly true/customerEligible false. Do not supply real secrets; the heuristic is not comprehensive. No logs/reports are written by either command.

Catalog contract (closed objects; unknown fields rejected): `schema,generation,predecessor,supportedReleases,validFrom,validUntil,decision,members`. Bindings are `{path,sha256}`. Decision binds synthetic decision bytes. Members have exactly `id,revision,version,article,evaluation,manifest,evidence,audience,revoked,supersedes,routes`. Supersedes is null or JSON.stringify([id,revision,version]); all referenced metadata must exist. Article's existing supersedes remains `id@revision`. Evaluation bytes must satisfy the unchanged evaluation schema and article binding; these proposed textual expectations are not an answer engine. Manifest has exactly `version,sources`, matching the article ordered sources byte bindings. Evidence is the complete unique set of article evidence and media transcript byte bindings. Every source/evidence/media file resolves under SNAPSHOT. All catalog members, including superseded/revoked ones, must have valid bytes; missing payload quarantines the complete bundle, never revives old material.

Routes have exactly `id,version,audience,controls,requiredTokens,primary,context,group,incompatible,destination`. Destination has `url,version,fragment`; synthetic URLs use example.invalid and are inert data. Incompatibility identities are JSON.stringify([id,revision,version])+':'+routeId. Controls are exact reviewed article screen/control identifiers; question comparison uses normalized whole token sequence. Token routes require every reviewed token. Every prerequisite/permission/limitation/recovery string must be included among primary/context pointers; a selected step includes its three fields. More than three total components refuses. All distinct top candidates tie, regardless of pointer/group/text equality. Unicode is pinned to Node Unicode 17.0; other runtimes fail closed.

Simulation context has exactly `kind,authority,decisionDigest,generation,catalogDigest,issuedAt,instant,expiresAt,invocation,audience,version`. Kind must be simulation, authority SIMULATED. Dates use UTC ISO milliseconds `.000Z`. These pins are synthetic evaluation inputs, never identity proof, real freshness, globally current revocation or replay prevention. Deterministic replay is allowed only as simulation evidence. A future genuine launcher requires separate verification and design; no production trust constructor exists here.

Focused tests: `node --test scripts/support-knowledge/tests/pipeline.test.cjs`. The fixture factory creates synthetic immutable bytes only in per-test temporary directories, cleaned afterward. Tests read all five actual source drafts without changing them and exercise ordinary CLI refusal. No provider/network/process execution from prose occurs. The existing article/evaluation schemas are loaded read-only using already installed AJV dependencies. This code adds stricter bounded validation without modifying or invoking the older validator (which performs unbounded rereads). Limits: 64 revisions, 1 MiB each declared file (including binary media; conservative), 16 MiB total distinct paths, 128 sources/article, 256 evaluation cases, 512 question Unicode scalars, three output components. No recursive discovery or undeclared source lookup.

Remaining limits: no human/editorial semantic verification, release/media authenticity, authenticated internal user boundary, network currentness, customer activation or full B5 completion. Test evidence demonstrates selected boundary cases, not exhaustive race/adversarial proof. Snapshot files must remain immutable during invocation; byte hashing detects changed bytes, but filesystem-level snapshot locking is outside this local evaluator.

## Round 1 containment and reproducibility boundary

The original immutable-directory instruction was insufficient. Actual snapshot-content reads now run under a macOS kernel sandbox, using fixed `/usr/bin/sandbox-exec` and `/bin/cat`, no shell, cleared worker environment, a 2-second timeout and bounded output. The profile denies writes/network/all file data, allowing only root directory `/` for process startup and the intersection of the exact declared canonical filename, snapshot root and `REGULAR-FILE` vnode type. No OS library, home, runtime, `/dev/fd`, inherited source descriptor or other directory data exceptions exist. Parent filesystem metadata operations and a nonblocking, no-follow pre-open establish identity without reading file content; descriptor/path metadata are checked afterward. The worker opens its own pathname so kernel checks apply to the actual vnode. Inherited-descriptor input is expressly avoided: its existing capability could bypass sandbox path policy.

Only Darwin with functioning sandbox-exec and the tested profile is supported for simulation reads; unavailable/unsupported workers refuse. This relies on a trusted local OS, fixed system executables, Node runtime and installed schema dependencies; it does not claim immunity to privileged OS tampering. The root directory bootstrap permission allows root directory data, not other regular-file contents. Snapshot metadata is readable outside the root for containment checks; outside snapshot file content is not. The reader makes no filesystem-enforced snapshot immutability claim: inside-snapshot replacements are checked by exact byte digests/identity, while outside-content and nonregular reads are kernel denied. Race regression swaps an intermediate directory immediately before worker invocation and asserts zero outside bytes; FIFO replacement returns EPERM without waiting for a writer.

All pointers, primary and context, participate in step closure. Every selected step must contain instruction, expectedState and effect. Missing closure is an integrity refusal; complete closure over three components is unavailable rather than truncated.

Evaluation reports now include implementation identity over core/evaluator and the two actually loaded schema byte buffers, plus per-case observed bundle identity (sorted path/digest/size inventory, total bytes and aggregate digest) and catalog digest even for refusals after catalog read. A selected result validates the complete declared catalog/member bundle; early-refusal identities explicitly list only observed files and must not be interpreted as full validation. The catalog digest transitively binds all declared members/manifests, including those not read on an early refusal. Case ID, expected and actual envelopes remain explicit. Absent catalog bytes are represented by null, not an invented digest.

Saved evidence is under `logs/round-1-red.log`, `logs/round-1-green.log` and `logs/round-1-boundaries-green.log`. These are explicit implementation/test artifacts, not automatic evaluator report persistence. Full focused command: `node --test scripts/support-knowledge/tests/pipeline.test.cjs`. Boundary subset: `node --test --test-name-pattern='kernel boundary|special-file|context step|complete step|16 MiB|256|identity|real drafts|literal safe' scripts/support-knowledge/tests/pipeline.test.cjs`.
