# Desktop session authority and token format

The HMAC verifier previously passed signature strings directly to Node's hexadecimal decoder, which ignores some non-hex suffixes or an unmatched nibble. Four suffix regressions reproduced acceptance of altered representations of an otherwise valid signature. The verifier now requires exactly 64 hexadecimal characters before its existing constant-time byte comparison. Valid uppercase hexadecimal remains compatible. This is canonical-format hardening: it does not mean an attacker could forge a session without the original valid signature. No keys, sessions or role grants are changed.

Twelve token-integrity cases pass, including the original cross-session/key-rotation tests and newline variants. Ten additional owned PostgreSQL cases use the real HMAC verifier, Prisma session adapter, current membership, capability checks and public Free entitlement reads, with only the database binding redirected to the verified private fixture. They cover valid durable reuse, role reduction, admin loss, shared-member removal/unaccepted membership, revocation, expiry, invalid signature suffix, mismatched current billing account configuration and API-key refusal on paired-session-only routes.

The portable runner now executes 50 owned database cases: 13 prior Agent/approval settlement, nine HTTP Agent chain, ten paired-session authority, eight coding admission and ten approval writer guards. The first authority fixture correctly encountered the immutable billing evidence guard when it tried to edit enrollment evidence; the final test changes only isolated service configuration and restores it, never bypassing the guard. Final actual runner passed all 50 cases and removed the owned cluster. No customer credentials, real provider inference, production writes or private production backup were used.

Independent review found no blocker. The real native read-only acceptance and automatic credit settlement were verified separately earlier; these synthetic signing-key/database cases do not replace broader customer workflow acceptance. Exact-source release checks are recorded separately.
