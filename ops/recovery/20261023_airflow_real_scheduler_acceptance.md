# Real local Airflow scheduler and historical-run exclusion

A combined acceptance now starts a private loopback Airflow 3.3.2 engine with one randomly named, tagged two-task no-op DAG, then runs Axiom's scheduler, execution claim, completion persistence and audit against a separate owned PostgreSQL 17 fixture. The provider client and workflow implementation are real. Only database/connection-loader bindings point to these isolated fixtures; the production HTTPS/private-origin validation remains unchanged and is explicitly checked to refuse the loopback URL.

The first actual run reproduced a historical-run bug: Airflow 3 manual runs have a null logical date, and the scheduler selected a successful earlier adapter-test run that predated the new rule. The scheduler now requires a valid logical date, or an observed start time when the logical date is absent, within the rule's lifetime. The final write executor applies the same requirement so older pending actions cannot bypass it. Missing or malformed dates do not establish freshness. Current null-logical-date manual runs with a valid observed start remain supported. Three separate executor regressions reproduced prior acceptance of absent, malformed and stale manual-run start evidence before the fix.

Final actual acceptance passed: one new scheduled occurrence, both real no-op tasks successful, one durable succeeded execution and one completion audit event, historical runs excluded, and repeat evaluation created no duplicate action/run. The underlying 63 PostgreSQL checks and three real low-level engine checks passed. Focused Airflow tests passed 140; nine opt-in database/engine cases are skipped in an ordinary environment, and are exercised by their explicit portable runners. No paid model inference, external cloud action, customer connection save or production database mutation occurred.

The optional `--pg-bin-dir` mode of the Airflow runner invokes the existing database runner with a private owned fixture descriptor. Both descriptors enforce canonical, owner-only paths and exact fixture identity; the Airflow descriptor additionally enforces literal loopback, no URL credentials, known user/version and owned DAG/tag. Each nested operation/test has its own deadline. There is no shorter outer timeout that would kill the database owner before its shutdown block. Both runners write cleanup receipts only after successful resource cleanup, including failed-test paths. Final receipts prove the database cluster, Airflow processes/group/listener and private engine home were removed.

Independent review found no blocker. This proves the observed local scheduler/no-op path. Customer authentication/connection setup, real hosted scheduling, GitHub/cloud actions, atomic provider revocation, deployment recovery and cross-platform installed acceptance remain separate. The earlier exact-rule/credential freshness and conditional schedule-update protections remain intact.
