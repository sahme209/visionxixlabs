# Downloadable Mac package verification

Read-only verification downloaded the current public arm64 `desktop-v0.1.20` disk image and matched GitHub's SHA-256 `71389d31f2cbf85c29511597100409824033b4676df91320d380675254f1b1bc`. Its Developer ID signature verifies, but Apple's stapler validator exits65: no ticket is stapled to the disk image. The new strict verifier stopped there, before mounting. This does not establish whether the app inside that old image is notarized. No installer was executed, modified or republished.

The candidate workflow now explicitly notarizes and staples the outer disk image, requires an Accepted result with a valid submission ID, then validates it. The mounted-image verifier checks container and app signing identity/tickets, app identifier/version/architecture, Gatekeeper notarization acceptance, unchanged package hash and successful detach before returning evidence. It mounts read-only and retains the mount directory if detachment is uncertain. The receipt is uploaded within the same platform artifact. Public signing attestations remain withheld pending actual candidate acceptance; this batch does not manufacture positive release claims.

Sixty-one focused fixture/workflow tests pass, including missing credentials (a failing regression corrected an AND-list shell exit trap), rejected/invalid submissions, failed stapling, missing/ambiguous packages, identity and architecture mismatch, symlink rejection, tampering and cleanup failure. Independent review found no blocker. These tests use synthetic commands, not Apple credentials or notarization. No CI dispatch, actual new notarization submission, signing-secret retrieval, publication or provider spending occurred. Full clean-source validation is recorded separately.

The workflow follows Apple's [packaging guidance](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution) and [notarization workflow](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow); Tauri's [macOS signing guide](https://v2.tauri.app/distribute/sign/macos/) describes its credential setup. A clean-host install and signed credential persistence remain separate acceptance requirements.
