# Customer-owned Terraform plan producer and current-target admission plan

> For agentic workers: use the executing-plans workflow inline after root design approval. No subagents. This is a SOURCE-READONLY proposal, not authorization to run a workflow, provider, CLI, migration or installer.

**Goal:** A currently authorized desktop workspace administrator imports an exact saved plan produced by an independently trusted customer CI workflow, inspects its sanitized summary on the existing selected deployment request, and sees whether its backend/target still matched at inspection. Approval and execution remain unavailable.

**Architecture:** Customer CI owns planning, its backend lock and its own `show -json`; Axiom does not dispatch CI or execute customer HCL/provider plugins. Axiom independently verifies the exact run, reviewed workflow identity, attested binary/show/receipt subjects and current AWS backend/connection facts, then atomically stores immutable evidence through the existing artifact boundary. Existing fixture-v1 artifacts stay fixture-v1. A new customer-v2 binding and linked provenance record are explicitly separate evidence types.

**Stack:** Existing TypeScript/Next paired handlers, React/Tauri read UI, parameterized PostgreSQL optional storage, tenant cloud-v2 broker, bounded AWS/GitHub clients and official offline Sigstore verifier. No new approval engine, reservation ledger or generic kernel extraction.

**Spec/base:** This document is both bounded design and implementation plan; inspected source main `037eacb6fdbb5e4261d755754240400ed328ed94`, with published PR172 `9ab6d65d` treated as a dependency for legacy containment, not modified. Planning reads used the clean published worktree; no repository source/canonical files were changed.

## Proposed customer contract and trust boundary

New `CustomerSavedPlanBinding` has schema `axiom.terraform.saved-plan.v2`, evidenceScope `customer_ci_attested`, tenant/request/current immutable request-version contentHash, environment/profile ID+revision+digest, source repository identity/ref/commit, producer workflow path+exact commit/run/attempt, reviewed toolchain/executable/configuration tree/provider-lock digests, exact binary/show digests, backend identity, connection ID+version, bounded created/expiry timestamps. V1 parser remains unchanged in meaning; dispatch by explicit schema and reject unknown keys/versions.

Backend identity covers account/region/bucket/key/default workspace/expected bucket owner/DynamoDB table and computed lock key. State observation covers exact S3 VersionId, SHA256 of bounded state bytes, lineage and serial, plus observed lock outcome/time. Never use ETag as state content hash or permit bucket URLs/endpoints. Target digest uses existing canonical content hash over ISO/string/number-only independently loaded profile/environment/account/credential identity; no Date-object canonicalization or client-supplied digest authority.

Producer receipt is <=64KiB, and binds all the above plus its exact own-show derivation protocol. Plan <=16MiB, JSON <=32MiB, state <=16MiB, attestation <=1MiB; fail on truncation, redirects, compression/budget/timeout failure. CI and import hash the actual same file bytes. Signed SLSA subjects are exactly `plan.tfplan`, `plan.show.json`, `plan.receipt.json`, with their actual SHA256s. Reject extra/missing/duplicate subjects and mixed run attempts. Raw plan/show/receipt objects stay private in S3; public attestation subjects reveal names/digests, not values.

Trust is the reviewed producer code plus official signed workflow provenance: independently verify exact source SHA, repository and successful workflow_dispatch run/attempt, workflow bytes at that commit against the reviewed producer/template digest, supported direct workflow identity/profile and subject coverage. A signature attests the workflow's outputs, not universal semantic equivalence of arbitrary binary and JSON. The fixed producer code is the component that proves `binary -> its own show`; accepting a user's JSON/hash assertion is forbidden. The trusted sealing adapter accepts only the verified internal result, cannot be called by routes with raw JSON, and uses versioned artifact AAD. Customer plan values never enter logs, audit, DTO or prompt.

## Authorization contract (review revision; no global auth changes)

The existing `resolveRequestDesktopSession` applies `requiredScope` only when authenticating API keys (`lib/desktop/resolveRequestDesktopSession.ts:129-146`). Its paired-session branch instead resolves the durable session and **current accepted workspace role**, enforcing `requireWorkspaceAdmin` and `requiredCapability` (`:174-211`). Paired tokens do not acquire pipeline read/trigger scopes from these route options. Do not invent a read-scoped paired-token escalation, encode new token claims, change the resolver or broaden global auth behavior.

| Route/operation | Existing route option | Paired-session authority | Feature-side constraint |
| --- | --- | --- | --- |
| GET profile metadata, saved-plan list/detail and current-target inspection | `requiredScope: "pipeline:read"`, `allowApiKey:false`, `requiredCapability:"workspace:read"` | Active durable paired device and currently accepted member with workspace:read; no owner/admin requirement for metadata/inspection | Tenant request/profile ownership and bounded reads only; no profile configuration, import or artifact mutation. |
| POST profile configure/revise/CAS/revoke | `requiredScope:"pipeline:trigger"`, `allowApiKey:false`, `requireWorkspaceAdmin:true`, `requiredCapability:"policy:manage"` | Current owner/admin; profile is a policy write, so policy:manage is mandatory | Additionally require current connections:manage for its bound connection, including revocation/CAS. Never accept role/capabilities from request or cached token state. |
| POST import | `requiredScope:"pipeline:trigger"`, `allowApiKey:false`, `requireWorkspaceAdmin:true`, `requiredCapability:"connections:manage"` | Current owner/admin with connections:manage | Import cannot change profile policy; independently resolve current profile, connection and all request/version facts before provider IO and before commit. |

The resolver exposes a single `requiredCapability` option. Check the additional profile bound-connection capability with the existing `hasDesktopCapability(currentRole,"connections:manage")` in this feature boundary; do not add a new global auth API. Recompute **all** required capabilities from freshly loaded accepted membership inside the final transaction for every configure/revise/revoke/import write. Current role must still be owner/admin for mutations, with fresh durable device identity/revocation/expiry and fresh clock. A role/capability captured in the earlier route principal is insufficient at commit. Read detail must likewise suppress any late current-target observation after current session/member/connection authority changes.

API keys with pipeline:read, pipeline:trigger, pipeline:* or * remain denied, regardless of role-like claims in request JSON. Actual-handler tests must exercise the real resolver branch (auth/persistence/provider adapters may be mocked), not mock the resolver to an always-authorized principal and infer route safety. Current non-admin operator/security_reviewer/finance_viewer/read_only sessions, missing/unaccepted membership and revoked/expired/wrong-device sessions must fail before **Terraform feature provider IO or profile/artifact/provenance writes**. Existing auth/session/membership bootstrap/touch semantics are unchanged; do not assert that ordinary authentication performs zero database operations. In-flight demotion/removal/capability loss or device revocation before the final transaction must leave every profile/artifact/provenance mutation uncommitted.

## Actual customer journey (one existing surface)

1. In the existing selected-request Terraform panel, a current owner/admin with policy:manage and connections:manage can configure or revoke a named plan profile using tenant-verified repository/environment/cloud-connection catalogs and bounded S3/lock/producer identity fields. Read-only users can inspect metadata but cannot configure/import.

Axiom only reads this completed run and deterministic `prefix/repositoryId/runId/attempt/` objects.
3. Import verifies provenance and current backend/connection facts and atomically inserts the exact encrypted artifact plus linked immutable producer evidence. Successful response returns artifact identity/sanitized summary only; approval unavailable, execution false. Missing profile/toolchain/trust/backend capability has actionable unavailable reasons, never fixture fallback.
4. Existing metadata list stays metadata-only, with stored producer kind clearly labeled. Explicit detail inspection for v2 checks exact bytes/provenance and repeats current target/credential/state reads. Display **Customer CI plan · backend matched at [time]** or **Stored evidence · current target unavailable/changed**, never unqualified Current/Approved/Ready. V1 still says owned local fixture and never checks/borrows a customer credential.
5. Request/version/session/API-base/profile changes clear old summaries immediately; late list/import/detail results cannot repopulate a different context. Request revision invalidates old evidence; connection/profile revision blocks current-target claims and requires a new producer run against the revised profile.

## Current checks, final fence, failure and replay

- Admission preflight follows the exact GET/POST authorization table above: GET pipeline:read/workspace:read; profile configure/CAS/revoke POST pipeline:trigger with current owner/admin, policy:manage and connections:manage; import POST pipeline:trigger with current owner/admin and connections:manage. API keys are denied on all routes. The paired-token branch enforces current role/capabilities rather than a fabricated token scope. Then resolve exact tenant request/version/environment/profile/repository/installation authority, optional schema/trust/toolchain readiness and rate budget before provider IO. Preserve404 foreign isolation. Do not start CI or send cloud writes.
- Use `withTenantAwsConnection` for the observation credential and an additional read-only verified STS/S3/DynamoDB adapter. Read expected-owner bucket versioning, state VersionId/body+lineage/serial, private artifact versions/encryption metadata, and strongly consistent DynamoDB lock item. The exact allowed AWS operation set is STS AssumeRole/GetCallerIdentity, S3 GetBucketVersioning/HeadObject/GetObject with ExpectedBucketOwner and fixed path-style regional S3 endpoint, and DynamoDB GetItem with ConsistentRead. No List/write/delete/lock mutation operation; no caller or ambient endpoint override. Per-object limits above and96MiB total response budget/30-second parent deadline apply; repeat HeadObject/GetObject version consistency before the final DB fence. Lock held =>423; missing lock read capability/timeouts =>503, never interpreted as unlocked. Existing state is mandatory. No lock acquire/release/delete by Axiom.
- CI producer reads the same baseline state and obtains the normal Terraform backend lock for planning (`-lock=true`, bounded lock timeout); it never uses `-lock=false`, `-refresh=false` or `-backend=false` for customer evidence. It runs plan and own show against immutable files, verifies executable/config/lock/binary before/after, ensures state identity did not change, and only emits a receipt after successful lock release and identity checks. Failure cleanup is CI-owned and does not force-unlock an unknown lock. The builtin local fixture protocol is distinct.
- After download/hash/signature checks, re-read exact run attempt/status/identity, source/workflow/profile/trust facts and current state/lock/role identity. Compare every observed field to producer/profile binding. Remote state must still match the plan baseline. Never recapture a changed target as the original target. Credential disconnect/version/account change discards results.
- Immediately before insert, one bounded Serializable transaction locks/rechecks current desktop session/member and recomputes the operation-specific owner/admin/capability requirements from current accepted membership (using a fresh clock, never principal/token snapshots), request+immutable request version/contentHash, environment, profile pointer/revocation/revision, cloud account+credential version/revocation, repository/install/policy revisions. A mismatch or serialization conflict inserts neither artifact nor producer evidence. The transaction is the final DB fence, not only an earlier route check. No long external network reads while DB locks are held.
- Stable import identity = digest(tenant/request/version/profileRevision/repository/runId/attempt/binaryDigest/showDigest/receiptDigest). Exact replay after fresh authority checks returns the existing record; conflicting duplicate key/subject bytes returns409; concurrent identical imports commit once. Unknown HTTP/DB commit outcome is reconciled by this identity, without relaunching planning. No new quota/reservation ledger or released financial hold exists in this read/import operation.
- Remote state may change immediately after the last read; PG cannot transactionally lock S3/CI/IAM. Report observation time and expiry honestly. This milestone provides no final apply-time lock/fence and no claim of preventing that residual race. Stored validity and current-target observation are separate DTO fields.
- New optional schema absent/partial/drift =>503 bounded unavailable before IO. New-v2 artifact without linked verified provenance =>409 unavailable; legacy pending/text records cannot be promoted. V1 reader remains safe on old installs; no P2022-based adoption. Current-target failure may permit explicitly historical sanitized inspection of valid stored bytes, but never the matched-at-inspection badge; expiry/request-version mismatch still refuses evidence.
