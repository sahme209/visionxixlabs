## Current source and exact gap

`codeProposeRealExecutor.ts:117–141,194–224,256–275` builds initial and refinement messages, resolves the current permitted concrete Gateway model, checks its existing output-bound exclusion, and flattens message contents with `\n\n` and system blocks with `\n`. Refinement includes the original instruction/context, broken patch and validation feedback: it needs its own quote after that complete payload exists. Builder role/cache metadata is not forwarded as a messages array by this coding callsite; do not price a hypothetical multi-turn/cache-discount request instead of the actual text request.

The executor checks `boundedAIInput` but currently discards its returned redacted strings. `AIProviderManager.generateTextWithAdmission` redacts the prompt, and `VercelGatewayProvider` recomputes bounded/redacted prompt and system immediately before SDK `generateText`. The existing aggregate input limit is 128 KiB; output limit is 4,096 tokens, coding temperature is 0.2, and governed dispatch uses one `generateTextOnce`/zero-retry attempt. Current text-admission consumption checks task/org/correlation, not complete payload/model/output equality. Adding an exact coding quote therefore requires both manager-consumption and final SDK checks; an executor-side digest alone is insufficient.

`governedExtractAdmission.ts:56–61` currently supplies `requestReservationCents()` to coding admission: default 1,000 cents. `codingRunReservation.ts` checks current run/stage CAS generation, actor/member/model/policy/cap, then atomically creates the workspace hold and companion. That default correctly refuses under the 500-cent default run cap. Smaller synthetic holds in owned tests are not pricing authority.

`smallSonnetRequest.ts` is a bounded structured-extraction/public-Free protocol, with its own transformed JSON instruction, model, pricing parser, 120-second local TTL and final Anthropic routing/thinking options. `smallSonnet55Request.ts` instead requires a separate raw Messages adapter binding total output including thinking. Neither capability, byte/token assumption, rate, eligibility, Free-only policy, or proof transfers to arbitrary coding. `gatewayModelOutputBoundVerified` is an existing exclusion guard, not a complete pricing/transport qualification registry.

## Recommended first contract

Introduce a **separate**, server-internal coding request/quote/dispatch capability. Do not add a public body field accepting a rate, remaining balance, cheap-mode Boolean, quote JSON, trusted handle, token count or estimate. An authenticated request still cannot mint the actual stage CAS capability. Existing workspace roles, model choice, output/input guards, run policy and repository approval gates stay in force.

The first eligible transport should be narrowly qualified, text-only, fixed-output SDK generation. `anthropic/claude-sonnet-5`, **only when already selected and currently permitted**, is a candidate for validation because source contains the separate extraction example. It is not approved/qualified for coding by this proposal. Never switch a user's model to obtain a quote. Do not enable Sonnet5.5, multi-agent, reasoning, tools, images, streaming, new regions/providers or the raw Messages adapter by analogy. Unsupported selected models refuse quote mode with an availability reason; they do not silently use another model/transport or fall back to the 1,000-cent path after a quote attempt fails. The existing fixed-hold path remains the unchanged default until separately approved quote activation; modes cannot change midway through an original phase.

An eligible contract must bind the actual Gateway model and permitted upstream route. For the candidate above, validating a coding-specific `gateway.only=['anthropic']` plus disabled-thinking SDK option is a proposed routing restriction, **not existing coding behavior**. Confirm SDK serialization and upstream semantics before any activation; no inference that the current logical `only:'vercel_gateway'` pins an upstream provider. If upstream/rate/output semantics cannot be constrained and verified, do not mint the smaller quote.

## Canonical request and one-use boundaries

1. After building the entire initial/refinement payload, resolve the existing current workspace model policy and concrete effective model. Apply the shared existing redaction/input-bound function to the full prompt **and** system. Keep its returned strings as the prepared payload. Do not trim, truncate, remove feedback, rely on only the instruction length, or silently normalize later. Quote eligibility may be narrower than the existing 128-KiB limit; larger requests simply lack a smaller quote, without altering the general input limit. Reject malformed Unicode for this new contract rather than assuming byte/token equivalence.
2. Construct an immutable, versioned envelope: org, original actor, correlation, actual run/stage IDs and durable claim generation obtained from the server-owned opaque claim binding (never caller context strings), phase, stable existing idempotency key, task=`generate_text`, concrete model, exact redacted prompt/system bytes with an explicit absent/present distinction, existing temperature 0.2, exact output ceiling 4,096, zero retries, text-only/no-tools shape, SDK adapter-contract version, upstream/region/reasoning/cache/other billable options. Fixed SDK message serialization and any model-visible wrapper/overhead are part of the transport contract. Do not include JS object identity or arbitrary property order in its canonical digest.
3. A trusted server pricing-reader port supplies bounded raw metadata plus source provenance. Local pure parsing cannot turn caller-supplied metadata into a trusted pricing snapshot. Outside any DB transaction, derive the conservative quote and mint an opaque in-process handle bound to the full envelope and pricing digest/expiry. No prompt/system/code is persisted or sent to a pricing endpoint. Full request digests themselves are internal sensitive metadata, not public telemetry.
4. Reserve under the existing common run lock in the existing serializable coordinator. Revalidate the original CAS capability, scope/current member/model/policy/cap and quote evidence/clock. Derive the amount from the opaque quote; never accept caller `estimatedCents` as production quote authority. Create the exact workspace hold, companion and immutable quote evidence atomically through every legacy/public/v2 branch. Any failure rolls back both. Claim dispatch under the same existing lock and recheck quote expiry, exact envelope/model/options, current authority and funding before moving both ledgers to `dispatch_unknown` and minting one-use manager authority.
5. The manager must resolve `optionsForProvider` first, then consume and delete its handle against the final pinned provider options and complete prepared request binding, not the earlier caller options or only org/correlation. It passes a separate opaque coding-dispatch capability to the actual provider method. Immediately before SDK `generateText`, the provider recomputes the actual bounded/redacted payload/options and consumes/deletes that capability; compare the exact digest, scope, model, output/routing/adapter contract and expiry. Any re-redaction, default selection or SDK preparation drift refuses. No unchanged-digest assumption about repeated redaction, and no new generic `AIRequestOptions` Boolean that skips verification. All later request-affecting mutations are forbidden; the verified values are the values dispatched. **Before the earliest provider branch**, require coding dispatch to be mutually exclusive with **both** existing extraction handles: if `codingDispatch` is present and either `smallAgentDispatch` or `smallAgent55Dispatch` is present, refuse before selecting any adapter or making any SDK/HTTP call. This check must precede the current raw `smallAgent55Dispatch` early return, not live only inside the standard SDK branch; the separately accepted `smallAgentDispatch` must also be excluded. Model eligibility checks alone do not establish this separation. This is an explicit prerequisite for the unimplemented coding quote path, not a claim of a current mixed-handle bug.

Opaque quote use is not stage execution authority: retain the independently minted actual CAS claim. Bind each quote to one run/stage/generation/phase/idempotency key, consume reservation authority once, then consume manager and final SDK handles once. Copying JSON, using another actor/run/phase, reusing a deleted handle or changing a default cannot authorize another SDK call. Process restart loses opaque authority and does not reconstruct a dispatch from persisted quote JSON.

## Pricing evidence, arithmetic and unresolved authority

The existing endpoint-metadata URL pattern is a **candidate future source**, not a fetched/verified contract in this turn. A future reader must use a fixed reviewed HTTPS origin and approved concrete model path, no caller URL, credentials or code in the request, no redirects, a bounded streamed body before JSON parsing, timeout and explicit status/content validation. Validate exact model identity, active endpoint, supported output/reasoning parameters, all possible upstream/region routes, context/output capacity and all billable dimensions. A digest authenticates equality to observed bytes; it does not prove truthful, current, complete provider pricing or a maximum charge.

Pure pricing rules must use exact decimal/integer arithmetic, explicit USD-per-token units and checked safe-integer cent conversion. Reject absent/zero/negative/malformed rates, wrong units/model, duplicate/ambiguous eligible routes, oversized/deep input, unsupported request/reasoning/search/cache/region/tier fees and unknown billing fields. Enumerate and conservatively cover every supported tier/region/cache price; do not assume cache discounts or omit a nonzero request fee. Parser support for an unknown dimension requires renewed contract review, not an ignored field. Prefer a deliberately narrow first schema over claiming all endpoint metadata supported. The first proposed schema requires zero ancillary/request fees; the formula below leaves a term for a separately reviewed future supported fee contract, not permission to accept one now.

Let `I` be an independently qualified conservative total input-token bound for the exact final request **including transport/system/wrapper overhead**, `O=4096` the qualified total output bound, and `rI/rO` the maximum applicable nano-dollar rates. Proposed provider estimate is `P=ceil((I*rI + O*rO + supported_fixed_fees)/10,000,000)` cents. Proposed workspace/run hold is `H=ceil(ceil(3*P/2)*3/2)` cents: the existing 1.5 customer-margin policy plus a separately explicit proposed 1.5 estimation buffer, computed as integers. Both factors and the input estimator belong to the versioned quote contract; copying the extraction formula does not validate them. Do not clip H to 100 cents, remaining run allowance or workspace balance, and do not assume it will fit 500 cents. Nonzero total estimates require at least one cent; overflow or unsupported precision refuses.

Keep the same conservative H as both `PipelineAICallReservation.estimatedCents` and `AIUsageReservation.reservedCents`; do not introduce a second smaller run-only amount. Store P separately as quote evidence. Current run accounting then remains settled **provider** cents plus every unresolved full H plus verified other-stage costs, and refinement fits only if the first full H plus its own newly prepared H fits. The actual provider receipt still settles full cost, customer clipping stays unchanged, and over-estimate cost still records an anomaly and blocks later paid calls. A buffer is not a guarantee against provider overrun.

The extraction example's `4*bucketBytes+8192` input estimate is a **candidate assumption requiring independent qualification**, not a proven tokenizer bound for coding or all models. Body-byte bounds alone do not prove provider token or billing overhead limits. First implementation may test the arithmetic against synthetic fixtures, but must keep production quote eligibility unavailable until the exact estimator/model/context/output/reasoning/routing and metadata schema are substantiated. Sonnet5.5's total-thinking raw protocol cannot substitute for that SDK validation.

Proposed local quote TTL: at most 120 seconds and no later than the pricing snapshot's separately qualified freshness expiry. Bind source retrieval time, local quote time and expiry; validate trusted server time plus DB clock at reserve/dispatch, and server time again at final SDK consume. Future/negative ages, clock skew, stale source, expiry during waits or unverifiable clocks refuse. A fetched-at timestamp/TTL is only a local staleness policy, not evidence that a provider held a price fixed or published a trustworthy update timestamp. Do not invent a provider `asOf`, signed rate guarantee or contractual validity window absent from source evidence.

## Durable evidence and recovery

The current companion has no request/pricing evidence fields. Propose additive `admissionContract` with server-owned values `coding_fixed_hold_v1` (the default for unchanged historical rows) or `coding_request_quote_v1`, plus **nullable** versioned `quoteEvidence` JSON on `PipelineAICallReservation`. Fixed-hold rows require null quote evidence; quoted rows require complete valid evidence. The discriminator records the original contract, not caller authority. Quote/dispatch handles bind that same contract, so removing evidence or invoking the fixed-hold entry point cannot downgrade a quoted reservation; mismatch refuses. Strict server parsing and ownership validation are mandatory; JSON presence is not a trust constructor. Persist only policy/adapter/pricing-schema/estimator versions, exact request digest, model/upstream constraints, payload byte count, I/O bounds, P/H, canonical normalized pricing digest, bounded raw-response digest, origin/model identity and trusted retrieval/quote/expiry times. No prompt, repo content, secret, credential, source body or response text. Historical rows are not repriced or silently backfilled. Pricing data and request digests have separate meanings; both are needed. Retain the same evidence with usage linkage for audit, without duplicate mutable balances or reconstructing an in-process capability.

Quote expiry never frees a durably claimed or pending hold. Before dispatch claim only, an exact proof that **both** rows remain reserved/unlinked/undispatched may use the existing atomic void; released phase history stays consumed. After claim, final-boundary mismatch, expired quote, SDK/write failure, timeout, crash, missing usage or lost response conservatively retain `dispatch_unknown`/pending exposure. No auto-requote, changed idempotency key, automatic phase replacement, new nonce, refund, expiry release or second SDK attempt. A validation failure before any reservation creates no financial row and does not itself constitute a paid attempt; this proposal adds no automatic retry scheduler. Refinement is the existing separately bounded phase after a fully accounted response and existing parse/apply decision, not unknown-outcome recovery.
