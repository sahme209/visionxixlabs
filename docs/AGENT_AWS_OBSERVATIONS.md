# Governed Agent AWS observations

This capability reads actual scoped AWS enrollment data through the paired desktop Agent. It does not enable the legacy Agent scanner or deployment execution.

## Customer path and authority

An authenticated paired user opens an existing Agent conversation and asks to inspect an enrolled AWS account. An administrator must explicitly include `list_cloud_accounts` and `read_aws_inventory` in the enabled workspace Agent identity allowlist; registration does not grant those tools automatically.

The Agent can resolve the workspace's scoped account IDs with `list_cloud_accounts`, then call `read_aws_inventory` with the selected connection ID. Ambiguous account selection must be clarified. Neither tool accepts organization IDs, device IDs, credential references, role ARNs, regions or credentials from the model. The messages route supplies its verified paired session/user/workspace context. API keys remain excluded.

The adapter checks accepted membership and the durable device session, then uses the existing scoped enrollment inventory service. The service decrypts only the tenant/account/version-bound vault value and validates actual broker-assumed AWS identity before a bounded EC2 read. Connection metadata, credential version/revocation, device and membership are checked again before returning evidence. Agent allowlist revocation after the cloud read stops further model steps. Failures produce fixed-code errors, never fallback credentials or sample inventory.

## Observation contract

Results use `BoundedAwsObservation`, not `CloudSnapshot` or `NormalizedSnapshot`:

- Actual returned EC2 instance IDs, states, types and availability zones; at most five instances from one page in the enrolled region.
- Server-owned connection ID/version, observation timestamp and `source: live`.
- Mandatory incomplete coverage; truncated-page evidence where returned.
- Costs, utilization, backups, other regions and other resource types explicitly unknown.
- `authority: observation_only`; no fabricated vCPU/memory values, zero-dollar bills, backup flags or account-wide health assessments.

An empty page does not establish that the account is empty. Comparing bounded pages cannot establish deletion, missing Terraform resources, regional loss or drift. The legacy normalizer, cost-signal engine and drift pipeline never receive this observation.

After a successful inventory read the current request is report-only: the decision loop refuses same-turn write proposals and adds a coverage notice to final responses. This restriction does not permanently downgrade the conversation. A later operational request must independently establish its target, reviewed plan, policy and approval evidence through existing boundaries. Historical observations are persisted with explicit provenance and their original time; they are not refreshed identity, execution or approval evidence.

Model-generated explanations remain probabilistic. The runtime enforces the typed limits, unknowns and write-proposal prohibition; it does not certify every sentence generated by a model as factually correct. Provider/model selection, workspace opt-in, credit checks and usage reporting remain at the existing governed AI boundary.

## Validation and acceptance limits

Regression tests exercise trusted-principal wiring, explicit allowlisting, denied/expired device and membership access, strict tool arguments, scoped metadata, disconnected/replaced credentials, late authority changes, provider errors, malformed evidence, empty samples, report-only enforcement and later independent proposals. Provider calls are mocked; no AWS, model-provider or production operation is performed by these tests.

Real customer acceptance still requires an approved database target and enrollment schema, working production authentication/pairing, an entitled test workspace, explicit Agent/provider/credit policy, and an existing separately authorized nonproduction AWS role. Record actual STS/EC2 results, governed model usage and audit receipts; disconnect must prevent later and in-flight stale reads. Approving this code does not authorize database migrations, IAM/trust changes, production data changes, live billing, or cloud execution.
