# Concrete native ingress to the same private consumer

Design only; no source, test, OS/SDK call, service, build, key or provider action. This refines the existing `compiled-consumer-authority-bridge/process-placement-and-request-channel.md` six-operation design and current private-handler unit. It does not replace its placement, custody or genuine user authorization requirements.

## Roles and fixed source seams

- `native/origin_broker.c`: preserve `handle()`'s exact start/observe/begin/ack/live key counts and existing begin/ACK/live state machine. Do NOT pass business envelopes to that parser. Add a distinct fixed request-listener/bridge implementation for the already proposed `com.visionxixlabs.axiom.issuer-request`, owned by this broker epoch. It accepts desktop data requests, not startup or policy decisions. Registration/plist/System access policy remains part of later exact installation review.
- The broker authenticates each actual desktop message using the existing per-message `SecCodeCreateWithXPCMessage`/code-requirement pattern (not a claimed PID or bundle field). Match the approved desktop requirement; the precise selected installed requirement must be bound in the source packet rather than invented here. That proves allowed native sender only. The opaque paired credential still reaches Node's actual codec/session/member/capability checks; signature is not user/org/reviewer identity.
- `native/origin_session.c/.h`: preserve the private origin connection, nonces, owned SELF and fresh liveness assertions. Prepare a SEPARATE typed business message namespace on the EXISTING retained origin connection; no second child listener or caller-selected endpoint. Broker sends a dictionary with fixed `protocol:axiom.issuer-owned-request/1`, native id, epoch, absolute deadline and envelope bytes to its consumed `slot.peer` connection. Child replies on that same retained connection with only protocol/id/epoch/status/response bytes. Before the existing origin `handle()` dispatcher, route only this exact protocol to a separate strict business parser; all original origin op/key rules remain unchanged. Child event handler accepts this exact broker-authenticated namespace instead of invalidating every event; all other events still revoke. Binding uses the consumed epoch, original still-owned unreaped child and native authenticated connection. No client supplies an endpoint, child PID, epoch, root, challenge or credential supplier. Actual support for unsolicited bidirectional messages on this exact retained connection must be qualified; it is not claimed from the current source alone.
- `native/origin_guard.c`: current two frozen zero-argument exports are insufficient for delivery. Proposed new tightly typed native data methods are captured only by canonical main: `nextRequestEvent()` (one pending native Promise, data events only), `completeRequest(id, responseBytes)` and `assertRequestCurrent(id)` (bounded synchronous assertion, no authority return). No caller callback, resource getter, path/URL selector, replacement verifier or digest input. The id selects only a native-created outstanding request, never creates one. This changes the addon interface and needs explicit design approval; canonical export remains only the existing issuer reader.
- `index.cjs` captures those exact frozen native functions after fresh constructor/module checks. It owns the one event loop and private bootstrap lifetime. `privateReleaseMergeBootstrap.ts` exposes its fixed data dispatch only to that lexical lifetime; `privateReleaseMergeRequestData.ts` remains the sole six-operation decoder. Never return graph/repo/vault/keys/coordinator through IPC or public canonical exports. No legacy global handler or localhost fallback.

## Explicit data and state machine

Desktop input stays the existing 4096-byte fatal-UTF8/duplicate-key-rejecting envelope with protocol, one of six operations, requestId, planId, authorization and body. Node maps only the fixed existing routes, headers and strict nested schemas. Native treats it as bounded secret-bearing bytes, never logs/echoes authorization. Responses retain 262144-byte cap and fixed bounded unavailable/unknown statuses without secret diagnostics.

Proposed first implementation deliberately accepts ONE outstanding business request per native epoch and zero queued requests. Reject excess busy before copying payload. A request may own at most 4096 input bytes and 262144 response bytes plus bounded fixed metadata. This is a throughput limit, not a new security authority; it avoids inventing an unbounded scheduler. Origin challenges retain their separate native/control queue and 250ms bound—never hold existing `Peer.busy`/control worker for a 25s business request or block the current-origin probe behind it.

`absent -> admitted -> dispatched -> completed | cancelled | expired | unknown` is terminal per native-generated id. Before admitted: check exact desktop message sender, current epoch/owned child/origin binding, payload cap and available slot. Store an absolute monotonic deadline: min(25s execution or 10s history, remaining valid runtime deadline), never renew startup/slot deadlines. Native normalizes no user role/approval. After dispatch: only the exact owned child connection may complete that id once, with unchanged epoch and within deadline/response cap. An old id cannot create work or be reassigned; late/duplicate response is discarded. Release bytes and terminal slot only after outstanding native/JS references are drained; do not interpret slot reuse as replay permission.

The child receives `request`/`cancel` events, not arbitrary XPC dictionaries or executable callbacks. Each native event is accepted only after actual broker-message identity and captured epoch/connection checks; the bridge never accepts independent same-signed Node as the owned consumer. Native event delivery uses its private queue plus bounded N-API main-thread notification; origin sync assertion remains independent of the JS loop. Implementation must handle wakeup/cancel races and teardown exactly once. This is a specified mechanism to test, not an already qualified OS primitive.

## Cancellation, deadlines and final send

External transport cancellation is correlated to a native-created outstanding request and its ORIGINAL authenticated desktop connection; only that connection may cancel its own live request. Correlation data never admits a new request or selects another connection/epoch. Disconnect cancels only work owned by that connection. The six-operation `cancel_execution` remains a separate durable business action with its existing session/approval/version rules, not this transport cancellation. Broker interruption/cancel/deadline atomically marks that request ineligible in broker state and emits one cancellation event. Canonical JS owns an AbortController for that native id, combines it with the adapter/handler deadlines and aborts it on cancellation. Broker loss/owned-child exit/native-origin failure revokes the whole epoch and all requests; ordinary request cancellation alone does not reset or globally revoke the origin slot.

A JS signal alone is insufficient when cancellation arrives while JS is blocked. The request's final trusted transport wrapper must call the privately captured `assertRequestCurrent(id)`, then the existing native-derived issuer/current authority/expiry checks at the sole final-submit seam. The assertion performs a FRESH request-scoped broker exchange on the existing authenticated native lane with a new private native nonce, exact admitted id, consumed child/current connection and epoch. Broker serializes that exchange against cancellation/terminal transitions and checks its own outstanding state and monotonic deadline, then the native side authenticates the actual reply, exact nonce/id/epoch and deadline. A cancellation already admitted by broker before this arbitration MUST refuse even when its asynchronous event has not reached JS or the child; child cancel-cache plus an ordinary origin-live check is insufficient. Timeout, malformed reply or broker/currentness loss refuses without reconnect/retry. A later cancellation can still race an already arbitrated effect; no atomic remote-effect guarantee is claimed. This request-specific guard is constructed inside canonical/bootstrap lifetime from its native-created request, never supplied by desktop data. Trusted per-request composition invokes it before claim, credential exposure and final submission; client envelope fields cannot replace or disable it. Keep ordinary origin assertion separate: origin-live proves current epoch/owned child, not current request eligibility. Existing final transport/store logic remains the real executor. Recheck abort/deadline after every awaited native/DB/provider preflight and after a synchronous challenge returns. Provider I/O stays outside database locks.

There remains an unavoidable race after the final check and a remote effect. Do not claim cancellation rolls back a submission. Once a durable claim/intent exists, disconnect, late response, timeout or process loss preserves original consumed/unknown history. No reconnect dispatch, auto-retry, automatic fresh plan or resend; recovery reads the same saved operation through the existing no-provider history path.

## Lifetime and finite source acceptance

Canonical close first closes admission, invalidates native outstanding eligibility, aborts JS work, drops dispatch/graph references and disconnects resources once; pending wakeups cannot resurrect a lifetime. Broker teardown cancels only confirmed-owned requests/child and preserves cleanup uncertainty. There is no service adoption or epoch reset to rescue an unknown action.

Finite local tests: strict separated origin/business parsers; exact sender-vs-user distinction; one-slot overflow; changed/foreign/expired epoch/child; request/cancel/complete ordering and duplicate reply; JS-blocked native cancellation before final send; timeout budget after assertion; oversize response; native failure/close/late wakeup; composed six-op path into actual private handler with simulated rows/provider and no global fallback. Tests may mock OS boundaries locally, but cannot establish native authentication, custody or SAME-compiled-consumer qualification.

Later actual qualification must prove this exact registered listener/lane, actual message code identity and owned SELF, cancellation/final-send races and actual emitted canonical dependency/cache against the original matrix. Installation/material provisioning/native readiness, protected resources, runtime identity, custody/fleet/drain/enrollment and full workflow coverage remain separately closed. No new hostile-kernel or compromised-trusted-native guarantee is introduced.
