1. **Hardened Runtime.** Apple describes system-enforced restrictions and entitlement-based exceptions, warning that exceptions remove protections. This supports proposing no exceptions for our non-JIT custodian; it does not qualify our image or Node. [Apple: configuring the hardened runtime](https://developer.apple.com/documentation/xcode/configuring-the-hardened-runtime).
2. **Library validation.** Apple's default admits Apple-signed or same-Team-ID libraries. Retaining validation therefore cannot establish Axiom's exact dependency/process boundary by itself. Disabling it broadens loading further. [Apple: disable library validation](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.cs.disable-library-validation).
3. **Shipping/debugging.** Apple says `get-task-allow` can permit injection and should be removed for shipping. Notarization requires appropriate Developer ID signing and hardened runtime; secure timestamp generation needs network access. These are future distribution prerequisites, not authorization to sign or notarize here. [Apple: notarization issues](https://developer.apple.com/documentation/security/resolving-common-notarization-issues).
4. **Code identity.** Apple distinguishes on-disk `SecStaticCode` from running `SecCode`, with separate static/dynamic validation. A static object cannot enumerate or control its originating processes. A disk-signature result therefore cannot replace our owned running-instance proof. [Apple: code signing services](https://developer.apple.com/documentation/security/code-signing-services).

## Design consequence, not a security certification

Propose a protected, non-JIT native custodian without runtime exceptions, plus a complete immutable dependency/launch contract and actual running-instance checks. Keep Node's interpreter/JIT profile separate and unresolved. Every proposed capability still needs exact-image and supported-OS qualification. These four pages do not prove absence of all injection, debugger, library or same-code-host paths; effective item policy, installed principal/Keychain identity, legacy withdrawal and full Governance remain open.

No native/API invocation, signature inspection, signing/key access, account/service/installation, Keychain item, database/provider action, inference, deployment or spending occurred.
