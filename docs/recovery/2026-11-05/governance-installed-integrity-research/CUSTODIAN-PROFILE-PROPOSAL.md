This proposal concerns the native custodian and its maintenance writer, not the customer desktop app or Node interpreter.

## Proposed profile and exact remaining evidence

1. **Separate identities.** Keep the fixed root-owned synthetic generation/app/broker paths already selected. Bind a separate maintenance writer and non-root custodian; never link the privileged writer into the broker. Distribution is proposed to use a specifically reviewed Developer ID Application identity for executable code, with no ad-hoc/unsigned substitution interpreted as shipping readiness. Actual identity/certificate selection and use remain unauthorized here.
2. **Native runtime.** Propose Hardened Runtime for the non-JIT custodian, without runtime exception entitlements. Exclude JIT, unsigned executable memory, DYLD-environment allowance, disabled library validation, disabled executable-page protection, debugger and get-task-allow requests. Reject unknown or newly injected entitlements rather than accepting an unreviewed exception. This is our proposed narrow role policy, not a claim that flags eliminate every attack.
3. **Dependency closure.** Inventory the complete actual native load-command/dependency graph, including architecture slices, weak/reexport/upward dependencies, loader variables and search paths. Admit only reviewed fixed system dependencies and any explicitly selected immutable package inputs. No plug-in entry, user-writable resolution root or team-wide acceptance shortcut. Library validation remains enabled, but its broader Apple/same-team admission is not treated as this inventory or as exact authorization. No artifact has passed this requirement yet.
4. **Running instance.** Preserve loaded-file/native owned-child/audit-token relationships and static-versus-running validation separately. The actual supervisor, each native helper and child consumer must be bound to the same reviewed protected installation and fresh process epoch. A valid file signature, manifest, path, PID, Team ID or opaque claim alone cannot create that relationship or enable supply.
5. **Installed resources.** Preserve root/operator trust assumptions, protected no-alias generation files, genuine dedicated principal/System-Keychain identity and serialized administrative changes. Real effective policy must deny different-code/Node reads and modifications; copied genuine code must be denied or mandatorily refuse before reads under the existing composed boundary. No source profile substitutes for real supported-platform evidence.
6. **Node stays separate.** Do not copy a GUI app's entitlements, weaken the native custodian for Node's JIT, or infer a qualified interpreter from library validation. The exact pinned interpreter/addon/private compiled consumer, loader closure, same-artifact matrix and claim/credential/final-send behavior retain every existing acceptance requirement. No Node exception profile is chosen by this proposal.
