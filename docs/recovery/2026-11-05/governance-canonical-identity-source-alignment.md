# Canonical identity: correct the qualification sequencing

Source baseline d805a003. Design/source adjudication only; no runtime code or execution authority changed.

## Correction

The November3 `xpc-origin-local-unit/canonical-integrated-next-unit.md` already specifies the actual positive mechanism: the canonical main owns private lexical state after fixed main/loader/cache checks, verified read-only closure, fresh authenticated native construction, and the captured native zero-argument current-origin assertion. Every subsequent identity read rechecks the actual main/cache/native instance and current native origin. Its package digest names that observed executing closure; the digest does not initialize it.

The positive/adversarial SAME-compiled-consumer tests qualify this mechanism. They do not create a runtime credential or provide an earlier successful receipt that the mechanism must consume. Requiring such a receipt before implementing the positive branch would invent a circular dependency and an unsupported extra authority source. No test-only digest, qualifying flag, copied descriptor or alternate executor is necessary or acceptable.

Earlier connected-consumer notes that call the exact positive mechanism an unresolved architectural bootstrap problem are superseded on this point. The current implementation is still genuinely closed: canonical main's observation is always unavailable, issuer types expose no positive variant, merge issuer always throws, supplier/owner readiness is false and no business channel is mounted. Those are implementation and operational-acceptance gaps, not proof that the selected architecture lacks an identity mechanism.

## Concrete retained contract

1. **Runtime identity:** canonical lexical state is initialized only by the original actual protected/owned startup. A future discriminated current-instance variant may describe that executing artifact. It must not imply a user action, policy, fleet, legacy or enrollment grant. Public imports/custom mains/workers/cache substitutions cannot initialize it.
2. **Currentness:** every outward boundary reads identity through the same actual cached canonical module and captured native function. Fresh native failure, changed image/module, deadline, origin/owner loss or interruption permanently revokes that epoch; no reconnect or receipt-based rearming. Observe identity before/after the relevant awaited work and immediately at the existing final send/credential/claim seam, within existing time budgets.
3. **Business permission:** the real private handler/coordinator independently resolves current session, membership, entitlement, saved source/operation, genuine review, policy/baseline, one-attempt claim, credential lease and drain/fleet. Identity success cannot skip any of these. Unqualified uncovered families and activation remain refused.
4. **Qualification evidence:** execute the original finite positive/adversarial matrix against the SAME emitted private consumer and protected native runtime. Actual origin/custody/canonical identity cannot be mocked in the positive vertical; provider/credential responses may be simulated under the original reviewed scope. Failed/unknown rows remain preserved and tests never issue authority themselves.
5. **Operational scope:** trusted installation/principal/item-policy and source/resource protection are required actual facts; placeholders, root-owned files alone or successful static signatures are insufficient. Existing System/Keychain/provisioning/launch action approvals remain separate. Production key/resource withdrawal and legacy/fleet cutover remain separate as originally required.
