### 2. Fixed external native caller and one-use PRIVATE token handoff

Extend the existing signed AxiomIssuerController source with a separate fixed qualification branch, rather than adding an arbitrary client or seventh business operation. It remains an out-of-process caller of the actual request listener. Its actual selected signature requirement is the fixture profile's desktopRequirement. Do not claim an existing GUI route already calls XPC.

The controller consumes ONE private anonymous-pipe frame: eight-byte magic AXQAUTH1,32ASCII generation bytes, uint32BE payload length capped65536, then duplicate-key-rejecting UTF8 JSON with exact fields tenant/requesterToken/reviewerToken/scenarios. Tenant is the fixed fixture workspace, tokens carry only the two fixed session ids/current64hex HMACs, and scenarios is a source-declared list of at most64 case/request/plan/version entries; unknown fields/cases/extra frames/trailing bytes refuse. EOF and the original run deadline are required before accepting the frame. This conveys only generation, opaque fixture credentials and a finite schedule, not a key or source selector. It exposes no token getter, mint endpoint, SQL, actor selector or arbitrary HTTP proxy. It keeps both startup/control and request connections until completion/terminal close, authenticates actual broker replies, sends only the original six-op envelope and connection-bound transport cancellations, and records only allowlisted case ids/status/counts. All response/credential buffers stay private; no raw envelope/result logs.

Concrete issuer for this frame: the fixed producer, while holding its already delivered private session material and actual synthetic DB instance, invokes the actual private codec after seed/scenario setup. A separately inherited fixed fd3 (not argv-selected) carries the bounded credential/schedule frame to its trusted maintenance/harness owner; stdout remains the existing phase protocol. The owner hands that frame only to its confirmed-owned fixed controller through the paired private pipe, after fixture provisioning is confirmed. No root key is exported and no credential is obtainable through a public request. This is a NEW bounded fixture-credential delivery boundary requiring explicit design approval; it is not implied by current phase-only stdout.

The native parent MUST concurrently drain BOTH the existing stdout phase stream and new fd3 authorization stream while the producer is alive, using bounded incremental reads under the original60s IO deadline (and later outer native-call controller). Never assume pipe capacity can hold64KiB or wait for phase2/reap before reading fd3. Hold the complete frame privately, require final phase2 + normal exit of the still-owned child + exact EOF on both streams, then successful original item/locator provisioning, BEFORE releasing any credential frame to the controller. Extra/trailing/slow/overflow/reap-unknown results stop without handing off or retrying; buffers are wiped on every failure.

The later operational packet must bind which non-root process owns the controller and those exact inherited endpoints, actual code requirement, lifecycle and cleanup. No guessed OS user, public Unix-socket pathname, arbitrary recipient PID or unsupported privilege-drop API is selected here. The source unit prepares fixed frame/parser/handshake/state logic and mock ownership tests; actual spawn/descriptor/principal qualification is a separate gate, not assumed from a matching signature.
