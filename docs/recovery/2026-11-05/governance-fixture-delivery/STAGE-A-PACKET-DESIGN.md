## Deadlines, environments and ownership — keep existing limits honest

Use one orchestrator monotonic **active budget360s**, refuse to start a phase without remaining budget/cleanup margin, pass at most120/120/60 to its existing phase supervisors, and reserve attempt/result before the first process. A fixed outer held controller may use390s ceiling plus at most5s original-child cleanup, with terminal unknown on overrun. This is a declared stop policy, **not** a proof every synchronous OS/file/Git call is interruptible. Existing `git_bytes` individually invokes sandbox-exec/Git with60s timeout and may be called repeatedly by source checks; those invocations are explicitly part of this same bundle, including A1/A2 pre/post checks. No sandbox call occurs in ordinary preapproval preparation.

Do not assume an outer process group owns all descendants: `execute_generation` creates a new session for each supervised Node child. Give its existing inner supervisor enough remaining budget/cleanup margin before an outer ceiling; if an outer controller dies or cannot confirm inner cleanup, preserve the entire stage as **unknown**, make no success/quiescence claim, never signal reused numeric groups, delete/adopt it or rerun it. Existing helper post-reap descendant status stays unavailable. A normal known inner command failure stops before the next phase.

Environments must describe current behavior precisely. `install_offline.clean_environment` replaces its child env with PATH/LANG/TZ/TMPDIR/skip-autoinstall/Next-telemetry settings; it does **not** inherit a private HOME or CHECKPOINT flag from the wrapper. Its fixed offline/no-audit/no-fund/no-updater/config flags plus the inherited outer kernel policy provide the selected boundary. `execute_generation` sets private TMPDIR/XDG cache/CHECKPOINT/engine overrides but no HOME. Do not silently monkeypatch these helpers or claim universal secret-read isolation. Existing profiles leave reads allowed unless explicitly denied; stage source must contain no actual `.env` input. The new emitter invocation can use a fully fixed private HOME/XDG/TMPDIR, CHECKPOINT_DISABLE and no credential/env inheritance. All child write permissions must be limited to fresh stage/copied cache/private temp/fixed logs while original repo/cache/Node/engine inputs and prior recipe artifacts remain write-protected.
