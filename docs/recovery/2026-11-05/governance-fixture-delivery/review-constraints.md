# Fixture delivery: independent source contract constraints

Design/source audit only, November 5, 2026. No code, emitter, engine, package/image/sign/install, helper, database, provider or native operation executed. This document owns only delivery review constraints. It connects the already reviewed fixed synthetic producer to real packaging; it does not authorize a new provisioning service or operational experiment.

## Exact current mismatch

The native producer pins `AX_SYNTH_ROOT/fixture-tools/node` and the fixed helper `AX_SYNTH_APP/Contents/Resources/qualification/fixture-producer.cjs`. Before material generation/launch it checks those bytes and the ACL-aware protected paths of `fixture-schema.binding.json`, `fixture-schema.sql` and `fixture-seed.sql`, then rechecks before material return. Preserve all five exact installed input coordinates and the three-file ACL repair.

`emit-synthetic-fixture-producer.cjs` currently emits `.next/server/__axiom_private_fixture__/fixture-producer.cjs` with nonrelative packages external. `privateAuthorityDatabase.ts` imports the actual `@prisma/client`. A helper installed under the app's qualification resource directory does NOT automatically search `/Volumes/Axiom Synthetic Issuer-<generation>/node_modules` for that dependency. Ordinary Node ancestor resolution searches the helper's ancestors. An emitted file existing and hashing correctly does not prove its installed module/Prisma engine resolve path works.

Current `system_build_inputs.py` and `materialize.py` select fixed system companions; `container_assembly.py` derives exact v2 inventory and `final_seal.py` is frozen to the historical exact app/prestate/mutation set. Their rejection of extra files is intentional. Adding qualification resources through an undocumented copy after verification, widening the old allowlist in place, or calling the old receipt current would defeat that binding.

## Joined contract required of the adapter

1. **Separate fixed profile:** choose an explicit new delivery input/receipt/profile version for this source unit. Keep existing v2 parsers, exact file inventories, sealed/preseal receipts and historical artifact bytes unchanged. The new profile may reuse the nonauthority main and acyclic role paths, but its additional files must be derived from its fixed profile, not a caller-provided arbitrary destination map. Existing old-profile rejection of extras must continue.
2. **Finite resources:** the qualification resource set is the four already selected filenames: producer CJS, schema binding JSON, schema SQL and seed SQL at their fixed installed resource coordinates. The separately selected administrative Node coordinate is `fixture-tools/node`. Node/client/engine/support sharing must be explicit dependency inputs, not a permission to copy arbitrary application resources, secret files or executable commands. Record observed0600 quarantine modes separately from the reviewed prospective copied modes. Never chmod/modify original bound inputs to make the new profile pass.
3. **Source-to-output provenance:** bind the actual fixed entry, producer, schema splitter, explicit database factory, seed source, emitter/loader, source Prisma schema, pinned schema engine and recipe-generator source. Bind real compiler/emitter invocation and completed output when separately permitted; local mock output is labeled synthetic. Join the schema recipe's original schema hash, exact datasource-only temporary transformation, engine pin/diff-input hash, SQL/seed hashes and complete model inventory. `completeSchema:true` is not authority or proof independently of that derivation.
4. **Helper bytes and launch join:** the emitted producer copied to the fixed app path must be exactly the byte binding used in `AX_FIXTURE_PRODUCER_SHA256`; the installed administrative Node must match `AX_FIXTURE_NODE_SHA256`. Include those configuration/header inputs in the native maintenance build binding. No secret/URI/helper path in argv/environment; actual parent argv remains only the fixed Node and fixed helper. Do not silently substitute runtime Node or an unrelated compiler Node. Any selected identical-byte reuse must be explicit, hashed and copied separately.
5. **Actual dependency resolution:** explicitly choose the producer's `@prisma/client` resolution and generated-client/native-engine/support-asset coordinates. Resolve using a reviewed fixed emitted/source mapping or exact protected copied closure, never NODE_PATH, caller loader hooks, cwd/PATH guessing, repository node_modules or a host-global install. Test resolution from the intended helper filename and working directory with inert fixture modules; do not claim actual engine compatibility from mocks. Binding a top-level package.json alone is insufficient; trace generated client delegation and native engine lookup too.
6. **Protected sharing:** if sharing the already selected read-only payload dependencies, join their exact package manifest/digest, fixed mount/root/backing/alias identity and required closure to the administrative helper path. The parent must refuse if that selected root or dependencies are absent/unprotected/changed; a matching helper hash alone is not sufficient for its external dependencies. Mounted immutable image files may retain build-user numeric ownership: use the existing protected read-only/backing semantics, not an invented claim that each image member is root-owned. Preserve maintenance's helper-fork-before-Security/dispatch ordering; inspect any reused root-binding helper for hidden platform initialization rather than inserting it before fork blindly. If copying dependencies instead, define an exact independent protected file closure and its package/native-linkage rules. Do not grant a generic root helper access to arbitrary executable dependencies. Which option is selected belongs in the joined proposal, not an inferred implementation fallback.
7. **Independent verification:** derive the new expected file inventory/modes/coordinates and output provenance from the strict input contract. Do not accept a receipt that adopts its own arbitrary `files`, rewritten copied-hash summaries, extra leaf, symlink/hardlink or changed helper/recipe. Rehash only the bounded synthetic fixtures in local tests. Actual full-package verification belongs to a separately authorized future operation.
8. **DAG and seals:** qualification resources/dependencies join the protected container/resource closure; authoritative leaves retain their fixed paths and detached identity. Preserve outer seal last and the separate nonauthority main. Do not reintroduce final-seal→broker-CDHash→guard→image→final-seal cycles, deep-resign leaves, reuse a prior successful static receipt for changed bytes or patch the consumed sealed app. A future new artifact needs new source/output/sign/seal bindings and exact permission.
