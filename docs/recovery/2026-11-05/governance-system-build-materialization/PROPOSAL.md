# System compiled-consumer build and materialization proposal

Status: proposed; implementation requires an explicit validation-first decision. This document grants no execution or qualification authority.

## Problem and bounded outcome

System preparation now produces actual native source/role recipes and runtime payload inputs, but the real source compiler and materializer accept only the historical native-overlay profile. The next unit must connect those actual artifacts to a complete compiled private-consumer package; another metadata-only wrapper or peripheral refusal does not close this gap. Successful local preparation must still report issuer identity, installation, resource custody and business-channel qualification unavailable.

- `scripts/governance_local_issuer/system_preparation.py:138–173`: fresh staged source/config/header graph, actual runtime module/Node payload, role recipes and closed preparation receipt. This does not produce a Next compiler result.
- `scripts/build-local-issuer-package-source.py:344–350,352–399`: only legacy overlay receipt is recognized; generated-file exemptions are specific to that profile. `:473–524`: bounded compiler invocation binds original build-tool Node and emits the private bootstrap.

- `packages/verified-issuer-runtime/index.cjs:30–37,55–98`: exact package/runtime roots, native guard import, actual fd0 resource consumption and emitted initializer import; current identity and business channel deliberately unavailable.
- `scripts/governance_local_issuer/manifest.py:23–24,277–291`: fixed runtime path and strictly unavailable qualification. Keep these claims closed.

## One coherent implementation unit

1. Add a separate System build-input adapter, never edit `native_overlay.py`. Bind one exact source revision/archive, fresh System preparation/config/source receipt, native role/guard observations and all actual input hashes. Accept only the reviewed fixed System layout and completed required role inventory. The required inventory is a fixed exact role table for runtime Node, controller, owner, detached broker, maintenance, bootstrap and guard, plus explicit module distribution—not arbitrary caller-defined labels. Freeze each role’s expected identifier/coordinate, actual byte/stat binding, specific compile/signing receipt, current config and generation. Only the successful detached broker observation is eligible; exclude the historical app-bundle-context broker. For the guard, bind the separately approved supplemental representation observation alongside the original consumed/failed batch; never rewrite historical allFourStaticSequencesAcceptedfalse. Input observations are not cryptographic verification or installation authority. Reject missing, changed, aliased, unsupported or mixed-generation inputs without fallback.
2. Extend the actual source compiler with an explicit System profile. Preserve legacy behavior as a separate branch; reject selecting both profiles. Freeze inputs before a fresh compiler attempt, copy the exact runtime module source and bound guard/bootstrap bytes into the compiler stage, and exempt only the explicitly bound generated artifacts from archive equality. Recheck the same observations before and after compilation. Do not patch completed stages or transform old receipts.
3. Separate the original build-tool Node from the signed runtime Node. The original pinned Node remains the compiler/generator executable with its existing bounded environment and engine provenance. The signed Node is an inert payload input, copied byte-for-byte to `__axiom_runtime__/node`; it is never used implicitly to run npm, generation or Next. Bind both identities under distinct receipt fields. Runtime headers/guard compilation provenance must correspond to the prepared Node profile; a shared version string is insufficient evidence by itself.
4. Add the paired System materializer branch. Consume a successful actual compiler observation and the same immutable System inputs, then materialize the real `.next` output, emitted `.next/server/__axiom_private__/release-merge-bootstrap.cjs`, complete required dependency/traced-support closure and explicit runtime module distribution. Place guard at `node_modules/@axiom/verified-issuer-runtime/native/origin_guard.node`, bootstrap at `__axiom_runtime__/origin-bootstrap`, and signed Node at `__axiom_runtime__/node`. Preserve recorded bytes and quarantine modes, and recheck every input/output binding. Observed source modes (currently0600) and any eventual per-role packaged/installed mode mapping must be separate explicit fields. Never silently chmod original inputs or infer a launchable Node/bootstrap from a0600preparedcopy. The addon is loadable code with a distinct mode requirement, not an executable launch target. Code/mock tests may model only an explicit proposed mapping; actual application of a mode map and operational package qualification require a later concrete authorization. Missing or unreviewed mode mapping keeps launchability/readiness unavailable. No generic native source directory copying into the private module.
5. Keep native companion tools separate and fully bound. Owner, broker, controller and maintenance belong to the intended System custodian app, not web dependencies. Record their exact artifact/receipt/config identities and intended coordinates alongside the package assembly receipt; do not copy those privileged roles into the Next payload or treat caller-provided role names as authority. Keep intended installation distinct from private staging and never install or launch anything in this unit.
6. Use the actual native load-closure observer for every packaged Mach-O and companion inventory, retaining its unsupported loader-path/runtime limits. Any needed non-system dylib must be present and mapped explicitly; do not silently drop unresolved libraries or declare system prerequisites attested. Preserve bounded file/trace counts, alias checks, no-private-material checks and copied-byte verification.
7. Emit one complete actual package manifest and paired assembly/materialization receipt, with the source/compiler/runtime/companion provenance chain. Preserve `executionAuthorized=false`, unavailable executing identity and closed activation. Do not change `index.cjs` to mount a business channel, substitute synthetic credentials or promote file hashes into running identity. Its existing actual initializer remains the consumer to materialize.
