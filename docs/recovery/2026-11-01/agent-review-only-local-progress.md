# Agent separation Task1: review-only backend

User approved the local design. Both desktop and browser decision entry points now call a review-only service. Approval saves approved plus an agent_review_only_v1 audit marker binding the exact digest, requester, current reviewer role and expiry; it appends a waiting-for-requester turn. executeApprovedAction is no longer imported or called. This does not execute or activate anything, even if enrollment metadata is absent or unreadable. Current execution coverage remains a separate refusal in future execution, not a condition for merely recording human review.

The transaction locks current accepted membership and the proposal row, then samples the database clock. It validates current capability, independent actor, unexpired deadline and a compare-and-swap over original digest, arguments, tool, proposer, conversation and expiry. Audit and conversation writes share that transaction. The caller's role string is not authority. Existing already-approved/executed/failed rows cannot receive a fresh review marker. Rejection stays non-executing; current API approver gates are unchanged, so ordinary proposer self-stop via those routes is not newly accepted.
