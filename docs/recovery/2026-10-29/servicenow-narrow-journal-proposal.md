# Narrow ServiceNow journal verification — review proposal

The existing dev316885 Change Management OAuth grant does not prove journal reads. Read-only inspection of its API Explorer found Change GET/PATCH and Next States but no dedicated journal resource. CHG0030002 remains Normal/New, exact sys_id 85ebd990935c1310005fb6597bba1011. Its state menu offers New, Assess, Canceled. No state/approval/work note was changed. Native workflow remains authoritative.

Proposed local implementation: one dedicated read-only scripted REST resource, GET /api/x_axiom_evidence/v1/change/{sys_id}/journal-proof, protected by a separate explicit OAuth scope axiom.change_evidence_read. It accepts only a valid change sys_id and exact expected Axiom evidence SHA256 digest, checks the caller can read the change, searches only work_notes journal entries attached to that exact change, applies record/field ACL checks, and returns only an exact-match boolean and canonical entry digest. No arbitrary table, encoded query, field selector, record write, user-management operation, raw journal body, or token leaves this boundary. Missing/duplicate/ambiguous/denied results never prove success. The server-side verifier constructs the canonical Axiom note from its already saved evidence and compares the exact text; client-supplied authority is refused. Request/body/time/result limits and cancellation apply. No automatic resend after an unknown write.

The source package must include fail-closed adapter tests and a deployment review describing the exact resource, role/ACL/scope binding and current credential. Local implementation approval alone will not install it, change OAuth access, set journalRead=true, deploy Axiom, or append a note. Those require a later exact grant/activation review after source verification. The dedicated endpoint is a new provider capability and therefore requires the user's existing validation-first blueprint approval before implementation.

Alternatives: keep journal links unavailable, or use another existing supported narrow journal endpoint only after it is identified and verified. Broad Table API access and blank work_notes inference are excluded. Successful closure also requires real native lifecycle progression and its human decisions; the new read capability cannot bypass CAB/transition conditions.
