## Proposed claim and current authority

1. Keep all read/propose/validation/gate stages. For the real code_pr_open stage only, check actual canonical issuer availability before consuming its queued stage or any write credential. Unavailable leaves the queued stage, exact gate/artifact and old decisions intact; it cannot start a provider action. This is an eligibility refusal, not a fabricated completed/failed attempt.
2. Replace only that stage's existing CAS with a trusted org-first transaction which rereads the owned run/stage, source artifact/read/gate/decision history, current triggering-user membership/capability and pinned installation. CAS queued→running and create one versioned workforce attempt record together, binding organization, run/stage IDs, actual claim timestamp, server nonce, artifact/gate/read/proposal digests, installation/revision and exact deterministic output plan. Issue an opaque private in-memory capability only after the committed CAS result is positively known. No proof from request JSON, plain context IDs, serialized row or Agent WeakMap is accepted. Lost commit acknowledgment leaves the consumed original stage/association; it grants no adoption or retry.
3. Bind a nonrenewable **600-second execution lease**, measured by database clock and private monotonic freshness, to that new stage attempt. This limits the new worker capability; it does not manufacture expiry for old approvals (the current snapshot has status but no historical expiresAt). Any actual returned token expiry caps subsequent use sooner. Lease expiry stops further effects; it never clears possible credentials/accepted work or permits another worker to resume. Existing running/unknown legacy stages without this exact new claim stay unavailable; no backfill/reset.
4. The trusted worker derives its subject from the persisted run and successful private stage claim. Revalidate current accepted triggering-user actions:apply permission, exact approved snapshot/decisions/artifact and installation before credential release and each physical effect. Do not invent a desktop session or set sessionId=runId. Original sessions were not recorded by this workflow; no session-currentness qualification is claimed. For current user voters use their original existing approval capability semantics; for bound API-key voters use the actual tenant-owned key's current expiry/revocation/scopes under the existing API approval contract. Missing principal/capability evidence refuses. New physical accounting creates no role or policy grant.
5. Preserve existing allowed principal kinds and actual required distinct-principal count. API keys remain machine approvals, not humans. No actor is silently substituted by a workspace owner. This implementation cannot satisfy a later policy requiring independent humans merely by counting API keys or a requester vote; such positive Governance admission remains refused unless its exact real human evidence exists. It does not retrofit independent-review/session claims onto old decisions.

## Durable effects and credential exposure

Use existing durable workflow/event tables with strict workforce-specific versioned parent/child records. Reuse reviewed organization-lock/barrier/history/late-intent patterns, not Agent row IDs, authority ports or claim capabilities. Add explicit canonical validation of the new workforce kinds to the all-tenant blocker reader; an unsupported/malformed kind cannot disappear from the scan or yield a green empty list. Existing version1 desktop drain records and decisions retain their original schema/meaning. A worker-scope record has explicit run/stage/claim identity, never a fictitious paired-session field.

Before the first consequential write token resolution reserve the exact parent credential-exposure/operation association under the org lock. Read-only base/mode/file evidence uses existing contents_read authority; eliminate the unused eager write token and write-capable tokens for GET preflight. Select a fixed one-repository coding token purpose for contents/PR writes using the existing issuer's actual permission/repository/expiry validation. A pending lifetime record precedes the actual issuer call, outside locks; issued records retain actual provider expiry before releasing the bearer. This is a coding-specific typed exposure record, not a renamed native-push or enrolled-release lease. Unknown mint/acknowledgment remains blocking. No guessed TTL, widened permission or caller grant metadata. Reuse only the original attempt's recorded bearer while valid/current; no per-effect remint or new issuance after ambiguity. Original generic cache behavior is not lifetime evidence.

The parent binds the reviewed base commit and positively observed tree/modes from complete immutable reads. Fix exact derived branch/commit message/PR title/body and ordered files at claim (including instruction/correlation fields actually used by the current executor). Persist method/path/body digests only; source bytes remain in the approved artifact. Derive every child ID from original private attempt+fixed phase/index. Each independently reserves, consumes exactly one durable submission intent and calls a retained private current-authority/signal/descriptor check synchronously at its sole fixed fetch. No provider I/O inside database transactions.

Persist bounded validated blob/tree/commit receipts before dependent effects; deletion entries use sha:null and their reviewed modes without blob creation. New-ref response must identify the exact new branch and derived commit; PR response must identify the exact repository/head/base/commit and positive PR number. HTTP success or a URL string alone does not establish these bindings. Exact parent credential/exposure and every prior canonical child-slot history/receipt are rechecked before dependency, receipt recording and completion. Slots are not automatically quiescent: dangling Git objects, an accepted ref/PR and a usable token may still exist.

On lost provider/result/commit response, revoked authority, cancellation, expiry, malformed dependency or recording failure: preserve the original consumed attempt and all child history, stop subsequent effects and report unknown where a write may have occurred. No child replay, restart adoption, branch/PR recreation, descendant retry chain, cleanup deletion or promotion to succeeded because an audit/webhook succeeded. Existing downstream coding.pr_opened notifications remain separate unqualified side effects; their success cannot certify this chain. Original stage/history rows are never rewritten to make old work eligible.
