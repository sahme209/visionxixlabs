## Implementation

Two fixed factories bind outlook.mail_send.v1 and outlook.event_create.v1; a request cannot select arbitrary profile or identity. Actual canonical issuer extractor always refuses. Outlook HTTP checks it before claim/approval consumption; existing request, read, approval, cancellation and unknown recovery keep their separate behavior. Shared store reads the actual one-attempt claim under org-first locks with exact owner/executor/user-ID lease, current executor session, original independent reviewer session, provider/action kind, current connection, task and enrollment absence. Mail recipients versus calendar account/time/attendees are separately target-bound; complete exact intent and approval are source-bound. Existing Teams/Linear binding outputs remain unchanged.

Existing Outlook connection validation decrypts an already-issued OAuth token inside local store transactions. This source preserves that behavior: it is not provider I/O, new credential issuance or proof of prior bearer lifetime. The adapter reserves before releasing credential to the fixed transport, not before every existing local validation/decryption. Current validated token expiry, connection-validation horizon and original action deadline are retained through a private freshness closure; no serialized flag grants authority. The actual transport child signal is checked across database/identity awaits, immediately before decryption and again before returning the credential.

Reservation and submission intent reuse canonical immutable drain rows/history. One private request can reuse its own successful reservation only; restart or lost acknowledgement never remints/resends. Exact persisted slot is read back before marking intent. Original action record versions/history remain unchanged. Sole fixed POST consumes one-use intent and retained current authority synchronously immediately before fetch. Graph GETs/readback perform no intent write; no provider operation occurs under DB locks. Mail202 means submission acceptance only, not delivery; exact calendar readback retains original semantics. Neither confirmation nor unknown closes a slot or proves provider quiescence.
