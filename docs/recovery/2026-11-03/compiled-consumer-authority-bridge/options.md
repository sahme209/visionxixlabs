# Compiled-consumer authority bridge: decision required

**Internal design options, not implementation approval or qualification.** Source `d410` (November 3, 2026). Source analysis only; no test, counterexample, exploit, runtime, credential or provider action. The previously blocked security test is neither reproduced nor proposed here.

## Original requirement and current gap

The approved [artifact-binding proposal](../../2026-11-02/governance-issuer-artifact-binding-proposal.md) requires the **actual compiled issuer/store/transport composition from the same verified package**, not a second compile, source wrapper, module replacement, passed digest or descriptor. Its sections4–5 also require a private bootstrap-owned capability and refusal if the compiled topology cannot establish it. This proposal preserves that requirement, the existing genuine approval/claim/freshness/unknown-result rules, and the bounded local trust model. It does not add hostile-host or fleet-attestation requirements.

Current source separates three things that must not be conflated:

1. `packages/verified-issuer-runtime/index.cjs:21–85` checks canonical main/root/loader/native origin and starts the fixed Next server, but its observation deliberately remains `canonical_consumer_qualification_pending`, executionAuthorized=false. A protected package and a successful native origin observation do not yet grant the compiled consumer authority.
2. `issuerArtifactIdentity.ts:1–8` reads that module; `mergeOutboundIssuer.ts:1–10` and other issuer readers still unconditionally throw. Replacing the throw with a digest/ready-object interpretation would leave the missing authority bridge unresolved.
3. `mergeOutboundDrain.ts:20–88` compares issuer digests and combines private claim callbacks with durable drain bindings. `enrollmentDrainStore.ts:65–77` explicitly relies on a trusted caller to verify the original private claim. Those interfaces are composition requirements, not proof that the caller is the qualified compiled consumer. `releaseProviderMergeCoordinator.ts` composes actual session/claim/credential adapters; `releaseProviderMergeTransport.ts:40–55` receives the credential and performs awaited policy/target/final checks before one PUT. A future bridge must govern that actual resource path, not merely its diagnostic reader.

## Recommended decision, including what the bridge must own

Choose **B initially**, with **C as an explicit new design if B proves unavailable**. Keep issuer readers/default coverage refusing until the actual bridge and original matrix are qualified. Do not package repeatedly in place of making this ownership decision.

The bridge is not “an attested process tells any JS caller its digest.” The protected startup must bind exactly one packaged compiled dispatcher and its fixed coordinator/resource composition. That same composition must retain ownership of the original durable claim, credential lease/acquisition and final bounded send. Requests, DTOs, environment fields, persisted receipts and plugins never supply an alternative callback, transport, claim verifier or permit. The native layer protects origin/lifetime and the private capability; the trusted compiled coordinator still performs current business-policy/session/approval checks. Neither layer alone replaces the other.

The production loader assumption must be documented and checked as part of the supported profile: no source-workspace fallback, external mutable modules, alternate startup, unreviewed loader flags/preloads or dynamically installed authority code. This is a closed-package local runtime assumption, not a promise against a compromised OS/admin. If ordinary Next composition cannot keep that private ownership through real route loading, report B unsupported and review C; do not turn a successful import/digest observation into execution permission.

Existing adapters may continue to carry issuer digests as **evidence labels** after binding, but those values cannot create permission. The bridge must be checked at the resource boundary after awaited claim/credential/source/policy work and at final synchronous handoff, preserving revocation/expiry and the original one-attempt unknown-result rules. Credential and effect ownership must remain inside the qualified component; returning a write token to an otherwise unbound caller would reopen the gap.

## Review gates before any implementation or experiment

- Approve the exact supported compiled dispatcher/resource-ownership profile and its loader assumptions; enumerate every included route/worker and explicitly refuse uncovered paths.
- Specify bootstrap-to-dispatcher lifetime, revocation and one-start behavior, without public DTO/callback authority; identify the actual claim transaction, credential owner and final send implementation being bound.
- Preserve migration behavior: existing enrolled/unqualified paths refuse, existing attempts/history remain unchanged, native-origin observations stay unavailable until qualification, and no old approval is reused.
- Future local validation must use the actual emitted compiled coordinator/store/transport from one recorded successful package, with isolated DB and simulated external provider/auth clearly labeled. Validate original positive and refusal/freshness/claim/credential/unknown matrices; source-only adapters, mocked issuer modules and file hashes alone cannot count. No test procedure or new execution is authorized by this design document.
- Only after independent source review and explicit user approval should implementation, exact package preparation or a bounded qualification run be separately scheduled. No service registration, identity activation, real credential/provider operation or production enablement is included.
