# A2 composed boundary decision within approved design scope

Design specification only, under `call_Nu5fVdY8QbGHZLHdabhskBJr[0]`. No implementation or OS action is authorized. Uses existing local source and the already supplied [Apple findings](apple-acl-source-findings.md); no external retrieval. The historical simple-ACL recipe remains rejected.

## Decision

It is valid to assess exclusivity across the **entire enforced resource path**, rather than demand every individual layer alone distinguish a copied genuine binary. A copied, immutable genuine supplier may be admitted by an OS code-identity ACL yet refuse before reading because its actual loaded location/installed epoch is wrong. That composition could preserve the original exact-instance requirement if every possible read path is forced through the unmodified check and the attacker cannot affect execution before it. This is a conditional design argument, not demonstrated macOS custody or a currently selected positive implementation.

Replace the historical blanket acceptance requirement “the ACL by itself denies every copied genuine artifact” with this exact combined requirement: **no unqualified process can obtain material, whether denied by OS authorization or by immutable mandatory checks before every read; only the actual installation-owned supplier can deliver it through the original owned-instance channel.** A self-reported refusal or expected metadata is insufficient. Actual installation and OS enforcement must make bypass unavailable. This does not relax the original copied-artifact/same-compiled-consumer acceptance, which remains unchanged and unperformed.

No new trusted runtime or root custodian is selected. Trusted root/operator/installer and non-root dedicated custodian remain the declared boundary. A code-identity policy narrower than signing-team membership is required: an arbitrary alternative signed with the same team must not gain resource access. A team-wide ACL would admit different code that can omit every supplier check and is rejected. Exact identity semantics still require a supported effective policy; the rejected simple policy's prompt alternative remains a separate bypass and is not repaired by supplier self-checks.

## Conditions that must hold together

| Attack surface | Required actual enforcement; current evidence limit |
|---|---|
| Genuine supplier copied or launched from another path | Mandatory native check binds the loaded supplier image to the exact protected installed file and generation before any secret read, not just argv/path text. Copy must refuse before read. Protected installed image cannot be modified or replaced by the attacker. Existing `origin_broker.c:215–217` checks fixed executable path and loaded-file match, but does not establish the complete installed system profile. |
| Alternate same-team program or a different resource caller | OS effective authorization must exclude different code/subject identities, including another app's signed binary. Path checks in our program cannot restrict a different program admitted by policy. No supported policy with this property is yet selected. |
| Loader, injected dynamic library, constructor, debugger, altered runtime | Code must be protected against attacker execution **before main**, interception of provenance/Keychain functions, writable executable mappings, debugger/process-memory access and untrusted loaded dependencies. Rejecting environment in main is too late to prove absence of earlier code execution. Hardened-runtime, library-validation, entitlement and debugger restrictions must be concretely qualified for this exact installed image; their effectiveness is not established by the inspected code or findings. No speculative entitlement flag is selected here. |
| Identical genuine code deliberately loaded as a library or driven through a different entry | Code admission must not permit an attacker-controlled host to call an internal read function while bypassing main. No callable exported supplier path, arbitrary interpreter/plugin entry or untrusted thread can reach reads. Exact executable/process identity and protected control flow must hold, not merely presence of genuine code in memory. Existing exported C supplier functions and loaded-main address check are not a proof against that attack on an admitted host. |
| Inherited FDs, redirected output, caller-controlled bootstrap | Supervisor itself must start with fixed installed inputs and a closed descriptor set; no caller FD becomes a secret recipient. Only the control queue owns the anonymous writer; no arbitrary output/log path, reply port, resource-selector RPC or requested PID selects the recipient. The current child spawn uses fixed argv/env, `POSIX_SPAWN_CLOEXEC_DEFAULT` and fixed pipe dup actions (`origin_broker.c:93–99`), but that does not prove supervisor startup FD closure or the actual installed launch. |
| Supervisor arbitrary params, environment or request replay | Fixed argument cardinality, complete startup input policy, actual dedicated principal/system context, protected installation binding and fresh process/native epoch must be established before reads. `argc==1` alone does not authenticate invocation. No runtime request/receipt supplies readiness or installation authority; arbitrary same-UID invocation must not become a way to export keys. |
| Node/worker direct Keychain reads | The OS ACL must exclude the interpreter/worker identities as direct resource readers, despite the shared dedicated UID; the node process must receive material only over the original native-owned one-use channel. A principal-only read grant or a signing-team rule that includes Node is insufficient. Node importing Security APIs cannot rely on JavaScript API privacy as enforcement. Actual denial remains a mandatory deployment qualification. |
| Node material after legitimate delivery | The actual compiled private initializer/consumer graph, loader closure, original lifetime and fresh claim/credential/final-send checks must qualify. Legitimate delivery itself gives Node copies; supplier location checks cannot constrain an unqualified consumer after delivery. The original complete compiled-consumer matrix remains required. |
| Active epoch and resource/installation changes | Actual protected immutable program/configuration, administrative quiescence and retained exact resources must hold. A generation string/ACL dump alone cannot exclude concurrent privileged changes or restore a consumed pipe. Trusted root remains explicitly outside the attacker model. |

## Source alignment and finite disposition

The current supplier startup is called at `origin_broker.c:218` after the broker's loaded executable check, before queues/listener; it is not evidence that all conditions above are enforced before reads. Current source also has readonly-root/loaded Node/addon checks (`origin_process_identity.c`), root anchor checks (`origin_root_binding.m`), fixed child environment (`origin_bootstrap.c:44–45`) and Node loader-variable rejection (`origin_guard.c:37–40`). These are useful parts of the path, not a proven hardened supplier, system install or resource grant. The canonical `operational()` remains constant false and the business channel unmounted.

The finite next decision is the effective **OS resource policy plus pre-main integrity** qualification, not another metadata wrapper: determine whether one supported policy can admit only the intended immutable supplier code identity and trusted administrative writer, exclude all different programs/Node and interactive alternatives, while the actual installed executable enforces its location/epoch before reads. Neither this composition argument nor `SecAccessCreateFromOwnerAndACL`'s CSSM declaration supplies that policy. No lower-level policy is silently selected. The existing design-specification approval covers this analysis; implementation and any further platform retrieval or installed synthetic qualification require their own authorization.

If those policy/integrity conditions cannot be established, reject the proposed positive custody mechanism and retain refusal. If they can, future acceptance must observe actual OS-denied alternate-code/Node access and actual pre-read refusal for copied genuine supplier paths, alongside the original unmodified native/compiled-consumer/copy/fleet/coverage/history matrix. This is a precise refinement of layer attribution, not a reduction in whole-boundary acceptance or a claim that the current mechanism is sufficient.
