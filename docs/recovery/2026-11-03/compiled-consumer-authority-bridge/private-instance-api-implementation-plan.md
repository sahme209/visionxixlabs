# Local private-instance API refactor: review-ready plan

**Proposed local code/tests only; approval pending.** This is necessary real-resource API work for C’s actual compiled Node owner, not an inert DTO milestone or completed custody. No code, tests, services, keys, grants, environment/schema change, provider action or qualification is performed by this document. Original same-compiled-consumer, native resource provisioning, process-wide cutover, fleet/legacy/drain and full-profile coverage gates remain unchanged. All issuer readers remain unconditionally refusing and the C profile remains OFF.

## Scope and API boundary

Add resource-instance APIs which operate on actual Prisma/crypto/JWT/session implementations with explicitly supplied private dependencies. Existing legacy exports retain existing behavior until a separately reviewed real C composition replaces them. A factory, configuration object or successful test is **not execution authority**. Ordinary code must not interpret the presence of these instances as qualified origin or coverage.

## Actual source changes and caller map

- `lib/db.ts:3–20` currently eagerly creates/caches a default client. New explicit-resource module must be importable without importing that default. The actual `createReleaseProviderMergeCoordinator(repo,request,ports)` already accepts a repo, but its `resolveRequestDesktopSession`/configuration dependencies still use global IO and require an instance-aware composition path.
- `credentialVault.ts:6–15,64–74` owns key lookup and actual scoped AES-GCM. Share the pure algorithm with explicit bound key; keep legacy wrappers’ current semantics. `platformGithubAppCredential.ts:60–87` reads global Prisma and invokes that vault; private platform configuration needs the real repo/vault rather than a safe-config DTO asserting a key exists.
- `githubConfig.ts:104–174` prefers DB singleton then environment fallback; `githubAppAuth.ts:57–86,151–248` signs JWT, caches and mints. Refactor pure/internal mechanics so the private instance can use them without calling legacy configuration or sharing cache. `releaseProviderMergeToken.ts`, `releaseProviderMergeCredential.ts` and `releaseMergeCredentialExposure.ts` are eventual fixed compiled callers; no direct public token export is added.
- `desktopToken.ts:25–60` resolves environment key; `desktopSession.ts:64–172` owns a mutable module-level store; `desktopSessionStore.prisma.ts:58–104` wraps the actual model; `resolveRequestDesktopSession.ts:6,64,94,126+` imports global DB/token/session/commercial/membership readers. Instance-aware APIs must retain these real checks. The direct-merge coordinator and current-session freshness/store authority readers are the eventual private graph, not a new synthetic principal source.
- No current public route is switched to the private profile during this refactor. No issuer-reader throw, coverage registry, enrollment gate, final transport or legacy route is relaxed. The real compiled graph migration is a subsequent reviewed change once native provisioning and protected resource custody can be qualified.

Focused checks use owned test keys and bounded simulated transport: actual JWT signature/claims, exact repository/permission response validation, no environment fallback, separate caches across instances/keys, abort/expiry/purge and no automatic retry. No real token/provider request. Preserve existing focused legacy behavior tests once affected code changes.
3. Add private actual desktop token/session/resolver instances. Focused checks: real HMAC verification; real isolated store/DB membership/session records where appropriate; revoked/expired/current role/capability and organization mismatch refuse; distinct instance keys/stores do not mix; API keys cannot satisfy direct-merge role/session authority; no environment fallback or mutable global store in the private path.
4. Source-review private import closure and actual C graph migration seams. Demonstrate these APIs are real implementations, not fake-ready descriptors; keep native/issuer authority unavailable. Run only affected scoped types/tests and independent review. One future full compiled build is separately scheduled after a coherent integrated change, not per helper.

Tests above are ordinary resource-function correctness and isolated composition checks. They do not exercise or regenerate the blocked security test, certify hostile-host containment, or prove private native provisioning. No test/counterexample code is included or authorized until local design approval.

## Resource provisioning and qualification prerequisites remain exact

A legitimate Prisma datasource, actual vault key and actual session key must eventually reach the owned qualified Node/private bootstrap once per epoch without environment/argv/log/file/JS-global or generic credential export. The selected native mechanism must authenticate the actual retained owned instance—not merely UID/signature/public metadata—and preserve freshness/lifetime. This plan provides the source APIs those resources need; it does not prove the delivery mechanism exists.

Local refactor approval cannot create the service principal, register a supervisor, transfer keys, grant DB rights, migrate shared authority writers, run provider effects or activate Governance. Deployment-wide shared App/vault/legacy-token cutover and original full-profile/fleet/coverage acceptance remain required. If real private resources cannot be provisioned under that model, the profile stays OFF regardless of passing API tests.
