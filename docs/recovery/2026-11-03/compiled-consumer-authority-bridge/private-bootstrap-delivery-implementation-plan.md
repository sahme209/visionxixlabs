## Pipe lifetime and custody contract

Create the pipe with close-on-exec on both original ends and make the parent's writer nonblocking. Require supervisor fd0–2 to be established before allocating pipe descriptors so mapping cannot accidentally alias them. Spawn file actions duplicate only the read end to fd0; originals and the writer cannot survive into the child. Close the parent's read end immediately after successful spawn (also on failure); retain the writer in the exact job and then the adopted child/epoch state. Parent never sends the endpoint to clients, stores a pipe path or forks another holder. Recheck existing actual owned child, startup deadline, root binding and epoch before supplier access and before resume/write. Track supplier work off the control queue with retained cancellation state; a late result is wiped, not adopted by a newer epoch.

Adopt the stopped child and establish its exit watcher before any material-bearing write. Reserve this epoch's one delivery before the supplier operation. Resume only that fixed bootstrap under the existing `axiom_origin_slot_may_resume` checks, then drain the bounded payload through nonblocking writes while its native guard reads; never block on filling a pipe while the child is suspended and never assume pipe capacity or one atomic write for the entire frame. One supplier result yields one frame. Mark consumed immediately before the first write that may expose bytes. Handle partial writes, EINTR/EAGAIN, broken pipe and SIGPIPE without killing the supervisor unexpectedly or retrying from byte zero. Deadline, child exit, revocation, short read, malformed frame or uncertain write closes the writer, revokes/kills/reaps only the actual owned child and preserves consumed unknown. No retransmission/reissue or adoption after unknown.

The fixed preexec bootstrap validates readonly pipe fd0, keeps it only across the exact packaged Node exec, and preserves restriction/env/argv checks. The native guard reads an exact fixed header plus bounded payload under the remaining original startup deadline before business resource imports; verifies EOF/no trailing bytes after the parent closes its writer, closes fd0 and replaces it with `/dev/null` before resource-owning modules initialize. Select a frame cap below 32 KiB, datasource at most8192 bytes, vault exactly32 bytes, session key32–4096 bytes (a proposed bound; existing compatible key must fit or the profile refuses). Short EOF, no EOF, bounds/encoding/duplicate field failure permanently refuses. The source already supports readonly pipe descriptors in its typed protected-resource inventory; its observation does not authenticate this pipe. Preserve inventory completeness and verify closure at the selected phases rather than relaxing it globally.

No JavaScript stdin listener, ordinary Next startup, worker, fork or business handler runs before consumption and fd0 closure. The fixed canonical main receives native bytes once, passes them lexically to the manifest-bound initializer and erases staging where supported; the actual private DB/vault/session factories then own their necessary copies. Successful parsing is initialization, never an executing-issuer identity or approval result. The remaining same compiled-consumer/current-boundary qualification remains unchanged.

## Exact material record and lifetime

Proposed total response cap: 32 KiB including frame, with fixed lengths and no unknown fields. Datasource UTF-8 is at most 8192 bytes (existing private constructor limit); vault key exactly 32 bytes; session bytes are32–4096 bytes; the existing token codec copies the supplied bytes and requires at least32. Provision the exact compatible bytes rather than reinterpreting a legacy text key; exceeding the new cap refuses pending review. Billing is fixed nonsecret `legacy` or reviewed `public` account/livemode identity, not a caller entitlement. No raw App private key is independently delivered: actual private platform App configuration reads its encrypted singleton through this DB/vault and fails closed. No provider token is in the bootstrap payload.

Actual DB rights, network/TLS configuration, compatible encrypted rows and global key sharing must be operationally established. Neither choosing a new datasource nor sending a new key makes current sessions/rows compatible. The authority client/vault/token codec necessarily retain copies (datasource string/Prisma configuration, copied vault key, crypto inputs); clear staging buffers where supported without claiming V8/Prisma zeroization. No payload/ciphertext/URL/key logging, error serialization or IPC echo. Epoch loss closes new operations and follows existing consumed/unknown/exposure history; wiping staging does not revoke already minted tokens. No reconnect/reissue, restart inheritance or generic credential RPC.
