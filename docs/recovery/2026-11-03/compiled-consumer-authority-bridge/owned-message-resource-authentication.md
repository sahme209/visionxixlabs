# C resource-plane authentication: public-API candidate and exact remaining proof

**Source-only mechanism proposal, not implementation or qualification.** Uses installed public macOS SDK headers only. No IPC, service, profile, resource, test or provider operation was performed. Existing observation-only broker behavior is not asserted vulnerable. This is a new resource-authority boundary requiring user design approval before code. Complements [placement and data channel](process-placement-and-request-channel.md); the business request XPC channel is distinct from this private resource plane.

## Concrete candidate selected for review

Use a **separate native raw-Mach resource receive port**, owned by the native supervisor, with a fixed, bounded, data-only request protocol. For every received message request a format-0 audit trailer using public `MACH_RCV_TRAILER_TYPE(MACH_MSG_TRAILER_FORMAT_0)` and `MACH_RCV_TRAILER_ELEMENTS(MACH_RCV_TRAILER_AUDIT)`. Inspect the actual receiver-supplied trailer after the bounded message, not any body token. Require supported trailer type/size/alignment and a complete `mach_msg_audit_trailer_t`; reject truncation, malformed/complex/OOL/right-transfer variants outside the fixed schema. These receive/parser decisions are proposed, not existing code.

The native supervisor extracts the **per-message** sender PID, PID version and effective UID using public `audit_token_to_pid`, `audit_token_to_pidversion`, `audit_token_to_euid`. It compares PID to its own still-owned, unreaped child record and expected dedicated service UID under one native epoch. The first accepted resource handshake retains its kernel token identity tuple; subsequent messages require that same tuple and current epoch. Do not parse `audit_token_t.val` manually. No client-supplied PID, epoch or token constitutes identity. Sequence/request IDs prevent protocol reuse only; they are not credentials. A forwarded Mach message authenticates its actual forwarder, not a sender named in its payload.

Use `SecCodeCopyGuestWithAttributes` with the kernel root host and `kSecGuestAttributeAudit` to obtain dynamic code for that same receiver-observed token, and `SecCodeCheckValidity` against the exact approved native/Node requirement. **The installed header declares the audit selector but does not document its CF value encoding.** Do not implement a guessed representation; resolve the official documented encoding/availability before code. `CFEqual(SecCodeRef)`, static `kSecCodeInfoUnique`, a path, signature alone, cached `xpc_connection_get_pid`, or a caller's SELF response is not process equality. The dynamic code check validates code identity; standard Node identity still does not authenticate loaded JavaScript.

The native supervisor additionally retains actual owned-startup state, fixed preexec/resource closure and epoch, and never reassigns ownership from a client report. An unreaped child prevents its PID being legitimately recycled while ownership remains, but does not by itself prove unchanged executable, current runtime heap or compiled-consumer reachability. Unknown/expired startup, exit/reap, mount/retained-resource change or verification failure permanently invalidates that epoch and pending grants. Do not use a replacement process or restart to inherit it.

## What this concretely establishes, and what it does not

Local `mach/message.h` calls an audit token an opaque identifier for Mach tasks and senders; public BSM routines name the PID and PID-version fields. Together these support a concrete **per-message sender filter** bound to an actually retained owned-child PID, rather than the current signature-only resource assumption. They do not document the relationship of PID version to every exec transition. `sys/event.h` provides `NOTE_EXEC`/`NOTE_EXIT`, but notification delivery is not a synchronized proof that no exec occurred between message validation and effect. Do not call asynchronous process notifications a complete current-execution fence.

Therefore the following exact proof is still missing: **a documented and qualified binding from each received kernel sender identity to the supervisor's actual owned execution instance, and from that execution to the original same compiled coordinator's claim/final-send call, valid through the protected effect**. Neither the audit trailer nor the first handshake alone closes the latter JavaScript/source-consumer authority bridge. No blanket guarantee about arbitrary code in the owned process is introduced. The current native canonical assertion remains observation/unavailable; TypeScript readers continue to refuse. This candidate must not grant DB/provider custody merely because PID/signature/epoch match.

Before implementation, official API documentation must settle the audit-selector encoding and intended process-instance/exec semantics; the design must then specify its actual claim/final-send authorization contract. If those primitives cannot supply required lifetime proof, select a different reviewed native effect boundary/placement rather than adding a caller boolean, task-port/debug entitlement or private XPC API. This is a finite unresolved evidence requirement, not a claim of impossibility and not authorization to recreate the blocked compiled-consumer case.

## Resource protocol and custody limits

The separate business channel carries paired-user intent to the protected actual compiled Node process; its sender is the desktop, not the privileged issuer. It must never be accepted by this private bootstrap resource port as an issuer. The selected role division keeps the **same Node process** as sole Prisma/session/policy/plan/review/claim/decrypt/App-sign/mint/final-HTTP owner. Native supervisor code does not duplicate SQL, business authorization or the merge transport.

The resource-plane candidate is therefore **one-use bootstrap provisioning**, not a per-plan signing/token RPC. Proposed request field names are only `protocol`, `operation`, `sequence`, with one fixed initialization operation; it accepts no SQL, URL, path, secret selector, arbitrary bytes-to-sign or caller claim. Exact bounded response framing and actual platform delivery remain undecided: no environment/argv/log/file/JavaScript-global delivery or generic get-credential API is permitted. Real Prisma configuration and existing crypto clients require a concrete private initialization design, not a fictional opaque DB handle. Establishing that delivery with public APIs and original compiled-consumer ownership is a prerequisite to approval, not presumed by this candidate.

Only the truly owned, qualified Node instance can receive minimal actual configuration, at most once per native epoch, before business work. No adoption, reconnect/reissue, restart inheritance, frontend access or same-UID/signature-only substitution. The Node graph then independently reads actual current paired identity, durable plan/approval/policy and attempt state under separately enforced database writer/key custody; the native supervisor does not. No outside process may retain equivalent platform-wide App-signing/global decryption resources for legacy organizations while claiming one organization isolated. Existing sessions/credentials/unknown exposure blockers remain authoritative.

Cancellation/timeout/revocation invalidates pending admission; after a claimed/submitted effect it records unknown when confirmation is unavailable and never auto-replays. Receiver/service restart loses the live epoch, not durable history or token exposure blockers. Cleanup touches only actual owned resources and retains unknown state when reaping/ownership is uncertain. Existing180s startup/250ms native observation limits are not expanded by this proposal.

## Local SDK evidence inspected

- `usr/include/mach/message.h`: `audit_token_t` opacity, `mach_msg_audit_trailer_t`, format/elements constants.
- `usr/include/bsm/libbsm.h`: documented `audit_token_to_pid`, `audit_token_to_pidversion`, `audit_token_to_euid`.
- `Security.framework/Headers/SecCode.h`: `kSecGuestAttributeAudit`, generic attribute lookup/error contract; `SecCodeCreateWithXPCMessage` uses the associated message audit token; dynamic validity checks; `kSecCodeInfoUnique` identifies static code, not process instances.
- `usr/include/sys/event.h`: process exit/exec notification constants; no synchronized effect fence claimed.

Paths are beneath `/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk`. No external documentation reads occurred for this proposal; root's separate request for limited official documentation remains pending.
