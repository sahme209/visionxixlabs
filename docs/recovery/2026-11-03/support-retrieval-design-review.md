# Independent support retrieval design review

2026-11-03. Static design/spec review only. No runtime, tests, builds, providers, network, customer eligibility or release qualification executed or asserted.

## Verdict

The bounded offline direction is consistent with B5 and the approved website IA. No unsafe authority promotion is intentionally authorized: real repository drafts remain customer-ineligible, synthetic approval is explicitly simulated, human editorial authority stays external, public/internal boundaries are stated, and missing or revoked replacements cannot resurrect predecessors. The proposal is suitable for user design discussion, with the concrete contract clarifications below resolved before implementation approval is treated as an executable specification.

## Findings

1. **Medium — freshness and deterministic evaluation need explicit trusted inputs.** Proposal lines 21 and 31 require an independently supplied expected current generation and a validity-window check, but the exhaustive command input list includes only the catalog digest, not the expected generation, trusted invocation/review record, or the time used for expiry. Line 69 promises identical outputs for identical fixed inputs. A clock-dependent expiration decision cannot satisfy that promise without defining time as an input. Specify the externally verified trust/freshness record and its scope, expected generation/digest and evaluation instant, including who supplies those values and how real runs prevent a caller-selected historical time from accepting an expired catalog. Synthetic tests may freeze a clearly simulated clock; that must not constitute real freshness. A self-asserted catalog must fail when external authority is absent even if its hash matches a caller-provided hash.

2. **Medium — define the simulation boundary as enforceable command behavior.** Lines 27 and 55 intentionally allow positive synthetic public fixtures, while line 35 requires genuine authority for public eligibility. This is reconcilable only if simulation is an explicit, separate evaluation context: the public eligibility algorithm is exercised using substituted simulated authority, and every result remains simulation-only. Specify that the ordinary public command cannot select this context or emit customer-eligible success from simulated pins/releases; simulation must not be inferred from article metadata. Add a negative case for a synthetic fixture/catalog supplied to the ordinary public path. This prevents implementation from resolving the apparent contradiction by introducing an undocumented public approval bypass.

3. **Medium — catalog-bound routing and quotation semantics are incomplete.** Lines 41–45 require reviewed routing terms, mappings, complete context, contradiction refusal and approved public destinations, but line 23's conceptual catalog entry does not yet define those bindings. Existing article fields contain arrays and step objects rather than independent section records. Before implementation, specify routing-to-pointer mappings, required context dependencies, incompatible-section declarations or another deterministic conflict rule, approved public destination/version mapping, and section hashing/serialization. Define whether a section digest hashes decoded UTF-8 text or a canonical JSON value; a JSON pointer identifies a value, not a raw byte span. Cite every returned context component and ensure a mutable public destination is not represented as proof of immutable quoted content. Without this, implementers must invent safety-critical extraction and conflict behavior despite the proposal's deterministic/no-synthesis promise.

4. **Low — duplicate identity wording should permit preserved history.** Line 21 rejects duplicate IDs/versions while line 33 requires a complete revision graph and explicit authorization for historical revisions of a still-supported exact version. Define uniqueness by article ID/revision (and the intended version scope), then separately reject multiple conflicting current entries. A blanket ban on repeated article IDs or versions would prevent representing normal immutable revision history. Missing revision metadata must refuse the catalog; a known replacement whose payload is missing must keep its predecessor excluded.

## Scoped re-review — 2026-11-03

Scope: findings 1–4 above and new contradictions in their revised sections only. Read the revised proposal and appended author report; no runtime, tests, build, network or provider work performed.

- **Finding 1 addressed at design level.** Verified context now binds authority/scope/decision evidence, expected current generation/digest, expiry and a trusted invocation instant. The launcher is explicitly outside caller-controlled inputs, replay cannot authorize fresh output, and absence of real verified facilities refuses. No actual authority/launcher is asserted.
- **Finding 2 addressed at design level.** Separate simulation evaluator uses simulation-only, permanently customer-ineligible envelopes; ordinary retrieval rejects simulation, synthetic pins and replay. The negative evaluation matrix includes this boundary. Real drafts remain ineligible.
- **Finding 3 substantially addressed, with one narrow residual ambiguity below.** Catalog now binds routing/context/conflict/destination mappings, string-only pointers, canonical JSON string digests and individual context citations. Semantic correctness remains explicitly editorial; mutable links are not immutable proof.
- **Finding 4 addressed at design level.** Composite identity and ID/revision immutability preserve historical revisions while rejecting duplicate/conflicting entries; missing replacement payload cannot revive predecessors.

**Residual medium — matching pointer lists do not establish identical answers across articles.** The revised matching paragraph allows multiple highest-priority routes when their primary/context pointer lists and answer-group IDs are identical. JSON pointers are relative to each entry's article: two different articles can both select `/goal` and the same context paths while containing different text. An identical group label does not prove equivalence. Require equality of the fully qualified article/revision/version/digest/pointer/component-digest tuples (or conservatively refuse all distinct tied routes); permit deduplication only for routes selecting the same bound components. Otherwise the stated equivalence exception can accept conflicting outputs or leave selection to display ordering. This is confined to the newly specified tie rule, not a request for semantic inference.

Overall: findings 1, 2 and 4 addressed; finding 3 needs the single tie-equivalence clarification above before closure. All conclusions are design observations, not implemented guarantees, executed evaluation results or genuine editorial/customer approval.
