## Genuine interface decision requiring explicit review before code

The approved diagnostic addon exports frozen empty state and cancels its connection. That cannot supply a fresh current-liveness answer to the existing synchronous `issuer()`/final freshness closures. Do **not** solve this with a cached ready boolean, startup transcript, periodic heartbeat, public initializer, caller challenge/PID, imported callback or accepting a future verified JSON shape.

**Proposed narrow change:** a fresh successful native constructor retains its private authenticated connection/session and exposes a frozen **read-only, zero-argument native assertion**. The actual canonical module captures that native function privately and never accepts a replacement from a caller. It is not an initializer, setter or identity/digest issuer. Each call sends a new private native nonce; the broker checks its still-owned unreaped child/consumed slot and current code, and the native side checks actual broker message/code/SELF/nonce/deadline. It throws on failure and returns no authority value. The canonical reader can return its privately established artifact identity only after this current assertion succeeds. The public exported consumer remains a reader; no private state can be initialized by calling it.

This is an explicit departure from **empty addon exports**, even though no public initialization is added. It needs user design review before implementation. Retain per-message signing checks, no reconnect/adoption, and permanent revocation after interruption/exit/restart; diagnostic15/30-second lifetimes are not silently converted into production runtime policy.

To preserve the current real synchronous store/final-send seams, the proposal is a bounded synchronous native challenge serviced on a private dispatch queue, with an absolute monotonic deadline and no dependence on the blocked JS event loop. The exact bound is an implementation-reviewed constant, not a caller option. It is local IPC, not provider I/O; nevertheless its worst-case duration must be charged to existing transaction/action budgets, and expiry must be checked monotonically after it returns. A status lease or last-heartbeat cache is not equivalent. A fresh check immediately before submission does not promise the broker lives throughout a remote effect; later uncertainty remains in the existing one-attempt ledger.

There is a second inseparable proof obligation: an arbitrary alternate-main process must not forge the imported canonical dependency through loader/cache replacement and thereby obtain real compiled-consumer authority. Actual main/cache/loader checks and module identity must be exercised on the final compiled consumer, not assumed from source. If that test can bypass the native assertion, the design has not qualified the consumer and must stop for a concrete trust-boundary correction. Do not wave it away by accepting a matching hash, a callable-looking export or a fabricated same-module object. This requirement does not add universal defense against malicious native code already inside the trusted runtime; it preserves the original no-caller-substitute/canonical-consumer boundary.

## One finite final-artifact matrix

Prepare all required scenarios against the SAME final source/build/package and real native code. Use one fixed reviewed harness/manifest, bounded cases and permanent claims; no ad hoc unreviewed main or per-case provider operation. Ordinary code/tests may prepare it, but actual image/restriction/service runs need one later exact reviewed execution authorization.

1. Positive fixed readonly/restricted canonical startup→same actual compiled store/isolatedPG→one fixed transport submission. Provider/credential responses may be simulated; origin, canonical package and compiled consumer must not be replaced.
2. Wrong/changed package, native dependency, writable mount/backing/alias or unexpected retained capability refuses before private state/application import. Preserve previous protected-resource semantics/results.
3. Direct import/custom main, independent same-signed Node, wrong broker/release, copied helper/app and forwarded message/connection cannot create private state or compiled-consumer authority. Foreign races may deny service but never mint authority.
4. Actual native/CJS cache clearing, cached exports, duplicate canonical modules, worker loads and native image aliases; constructor one-shot/freshness must hold on the exact packaged Node. If empty/cached exports bypass construction, record a design failure, not a synthetic-cache pass.
5. Reordered/repeated begin/ACK, stale nonce, child exit during exchanges, broker crash/restart and slot destruction refuse. No adoption or renewal; same exact pre-ACK canonical semantics remain those already reviewed, and any second private initialization/post-ACK re-exec refuses.
6. Actual current-origin loss before claim, before credential exposure and after intent but before final send produces the expected zero-effect boundary and durable uncertain history. No automatic retry/replay or resetting consumed attempts.
7. Same actual compiled consumer called through a forged dependency/cache or outside the qualified main refuses; source-level wrapper tests alone are insufficient.
8. Register ownership/real user consent and delayed read-only cleanup are recorded separately. Never unregister possibly preexisting/ambiguous state; no repeated unregister merely to get immediate process reaping.
