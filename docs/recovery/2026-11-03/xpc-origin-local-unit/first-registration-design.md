# First-registration state model — local correction review

This model corrects our agent-added literal0 guard within the existing local trusted-launch implementation approval. Independent source review precedes the local correction; no extra user design approval is required merely to repair that mistaken assumption. No host/status rerun, service registration, relocation or positive protocol experiment is included. The old exact driver remains frozen/refusing3, and the stopped invocation stays in history.

## Evidence and supported operations

The local SDK says service status3 is generic NotFound, not an authenticated assertion of absence. Actual logs resolved this calling bundle and its plist but found no BackgroundTaskManagement disposition record. Neither that log string nor status3 becomes security authority. The same SDK specifies that `registerAndReturnError:` returns YES for successful registration, rejects an already-registered service with `kSMErrorAlreadyRegistered`, and may reject user-denied or invalid-signature operations. An existing registered-but-notloaded service must not be inferred absent from `launchctl print` alone.

`agentServiceWithPlistName:` is scoped to the calling app's own main bundle and its `Contents/Library/LaunchAgents` plist. The proposed registration-only host must record its actual `NSBundle.mainBundle` bundle URL, executable URL and expected identifier in a bounded structured receipt, and require those to equal the frozen prepared app before calling SMAppService. Do not use a caller-supplied app/service selector or private BTM database. No `/Applications` relocation or LaunchServices installation is needed by this design; actual OS eligibility remains unproven until the supported registration call answers.

## State transition and ownership

1. Recheck exact frozen app hashes/signature, private artifact ownership, exact host/broker/plist paths, and unused local experiment/spawn claims. Existing claims refuse. Record read-only SM status as diagnostic evidence. Refuse Enabled or RequiresApproval and any loaded exact-label launchd service without changing it.
2. For NotRegistered0 or generic NotFound3, **request explicit user authorization for one first-registration operation**, acknowledging that3 does not prove prior state. It authorizes only the OS's supported registration request for this exact calling app. Independent review must verify preservation of the original ownership/status/approval/cleanup contract; one new exact-run approval remains required. This is not permission to relabel3 as0 or bypass the existing driver.
3. Consume the one-use host claim and fsync an intent receipt before the supported call. The host returns bounded structured `registered`, error domain/code and the exact calling-app identity/path, not only an opaque exit70. No private NSError userInfo or unbounded error payload is retained.
4. Only an unambiguous `registerAndReturnError:YES` result from that exact pinned host, durably acknowledged in the same run, grants the driver permission to run its one diagnostic controller and later unregister **that same calling app's service**. This is ownership of a temporary diagnostic registration, not issuer or execution authority.
5. A NO/error/timeout/lost acknowledgement stops without a probe **and without automatic unregister**. AlreadyRegistered, prior denied/pending state and generic errors must never trigger cleanup of possibly preexisting registration. The current driver's unconditional unregister-after-any-register-attempt behavior must be corrected before this changed design is usable. Ambiguous new service state remains material failure, with the intent/receipt preserved for separately authorized exact cleanup. No automatic register retry, status loop, settings change or user-consent simulation.
6. Following confirmed successful registration, one bounded probe runs and `finally` unregisters only that known-owned registration. Save the unregister result, final calling-app service status and exact-label launchd absence. Unknown cleanup remains failure. Host crash after successful OS registration but before durable acknowledgement remains an explicit unresolved cleanup case, not grounds to adopt/replay a run.

## Required ordinary tests before any new run proposal

Use simulated SM results only: status0 first registration; status3 diagnostic plus explicitly authorized successful request; status1/2 preexisting refusal; loaded service refusal; AlreadyRegistered NO must neither probe nor unregister; generic error/timeout/lost acknowledgement must neither probe nor unregister; YES ownership permits one probe and cleanup; cleanup failure preserves unknown; exact bundle mismatch and existing consumed claim refuse. Read-only bundle reporting must be tested without registration only if separately permitted. Do not invoke a new positive XPC run until compiled/signed artifacts, all hashes and the whole exact changed run are reviewed.

This supplies a feasible first-registration route using the documented operation itself as the transition authority, while preserving unknown prestate and noninterference. It does not establish production trust, current liveness, restricted canonical startup or same compiled-consumer admission.
