# Workload identity public-source review — not runtime qualification

Owner's three-page public GitHub documentation exception was consumed: one official documentation search, these three official pages, and cached section inspection. No account/repository API, discovery/JWKS endpoint, real token, workflow, credentials or provider action was requested.

1. [GitHub OIDC reference](https://docs.github.com/en/actions/reference/security/oidc): documents signed workflow-source/run/attempt claims and unique token identity. Audience may be customized; subject varies with environment, repository identity settings and event. Newer, transferred or renamed repositories can use permanent repository/owner identifiers in the subject. Therefore no default subject or repository identity can be inferred from the display name. The local private profile must bind actual stable IDs, exact subject/audience, workflow source and run/attempt; no live profile is qualified. Key provenance/discovery and actual repository configuration still need separately authorized observation.
2. [Reusable workflow OIDC](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments/oidc-with-reusable-workflows): caller identity and invoked-workflow identity differ. A caller match alone cannot qualify a different invoked implementation. The current fixed direct-workflow candidate refuses reusable-workflow claims instead of silently treating the caller as the executor. The documented header includes `x5t`; bounded string metadata is now accepted without using it to select a trust source or fetch a key. Unknown remote key hints remain refused.
3. [Actions contexts reference](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts): attempt numbering starts at one and changes on rerun; run identity survives reruns, and source interpretation depends on the event. Workflow source has its own commit identity. Local code requires the exact already-selected run/attempt, manual event, branch and fixed workflow/source profile. Environment variables are not substituted for a signed token.
