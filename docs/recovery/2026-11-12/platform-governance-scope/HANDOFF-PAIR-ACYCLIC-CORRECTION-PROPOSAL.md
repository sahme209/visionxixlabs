# Acyclic GitHub handoff artifact correction — proposed LOCAL design

## Reproduced source problem
The final whole-source review found that the compiled runner embeds bootstrapProfile.workflowSha256; the generated workflow embeds that runner's SHA256 at the same workflowPath. A truthful generated pair therefore needs a cryptographic fixed point. The source compiler currently returns metadata-only output when its injected qualifiers are no-ops; those synthetic tests never established a self-consistent installable pair. This is a local composition defect, not merely a held real-qualification gate. Do not change any expected hash to hide it, install the pair, open the batched PR as ready, or enable a fallback.

An ordinary isolated diagnostic uses the actual existing compiler and generated workflow (no emitted-code execution, network or credentials). ## Recommended construction: static runner, then workflow, then qualified pair
1. Compile only the fixed bootstrap CHANNEL coordinates/configuration into the runner, excluding the not-yet-generated workflow digest. Repository/ref/path, native token channel allowlist, audience, paired endpoints, environment/protection revision, expiry and the closed compiler/source/dependency graph remain pinned. Use a new strict source-definition version; do not reinterpret or upgrade old artifact/profile receipts.
2. Generate the fixed workflow that checks the exact runner digest as today. Its fixed wrapper additionally reads only the checked-out workflow at its one fixed path, through a bounded regular-file/no-symlink descriptor, computes its full-byte SHA256 and supplies that value to the fixed runner as CONTEXT only. The workflow cannot embed its own expected digest, nor may the runner contain it. No arbitrary file/path, command, shell snippet, audience or endpoint is accepted.
3. The runner validates the context digest structurally and binds it into the existing workload reference. It DOES NOT declare that digest qualified. This is the same distinction as existing GITHUB_SHA/WORKFLOW_SHA hints: hints may reject, but never authenticate or approve. Existing backend signature/JWT repository/ref/commit/run-attempt checks and private exact workflow-digest/protection qualification remain mandatory. Missing or different trusted expected workflow bytes refuses before any private AWS credential acquisition/send. No environment value or locally measured hash is an issuer or a native qualification result.
4. Once BOTH files exist, compute actual runner/workflow hashes together and present the complete immutable pair, configuration, source/dependency/tool evidence to the existing private build-qualification port. Recheck the identical source/channel/pair around awaits. Qualification must bind both actual files and their exact paths; no successful default qualifier, new key, new authority source, signing operation, API fetch or protected setting is created. The final qualified metadata is a detached private record, not embedded back into either file. Historical definitions remain historical and unavailable for silent reuse.
5. Keep createGithubJobEntry's old fixed-full-profile behavior for readable historical/source tests only if needed; the new compiler must exclusively use its new measured-context constructor and new definition version. The retired active workflow remains retired. No fallback may restore direct GitHub-to-AWS exchange or native SDK environment/file credential selection.
