# TypeScript 7 migration — in progress

Tailwind PR #319 merged green as `77d932c5` before this batch began.
Production remains build 4, unchanged.

## Compatibility decision

The first workflow-generated direct TypeScript 7.0.2 graph reproduces two real
problems: `createSourceFile`/`transpileModule` are absent, and `npm ls typescript`
reports invalid ESLint peer dependencies. It must not be merged or forced.

Microsoft's official transition documents an aliased side-by-side installation:
https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/

Retain the existing exact 5.9.3 compiler API for Next's owned website adapter,
ESLint, AST inventories and reviewed fixture emitters. Add official native
7.0.2 under `@typescript/native` and invoke it explicitly for root and desktop
checks, avoiding ambiguous npm binary links. Keeping API 5.9.3 instead of moving
it to 6 also preserves the current valid ESLint peers and exact historical
compiler evidence. This is a deliberate transition, not removal of all older
compiler code. Do not claim that Next's own additional API check is native.

The dependency workflow permits only this fixed alias source, still with exact
versions. It rejects arbitrary aliases, files/URLs, flags and command syntax.
All lockfile changes are generated by `dependency-fix.yml`; no lockfile hand edits.

## Gates still pending

Generated root/desktop graphs, actual native acceptance/refusal checks, full
application type checks, tests/builds, independent review and green CI remain
required. Native checks must preserve strict checking, not suppress errors.
No production activation, database, credentials, signing, installer or provider
acceptance is included. Existing qualification packets are not renewed.
