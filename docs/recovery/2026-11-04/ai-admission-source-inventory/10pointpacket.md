# Prepared AI admission call-site source inventory

1. **Goal:** identify concrete declaration-resolved inference/health caller lanes to inform a reviewed migration; not implement more refusal guards.
2. **Scope:** analysis of app/lib non-test `.ts/.tsx`; exclude declaration files, `__tests__`, `__smoke__`, `.test`, `.spec` and `.smoke` (diagnostic-only smoke callers are excluded). Imported files may be loaded by TypeScript for resolution; only selected roots are enumerated for call sites.
3. **Tool:** existing installed TypeScript API only, fixed canonical paths, no dependencies/install. Read actual tsconfig options, createProgram with noEmit, no incremental/composite/plugin execution. Never require application modules or SDK runtime.
4. **Resolution:** inspect actual call-expression resolved signatures. Selected origins are manager, orchestrator, Gateway provider, AIProvider interface and installed external `ai` index declarations. Constructors/status/config metadata excluded. Renamed imports can resolve through declared method names. SDK declaration identity uses canonical realpath equality to the fixed installed ai/dist/index.d.ts path, including symlinked packages.
5. **Ambiguity:** method-name candidates resolving elsewhere/unresolved are separate, not authority findings. Aggregate counts separately disclose all call expressions, statically unnameable calls and unresolved calls outside the keyword bucket; these counts may overlap and are not additional authority findings. Computed/dynamic aliases without a selected resolved signature can be missed. Interface-declared provider calls have their own lexical classification; imported components/packages outside app/lib are not enumerated. This is not universal coverage.
6. **Evidence:** deterministic ordinal source/line/column order, caller whole-file SHA, declaration path/line/whole-file SHA, method/classification/enclosing function names and counts. No prompt or argument content. Root/source/direct installed tool hashes included; compiler syntactic diagnostics are counts only, not a type pass.
7. **Environment/OS:** root executes once with fixed Node, scrubbed explicit env and owned cached directory; kernel denies all network and file writes. Capture stdout outside child. No source imports, SDK/provider/AI/DB/UI/credentials/inference/network.
8. **Bounds:** one newly owned child process group,45second timeout with only owned group termination/reap, no retry. Root must use bounded output capture (suggest16MiB; source inventory can exceed tiny unit-test caps), preserving raw output/result and exact script SHA. Preparation does not execute this script.
9. **Acceptance:** successful JSON parse/schema/count checks and normal exit; timeout/import/resolution errors remain failures. Counts are lexical lane counts, never current authorization/admission/financial/caller reachability acceptance. Manager admitted method naming alone does not prove valid consumed approval; normal calls may already be admitted by an upstream pipeline/ledger, so caller review is required.
10. **Remaining work:** parent reviews actual output to select a proper caller migration design. No features/schema/activation/deployment/build/test/claim of A7, billing or Governance completion. Production and existing previews/native sessions untouched.
