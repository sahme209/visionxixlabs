# Shared best-effort audit failure privacy — local repair

The actual audit helper no longer passes arbitrary thrown database objects to console.error when an audit insert fails. It emits its existing marker and a fixed failure code. The helper still resolves without retry after failure; successful database arguments, optional lead/metadata defaults and caller-provided metadata are unchanged. This does not make nonblocking audit persistence guaranteed.

Four actual-helper tests mock only the external Prisma create operation. The Error and structured-object privacy cases failed before the change while two success/default controls passed; all four pass after the change. Console payload checks reject both raw exception objects and sentinel-bearing strings. Success/failure create counts, exact stored payload and void resolution are checked. Tests ran under the existing bounded network-denied/owned-write-only harness. No real audit/database/provider/AI operation occurred. Whole-prior-file reconstruction passes by reverting only the diagnostic value/catch binding.

This is not arbitrary caller-metadata sanitization, a complete audit-integrity solution, complete security/Governance qualification, a full-project suite or production/native acceptance.
