## Actual source restriction and why change

system_build_inputs._observe currently requires guardSupplement format1, historical allFourStaticSequencesAccepted=false, and one supplement.packetSha256 equal to each owner/maintenance/bootstrap/guard signingPacket hash. This is correct for the preserved old four-leaf repair but unsuitable as the ONLY future input path. New complete configuration needs controller→broker→guard phase signatures. Independent existing leaf preparations/signing histories must not be merged into a fabricated historical packet, and a fresh valid result must not manufacture a failed history merely to satisfy an old reconciliation shape.

No new native compilation or signing has occurred. NATIVE-BATCH-REVIEW/PLAN are on hold pending this real composition gap; they do not authorize operations or prove those outputs would currently join. Existing APIs still support selected signed query bytes; no vendor authenticity gate or generic engine selector is added.
