## Actual gap and implementation

The local limits components formerly retained original pending mutations only in component memory. Server request lookup already binds operation/nonce to the original current paired actor/session and immutable historical receipt. Recorded-request directories cannot discover a transaction that never committed. Local restart recovery now retains the original locator **before** invoking the existing mutation, so an unconfirmed request remains observable after unmount/restart without resubmission.

- `desktop/src/lib/executionPolicyRecoveryStore.ts`: distinct namespace+original-nonce keys, canonical supported service origin + organization + user. Root-path origins only; credentials/query/fragment/custom service paths refuse. Values contain only strict format/owner, operation/nonce, known policy ID/digest/version metadata where available, and local creation time. Proposals have **only operation+nonce**; no fabricated pre-ack ID/digest, policy content, repository scope, executors/member list, credential or token. No expiry, automatic eviction or reset.
- Each original gets a separate key; interleaved windows cannot overwrite a sibling aggregate value. Enumeration is bounded to10000 total storage keys,20 matching records and4096 bytes per record; corrupt/conflicting/incomplete/overflow/read/write failure blocks affected submissions and is never absence. Per-record acknowledgment deletes only the exact original locator after a verified acknowledgment/observation. This is not a transactional cross-window mutation lock or tamper-proof ledger.
- `desktop/src/lib/useExecutionPolicyRecovery.ts`: inert local-storage state and notifications only. Current config/revision ownership remains with existing components; no credentials are persisted. Different service/org/user locators are not adopted. Same-user replacement pairing does not rewrite or delete the old locator: the server still requires the original live paired session for lookup.
- `desktop/src/lib/governanceExecutionPolicy.ts`: **separate** `observeOriginal` facade uses the existing fixed lookup POST body (operation+original nonce). The original full-mutation `lookup` and exact `matches` semantics are unchanged. The sparse facade validates strict historical DTO, proposal actor/org/status, known decision ID/digest/version/reviewer nonce as applicable, and returns only a historical summary with `exactProposalContentVerified:false` and `executionAuthorized:false`, never a policy payload, form or current authority. Activation receipt has only digest/pointer version; those match known metadata while tenant/original-session binding remains the existing server lookup's responsibility. No invented response fields or new backend trust.
- `GovernanceExecutionPolicyPanel.tsx` / `GovernanceExecutionPolicyProposal.tsx`: write and verify locator before the mutation callback; failed persistence sends zero mutation. Current async ownership is checked again before submission and after results. Acknowledged exact mutation results use existing validators; unknown/absent/refused lookups retain originals. Restart recovery performs a deliberate read-only observation, never mutation, replay, new nonce, form restoration, approval adoption or activation. A found sparse observation clears only its locator and removes displayed policy/pointer/review state; a deliberate exact current read is needed before a later decision.

Local storage is not authority. Corrupt or missing data does not grant server permission or prove a request never reached the server. The journal cannot attest complete history after external deletion/device loss; no retry or single-attempt safety claim rests on local absence. Existing durable server nonce/CAS/session checks remain authoritative.

## Containment exception: preserve existing revocation

Root reviewed and accepted an exact restriction to avoid extending a coarse journal hold into a revocation deadlock. Any unresolved locator blocks new **propose/approve/activate** actions. A current administrator may still deliberately acknowledge and revoke a separately loaded exact current policy using the existing backend permission/version checks, unless an unresolved revoke already names that **same policy ID**. A new per-nonce revoke locator is verified before sending; siblings remain unchanged. An unknown same-target revoke stays original-lookup-only, with no replacement nonce. Unknown proposal metadata has no target; none is invented.

Corrupt, overflowing or unavailable journal state cannot establish absence of a same-target unknown revoke and continues to refuse. This restores the existing containment capability rather than adding a server grant. No old approval, original nonce or retry budget is reused.
