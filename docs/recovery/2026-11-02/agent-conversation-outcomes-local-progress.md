# Saved Agent outcomes in the next explicit conversation request — local increment

## Confirmed gap and implementation

Approval records correctly say the requester must execute separately, but the next user-message route previously read only the old conversation turns. It did not consult separately saved execution outcomes. A confirmed/refused/unknown durable result could therefore be absent from the model's current context while the older waiting message remained.

The store now supplies a bounded read-only conversationHistory view. It checks the actual current paired reader/member/session, locks and verifies exact conversation ownership, filters by tenant/original requester/conversation and validates each stored operation/event history. At most five recent records are exposed, using a sixth row only as an omission sentinel. The observation clock is shared across returned records. A new same-user paired session may recover history but gains no right to execute an old-session operation. No state/event/conversation row is written by this reader.

A server-only facade exposes only this read, not prepare/claim/execute. It independently re-authenticates the paired reader, refuses an executor purpose, propagates cancellation and emits no raw private error. A strict formatter admits only closed metadata and at most2,000 characters; omitted rows/reference details are labeled partial. Empty data is explicitly not proof that no provider action occurred. Source arguments, review/claim proofs, credentials and raw provider output never enter this context.

The actual message route calls it only for an explicit authenticated user message in that user's owned conversation. Client-supplied execution-history fields are ignored. The decision loop receives a separate executionHistoryContext field, labeled historical data rather than authoritative UI selections or permission. Oversized context is replaced with an unavailable notice instead of partial JSON. No earlier turn is rewritten, no background model call or queued continuation starts, and no provider action is retried. Existing current model-policy, credit and action-approval boundaries are unchanged; this is not a new execution authority or a claim that the broader AI/security audit is complete.
