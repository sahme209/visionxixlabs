## Three separate identities

| Record | Truthful meaning | Cannot establish |
|---|---|---|
| Source/archive receipt | Exact source bytes and recorded build invocation/result. | Emitted bundle, external/generated dependency closure, actual running issuer or complete fleet. |
| Execution package manifest | Canonical identity of a closed set of emitted executable/support files and runtime prerequisites. | That an arbitrary process loaded those bytes or no other issuer exists. |
| Controlled local launch evidence | A specific owned process was started through a verified launch path from that exact package, with explicit limits. | Production attestation, hostile-host resistance, old-token invalidation or deployment-wide absence of old runtimes. |

**Recommendation:** do not populate V1 `issuerArtifactDigest` in real outbound bindings until the third record is available for the actual issuing process. Keep unsupported wiring unavailable. An optional observed-file manifest can be retained as explicitly unqualified evidence outside that field; it cannot unlock a slot, coverage or activation. Do not weaken the strict V1 schema to accept `unknown` or reinterpret a source hash as execution identity.

## Minimal proposed local package/launch protocol

1. **Build once, package that output.** Retain the existing source archive/build receipt unchanged. Construct a new immutable local package from the successful emitted build; do not compile again during identity verification or run source tests in place of compiled code. Choose and validate one supported local `next start` package profile first. Switching to standalone is an alternative requiring configuration/build review, not an already available artifact.
2. **Close the actual file set.** Include compiled routes/chunks and Next server/runtime/config/manifests, traced source/support files, all required external/transitive package files, generated Prisma client/engine, native addons and the actual Node runtime/native-library prerequisites. Materialize dependencies rather than preserving the current mutable workspace symlink. Directory trace entries require bounded recursive enumeration; symlink targets must be explicitly inside the sealed package or separately bound runtime closure. Missing/dangling/outside-root/partial/ambiguous dynamic dependencies refuse. Tracing alone does not prove completeness; verify package execution without source-workspace/dependency fallback.
3. **Canonical manifest.** Proposed `axiom.local-issuer-package/1` records source/archive/build provenance; exact entrypoints/profile; normalized relative paths, byte sizes, SHA-256 and executable modes; explicit runtime/architecture/Node/dependency identity; declared verified inclusions/exclusions and completeness. Sort paths, reject traversal/case collisions/duplicate aliases and non-regular special files. Compute the package digest over canonical manifest content, excluding its own digest/launch receipts to avoid self-reference. Mutable logs/cache/data live outside the executable root; executable writes/dynamic module download are unsupported. Do not include secrets or environment dumps.
4. **Controlled launch, before application imports.** A separately reviewed local launcher verifies the complete package and runtime against the manifest, seals or enforces an immutable executable root, rejects loader/preload/module-path overrides and unbound executable config, and launches the declared compiled entrypoint with the verified Node runtime. The application must receive identity through a private bootstrap-owned capability tied to that launch, not an HTTP argument, environment digest/readiness flag or writable JSON file. Revalidation must not bless already-loaded code after files are edited: loaded-module cache and pre-launch mutation races require explicit tests. This is a new trust boundary, not a helper that merely hashes files inside a running app.
5. **One exact issuer identity.** The runtime provider supplies the canonical package digest only when the current issuer is actually inside that verified launch and the versioned private capability matches its compiled profile. The server derives outbound `issuerArtifactDigest` from that provider; request/model/plugin data cannot choose it. All issuer routes/workers in the supported profile must originate from the same package or separately declared packages. Development servers, partial bundles, module mocks and unverified external workers refuse real binding.
6. **Preserve qualification separation.** Return local evidence as explicitly `local_verified_launch`, with fleet/legacy/runtime-transition qualification **unavailable** and `executionAuthorized: false`. The digest means only the bound local package/launch identity; it is not a signature or an endorsement of its safety. Existing actual role/source/approval/claim/credential/drain verifiers remain mandatory. Activation must still reject missing complete coverage, external fleet, legacy bearer and provider-quiescence qualification even if the local package verifies.

The private bootstrap capability is not yet designed or implemented in the existing Next build. Before approving runtime code, confirm whether the supported local packaging/launcher can actually establish this in the compiled module topology. If not, stop and propose a separately verifiable launcher/container boundary; do not inject a claimed digest to keep the outbound integration moving.

## Alternatives and selection

- **Recommended:** exact closed package plus controlled local compiled launch, then private issuer binding. Largest honest advance using current build provenance, with a clearly bounded local trust model. No claim of hostile-host or fleet attestation.
- **Future standalone/container package:** potentially simpler deployment closure, but requires a real packaging/build change, runtime/native dependency verification and separate acceptance. An image label or supplied image digest without actual image/process binding is insufficient.
- **Observed current files only:** useful audit metadata, explicitly unqualified; do not assign it to the V1 executing-issuer field or admit real outbound work from it. Hashing already loaded modules does not establish which bytes executed, especially after file replacement or dynamic import.

## Validation-first acceptance

1. **Same artifact:** produce package manifest from an exact successful archive build, then invoke the real compiled issuer/store/transport composition from that same verified package. No second compile, Vitest module replacement, source import fallback or symlink back to workspace. Use isolated auth/provider simulations clearly labeled; this proves local package binding only.
2. **Tamper/missing:** change one compiled issuer chunk, transitive external file, Prisma engine/native addon, manifest, runtime binary or executable mode; omit a dependency; introduce traversal/duplicate/case alias or outside-root symlink. Verification refuses before reservation/credential resolution/provider write. Wrong profile/entrypoint/package capability cannot substitute.
3. **Partial/transitive:** a route-only hash, source SHA, BUILD_ID, lockfile alone, successful trace generation, directory entry without contents, guessed module list and an incomplete trace must all fail. Exercise dynamically loaded server dependencies, optional/native resolution and required source-support reads in the isolated compiled package. Unsupported closure remains unavailable rather than dropping files.
4. **Loaded-code consistency:** test file replacement between verification and import, after import, concurrent imports, extra module roots/preloads, process restart and attempted development/HMR execution. Missing immutable launch assurance refuses; post-load rehash cannot retroactively attest memory. Keep runtime OS/native prerequisites explicit rather than claiming JavaScript hashes cover the host.
5. **No self-report:** spoof environment build ID/digest, request field, readiness boolean, copied descriptor or protocol-string hash. None constructs the private bootstrap capability or an executing-issuer digest. Missing identity means no outbound reservation/mint; no default or wildcard.
6. **Separation:** verified local identity still yields unavailable fleet/legacy qualification and cannot activate enrollment. Unknown outbound/credential records remain indefinite blockers; genuine provider readback, independent human review and separately authorized fleet transition are not fabricated by the package test.
7. **Recovery/provenance:** retain original source/build/package/launch receipts and hashes; cache keys bind package/profile/process lifetime. Restart re-verifies without replaying consumed operations. Bundle/manifest upgrades produce new identities; rollback cannot masquerade as a current protocol. No signing key, grant, setting, network action or deployment is required by this document.
