# Local engine binding: original-design alignment

Root-reviewed ruling: mandatory upstream vendor-checksum authentication was added
by the implementation agent, not required by the original user-approved local
issuer-package design. That design explicitly separates exact local artifact
identity from security endorsement, and accepts declared trusted macOS host/runtime
prerequisites. Vendor authentication must not become an extra blocker for that
approved model. No failed checksum request is reinterpreted as a success.

This plan binds **trusted local build input bytes**, not authenticated Prisma
releases. Upstream authenticity and engine-commit authenticity remain unavailable.
An expected commit from the pinned JavaScript package or cache directory is only
the requested version, never evidence authenticating the native binary. There is
no new network permission; a late approval for the now-unneeded diagnostic must be
reconciled with the parent before any request. No request is executed by this plan.

## Proposed preparation algorithm

1. Require the exact owned Git archive stage and its committed schema/lock bytes.
   Verify installed selected Prisma generation-source packages against the actual
   SHA512-verified pinned tarball bytes. No workspace dependency or generated client
   fallback is accepted. This selected-source observation is not full runtime closure.
2. Select exactly the existing local query-library and schema-engine files as
   declared host-trusted inputs. Open with `O_NOFOLLOW`; require regular files,
   single links, finite bounded sizes, and stable dev/inode/mode/link count/size/
   mtime/ctime before open, on the descriptor, and at completion/path recheck.
3. Parse the bounded native header as thin little-endian Mach-O64, arm64 subtype0.
   Require the query library's declared type `MH_DYLIB` and schema engine's
   `MH_EXECUTE`; refuse unknown, wrong-architecture, fat/ambiguous, truncated or
   malformed load-command bounds. This proves header compatibility only, not
   executable safety or upstream authorship.
4. Stream bounded bytes into new exclusive files inside a new owned private engine
   directory. Compute SHA256/size during copying, then independently re-read and
   verify the owned copies. No overwrites or modification of the original cache.
   Give only the needed owned execution/read modes. An exclusive secret-free receipt
   records exact byte identity, declared platform, source observation, requested
   version, and `upstreamAuthenticity: unavailable`/trusted-local-host provenance.
5. Immediately before any later reviewed execution, reverify receipt/copy bytes,
   exact archive schema/lock and selected SRI-pinned generation sources. Use a clean
   environment with fixed `PRISMA_QUERY_ENGINE_LIBRARY` and
   `PRISMA_SCHEMA_ENGINE_BINARY` pointing only at those owned verified copies.
   Deny networking and writes to source cache/original repository. No downloads,
   lifecycle scripts, npm fallback, migration, introspection, or database connection.
6. Run only explicit archived Prisma generation after mechanical tests and review.
   A fixed trusted recipe leader exit and exact required generated bytes can be
   observed at a particular time only. They do not prove completed/quiescent
   generation, compatibility, immutable packaging or loaded code. Compatibility
   and complete descendant quiescence remain unavailable/false.
   Unknown/missing/generated native closure refuses package qualification.
7. Build is a separate reviewed step. Package the resulting exact output without
   rebuilding for identity verification. The existing private bootstrap, complete
   sealed runtime/consumer, fleet, legacy, activation and execution qualifications
   remain unavailable until their actual independent gates pass.

## Mechanical test plan before actual engine execution

Use explicitly synthetic owned native-header fixtures (never call them real
engines). Test exact-copy/hash/mode receipts, wrong architecture/type, malformed
or truncated headers/load commands, unsupported fat images, symlink/hardlink,
mutation/growth, copied-byte tampering, existing destination/receipt collisions,
source immutability, fixed clean generation inputs, and no implicit execution.
Verify actual source-package bytes independently from those parser fixtures.

Only after mechanical tests and independent source review may the parent authorize
the first actual local engine execution/generation. No such execution, generation,
build, identity grant, or native bootstrap change has occurred under this plan.

## Offline generation executor: unqualified output observations only

`execute_generation` is now implemented in `scripts/local_prisma_engine_inputs.py`.
It accepts exact source coordinates and owned paths, not prepared JSON or a verifier
boolean, and has no automatic CLI/import execution. It recomputes preparation before
launch and again after the pinned Node version child returns; changed preparation
refuses before the archived generation CLI starts. It hashes/rechecks the pinned
Node bytes and requires actual `v24.21.0` output. Exclusive attempt/result/log files
are created before child launch; existing files refuse without overwrite.

The child receives a fixed clean environment and fixed archived Prisma CLI/schema
arguments with the exact owned engine overrides. Its actual Seatbelt policy denies
all networking and filesystem writes except the owned archive stage, owned temporary
output, and designated logs; explicit write denials cover the original repository,
source npm cache, original Prisma engine cache, and owned bound-engine directory.
There is no npm/lifecycle/download/migration/introspection/database command. Parent
wall deadlines kill the original process group and reap its leader only. Detached
children can escape that group and remain alive; complete descendant cleanup is
not established. Nonzero exit, output-limit violations, missing/aliased outputs,
changed source inputs, or wrong generated-query bytes refuse output verification.

After a successful child exit, the executor checks required generated client files,
exact generated schema and query-engine copy SHA256/size, selected installed source
packages, original archived schema/lock/package, bound engines and Node again.
This checks exact required bytes at observation time only, not completed/quiescent
generation, compatibility, immutable packaging, loaded code, full dynamic/native
runtime closure, or upstream authenticity. The result is
`generated_outputs_observed_unqualified` with `generatedOutputsVerified:true` only
after those byte checks. `generationCompatibilityVerified` is ALWAYS false and
`descendantQuiescence`, runtime, issuer and activation remain unavailable. A detached
writer may modify the stage afterward; later packaging must freshly verify and seal
under the original gates. This is an ordinary fixed trusted-host build recipe, not
a general untrusted-code containment service or a new fleet-proof prerequisite.

## Final review corrections, November 3

The foreign dynamically loaded builder owns a distinct `Unavailable(RuntimeError)`
class. Real instances raised after the Node version check or after fixture output
production previously bypassed the failure handler and left reserved result files
empty. Genuine RED: `/private/tmp/axiom-local-generation-foreign-error-red.log`
(two cases). Expected RuntimeError helpers are now caught and foreign messages are
replaced with a fixed safe reason; durable unavailable results are written. Before-CLI
failure still launches no CLI. KeyboardInterrupt/BaseException cleanup behavior is
unchanged; it is not converted into a truth result.

An actual finite detached/setsid fixture child survived the leader's original process
group and continued writing an owned heartbeat after output hashes. Genuine RED:
`/private/tmp/axiom-local-generation-detached-red.log`, where the prior result wrongly
set compatibility true. The corrected contract never does so. The test verifies its
unique token and owned marker pathname in the actual PID command and matching PGID,
then explicitly kills that exact known owned PID in finally and confirms host reaping.
It does not claim that the generic runner discovered or cleaned detached children.
The initial detached fixture's ignored stdio open was denied; inherited descriptors
were used to exercise the actual group escape without weakening the production profile.
