## Smallest mandatory wiring order

1. **Strict foundation before callers.** Agree immutable organization/epoch/operation/attempt/profile/target/source/connection/artifact bindings, versioned history/CAS, null pre-barrier epoch and all-tenant history semantics. Under the existing organization-first lock, a committed draining barrier refuses new applicable reservations. An empty new ledger says nothing about older runtimes or tokens. Require trusted current paired/rule authority; reservation itself never grants execution. Existing exact human approval, source, capability, numeric policy and one-attempt gates remain mandatory.
2. **Reserve before each consequential credential mint.** Wrap the actual shared purpose-bound issuer and merge credential adapter, not merely executor `claim`. Persist unknown pending issuance before POST; bind exact actual provider expiry/rights after response without storing bearer material. Lost mint/commit acknowledgment remains blocking, never guessed absent. Cover repeated preflight and final-transport mints, configured/custom adapters and all actual callers. Airflow needs a supported credential-exposure profile for auth/configured bearer paths before claiming that population safe; no JWT decoding or guessed lifetime replaces provider semantics. Do not silently repurpose native Git lease records.
3. **Reserve exact outbound work before physical submission can escape.** Bind the existing immutable operation and attempt; for scheduled Airflow bind its recorded occurrence and deterministic ID, and for direct Airflow retain its original server-generated ID rather than generating a new identity for recovery. Failed claim must preserve existing approval/attempt rollback. A remaining reserved slot can conservatively block drain until a separately supported no-submission resolution; it must not disappear on timeout.
4. **Use a dedicated once-per-submission transport seam.** Both release transports invoke current authority multiple times, including before preparation and after acknowledgment/readback. Do not record intent on every `assertCurrent` invocation. The current local preparatory patch provides optional server-only `beforeSubmission` hooks at the actual final mutation boundaries. They are not yet installed against durable intent stores or credential tracking; absent hooks retain existing behavior, so their existence supplies no coverage. Wire these hooks to the real protocol before claiming integration. Its transaction takes the organization lock first, validates barrier/epoch, exact reserved slot, actual operation/source/current authority, and records `submission_intent` atomically with final DB checks. Publish a private one-use synchronous closure only after commit and original freshness checks. After that awaited hook, invoke the combined original session/provider/source/time proof and intent-consumption closure synchronously inside the final callback immediately before fetch. No remaining awaited authorization, no client DTO/boolean, no token/body persisted. All provider IO remains outside DB locks.
5. **Observe without closing effects automatically.** Preserve ordinary operation `finish` outcomes and consumed history. Record exact safe receipt/unknown observations against the slot via org-first CAS; ideally operation finish and observation share the existing transaction. If either persistence acknowledgment is lost, the already durable intent remains blocking. Confirmed merge, accepted deployment, Airflow success, local refusal, abort signal, process exit and worker/credential TTL are not generic quiescence. Never reset an attempt or mint a replacement run ID to reconcile. After an intent, a local pre-fetch refusal closes only through an exact supported no-submission protocol; otherwise it stays unknown.
6. **Qualify each provider-effect profile independently.** Require an actual verifier bound to tenant/epoch/slot/profile/target/run/attempt/source and original observations; reject arbitrary positive callbacks, client attestations and fabricated coverage. Keep read-only current-authority reconciliation available while draining. Missing, purged, partial, stale or ambiguous evidence leaves a blocker. Activation remains unavailable until every applicable writer, credential exposure and asynchronous effect is covered and old runtime/credential populations are independently qualified.

## Honest provider quiescence semantics

- **Merge:** exact PR merged/readback can establish the requested ref change. It cannot establish quiescence of triggered workflows/webhooks or an old issuer that can reuse a valid contents-write token. A narrow profile may qualify only its precise finite mutation; all resulting applicable effects and bearer exposure need separate registered blockers and supported verifiers. No generic merge-confirmed → tenant-safe transition.
- **Deployment:** a run receipt establishes acceptance. `completed` is necessary only where a supported profile says so, and remains insufficient for arbitrary workflow external children/retries/side effects. Cancellation acknowledgment alone is insufficient. Without a real profile-specific no-future-effect or qualified stop+readback verifier, deployment slots remain blocking.
- **Airflow:** DAG/task state must include the actual profile's retries, deferrals, child runs and external effects; “success” alone is insufficient. Existing task observation intentionally does not expose credentials/logs/XCom, and this protocol must not expand that payload to fabricate evidence. Unsupported DAG/auth profiles remain unqualified.
- **Credentials:** actual provider expiration/revocation can end future bearer exposure only when provider semantics support it; it cannot erase requests accepted earlier. Configured/static/pre-ledger credentials and old processes require complete provider/control-plane qualification, not an empty ledger, elapsed grace period, self-reported artifact or key rotation assumption.

## Preparatory transport seam source review

The optional hooks are called once after ordinary provider preparation and final current authority, never during repeated readback/authority callbacks. A configured hook must return a private function; missing/malformed return values refuse. Both fixed transports invoke intent freshness followed by retained original authority synchronously immediately before the mutation fetch. This preserves cancellation/deadline/window checks across the hook await. Read-only review found no important issue in these two preparatory source changes. The reported 49 fixed-transport regressions are local simulated-provider qualification, not actual durable slot wiring, credential tracking, effect quiescence, manifest approval or activation evidence. No tests were rerun for this independent source audit.
