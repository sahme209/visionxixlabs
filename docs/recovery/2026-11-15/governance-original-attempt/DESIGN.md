# Original external attempt gate — proposed local source contract

Design only. No implementation, real journal, process launch, native compile/run, credential/account/provider/database access, resource, deployment, enablement or spending. Owner decision is required before this new authority component is implemented. This closes neither the full external supervisor nor host qualification.

## Current source evidence and exact missing behavior

The new operational owner preserves an exclusive `/run/axiom-operational-time/accepted` marker. It may fail before creating that marker, and `/run` does not provide cross-reboot consumption. The older evaluation bootstrap's HostOps.reserve similarly creates only `/run/axiom-host-evaluation`; it is a different evaluation-only package and cannot be registered as the operational issuer. Its result correctly keeps hostTerminationVerified=false. Neither component is an external durable consume-before-start controller.

The proposed component is the **original external attempt gate**, not a provider adapter, generic workflow runner or permission grant. Before either original host creation or original owner start can be attempted, the original external controller must irreversibly consume the exact owner-approved attempt. A caller cannot reset that consumption by supplying another host/generation, changing a manifest, retrying, deleting a marker or starting a new controller invocation.

## Trust choice requiring explicit approval

Use a separately selected, operator-controlled external Linux controller and its persistent local filesystem. Trust that operator, OS, filesystem and storage to preserve successful fsync acknowledgements and retain the journal across controller/target restarts. This is an operational durability premise, not mathematically proven persistence, malicious-root/backup-rollback resistance or an independent distributed quorum. This controller identity/storage selection is NOT supplied by the current target-host policy approval. No actual controller machine, disk, credential, account or hosted service is selected by this local source decision.

The original attempt namespace is supplied by the explicit owner's one-run authorization. Creating a new ID is a new authorization, not an automatic retry. A production binding to that exact owner grant must be separately reviewed; a digest-shaped JSON string is not grant authenticity. Local code is inert until the real controlled supervisor obtains the authentic binding and calls it through its private seam. No CLI, network endpoint, environment switch, public qualifier or generic execution factory.

## Local interfaces and fixed contract

New private Python module `scripts/governance_original_attempt.py`, import without effects. Standard library only. No provider SDK, subprocess, socket, signal, clock/service or cloud operation. Its only direct effects in tests are files in a newly owned temporary fixture directory. Real journal construction/execution is outside this grant.

- `AttemptManifest`: fixed version1 closed schema with the original owner-grant reference, external-controller identity, approved attempt ID, exact package SHA256, immutable semantic-policy SHA256, target recipe SHA256 and fixed phase budget references. Values are bounded canonical ASCII with exact field order in the encoded record; unknown/duplicate fields, arbitrary extra resource IDs, paths, commands and bytes refuse. Final actual package/recipe hashes and budgets are absent now; no live manifest can be issued from placeholders.
- `consume_original_attempt(original_journal_binding, manifest, expected_manifest_digest, original_deadline_ns)`: private dependency of the future original supervisor. `original_journal_binding` is the future supervisor's original protected path/ancestor/FD binding, with exact controller identity, fixed selected root and journal name, held ancestor chain and final directory FD. It cannot be reconstructed from a raw FD, `/proc/self/fd`, manifest hash or caller-selected path. The real authentic binding supplier remains unavailable; explicit private fixture inputs may exercise file operations but cannot qualify a controller or produce a live grant. Require manifest digest to match the supervisor's original held approved manifest, never an alternative supplied by a guest or provider response. Before any marker operation, require an exact bounded positive absolute monotonic deadline already fixed by that original supervisor and reject if expired; never reset it on another phase or error. It validates and exclusively creates `consumed` relative to the held original journal directory, writes one bounded closed record fully, fsyncs that file, rechecks original held/named identity/metadata/exact bytes and fsyncs the original directory. Only success returns one in-memory opaque grant; any uncertainty refuses and never removes, truncates, rewrites or repairs the marker.
- `claim_creation(original_grant)`: one in-memory use for the future supervisor's exact original host creation. Every grant records its creating PID and belongs only to that original process. Check current PID BEFORE touching its thread lock; a fork-inherited grant always refuses without acquiring a possibly inherited locked mutex. Serialize claim and retirement under one original process-owned lock, recheck PID/currentness/cancellation/deadline inside that lock and irrevocably transition before return. Competing threads and close-versus-claim permit at most one successful claim, never two. No disk/bytes/copy/unpickle restore or registry re-enrollment. Python object/registry identity alone is not a process boundary. No provider effect is performed by this module. Calling this method consumes its phase BEFORE handing control back. A later process cannot load/restore a grant from disk.
- `claim_owner_start(original_grant, original_resource_receipt)`: one in-memory use after the original creation phase returned an exact validated receipt bound by the future supervisor; it consumes owner-start BEFORE control returns. The receipt never substitutes a generic caller-selected resource. This module must not claim receipt authenticity from shape/hash alone; only the future fixed provider adapter/original response registry may supply it. For this LOCAL primitive, leave this receipt seam negative-only in normal production imports/construction: every attempted owner-start claim remains unavailable until the actual authentic adapter is separately supplied/reviewed. No caller-created object or shape/hash registry entry may turn it positive. A distinctly test-only specification model may simulate positive original-identity transitions, without importing a production receipt factory or being counted as a successful production owner-start test. No test flag, environment switch, fixture ID or public receipt constructor in runtime code.
- `close_original_grant`: irreversible local retirement. Failure, cancellation, lost/uncertain create/start acknowledgement and process restart never reconstruct/reissue an effect grant. Cleanup-only supervision may read the consumed original manifest and independently authenticated resource records; it cannot authorize another create/start. Cleanup authority and actual calls are outside this module.

### Filesystem and identity discipline

Only an original externally prepared journal directory is accepted, selected by the original supervisor, not by target/input JSON. Before first use validate each ancestor, original directory FD/path binding, regular-file/single-link constraints, owner/mode/no-ACL/no-capability/no-symlink guarantees under the explicitly trusted external controller identity. No writable untrusted ancestor, named-only check, hard-link alias or inherited unexpected FD acceptance. Concrete root and UID/GID belong to later real controller setup; test fixtures use their exact current owned test identity and cannot become a live profile.

The live directory must already exist on persistent storage. The module does not create controller parents or choose a volatile `/run` or `/tmp` fallback. A location name alone does not prove persistence; real mount/storage/retention qualification remains mandatory. This module rechecks the supplied original held ancestor/path/directory identity and protections; it does not discover or authenticate a controller/journal namespace from an arbitrary FD. The real original binding supplier is a required unavailable prerequisite.

One exclusive marker creation; bounded writes may handle progress/short writes only within the original fixed total budget. A zero write, unexpected error, cancellation or exceeded bound refuses; no fresh open, fallback marker/name, entropy generation or automatic retry. After any marker creation, including partial/corrupt file, the attempt remains held. Prior existence always refuses, including exact same bytes; no "idempotent success" returns an effect grant.

An fsync acknowledgement is trusted only under the selected controller/storage premise. File fsync then directory fsync must complete before any grant is returned. Failure before marker creation authorizes no effect and is not proof of durable consumption; failure after creation also authorizes no effect and leaves the marker untouched. In either case, the authentic supervisor MUST externally hold the original authorization after uncertainty; the local marker alone cannot enforce that rule before creation or after failed directory sync. The primitive cannot prevent another invocation from selecting a different directory or retrying an unrecorded precreation failure without the absent authentic original binding/supervisor. Never claim this local module alone establishes global original-attempt enforcement. This safety rule does not falsely claim a marker survives when directory fsync failed.

### Phase and crash semantics

| Point of interruption | Permitted next action |
| --- | --- |
| Before consume returns | No host creation or owner start. Preserve partial/existing state; no automatic retry or new attempt. |
| After consume, before creation claim | Original live grant may claim creation once only while original PID/binding/manifest, unretired cancellation state and original monotonic deadline all remain current; after controller restart no reconstruction. |
| After creation claim, before/after provider acknowledgement | No second creation. Unknown original identity requires external reconciliation and exact cleanup scope; this primitive supplies neither. |
| Before owner-start claim | Exact original creation receipt required from the future authentic adapter. New host ID/guest-provided receipt cannot authorize it. |
| After owner-start claim, before/after acknowledgement | No second owner start. Unknown outcome stays held; original resource inspection/cleanup requires its separate authority. |
| Target reboot or controller restart | Marker never becomes a reusable grant. No owner restart, re-capture, revision bump, new host or new nonce as automatic recovery. |
| Cleanup complete/unknown | Consumption remains. Completion never reopens the namespace. A new real attempt needs a new explicit owner grant. |

This is **at-most-one attempt under a trusted controller**, not exactly-once successful effect, liveness, cost closure, authentic provider state or full Governance acceptance. Python process death may lose the only in-memory grant intentionally. The external supervisor must bound its whole lifetime independently; this module cannot make an unbounded kernel fsync call mathematically time-limited. A future watchdog must have explicit shutdown/cleanup authority and must not restart a timed-out writer to obtain another effect grant.

## Meaningful local tests and evidence boundaries

Tests should invoke the actual private module on synthetic manifests and newly owned temporary files only, with injected fsync/write/cancellation failures. They must prove original-byte/identity checks, order of file→directory sync→grant, competing exclusive creation, existing valid/partial/corrupt marker refusal, zero/short/error writes, lost fsync result, no unlink/repair, closed grant identity and cross-instance refusal after fixture "restart". Actual local phase tests cover competing threads, close-versus-claim, simulated changed PID before lock acquisition, copied/foreign/reloaded grants, deadline equality/expiry, cancellation and identity change. No actual fork/process/native target run is needed or authorized by this unit. Every production owner-start test is negative until the authentic supplier exists. Separately labeled specification-model simulations can cover a positive owner-start transition, but do not test or qualify the unavailable production seam. No actual provider adapter or real receipt factory is introduced for a test.

These are local filesystem behavior and synthetic orchestration checks on the development OS. They do NOT establish Linux directory-fsync/ACL/mount/power-loss behavior, real grant authenticity, provider response custody, cross-machine persistence, target ABI, actual host death/reboot, administrative cleanup or cloud spending acceptance. Exact Linux/native/provider qualification must later exercise those contracts on the selected controller/host.

## Independent design findings incorporated

Reviewer advanced_cloud_control_guide found three important omissions: fork/thread grant semantics, raw-FD versus protected ancestor/path binding, and undefined currentness/uncertainty holding. The revised contract adds original PID-before-lock refusal plus atomic claim/retirement, an explicit original protected binding seam, and fixed original deadline/cancellation/identity checks. It states exactly what the absent authentic supervisor must enforce across precreation/directory-sync failures; the primitive cannot guarantee that alone. Positive synthetic owner-start is test-model-only; production remains negative-only until a genuine receipt supplier is separately qualified. Root incorporated these findings; no subsequent reviewer CLEAR, implementation or runtime qualification is claimed.
