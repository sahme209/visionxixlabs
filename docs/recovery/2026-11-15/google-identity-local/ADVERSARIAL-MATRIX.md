# Google identity adversarial acceptance matrix

Design SHA256 8c6b4df2ddaf8602255383dd50f9afd6527f2326d37b6756ace9ea581397c899; migration SHA256 df3c9c98b21da4e2a2f3982f6c8acc21346ed15dcc1ca488fc0fd7f4639ae475. Read-only design work only: no source edit, SQL/server, OAuth, account or secret action. These are required test oracles, not claimed passing results.

Use deterministic identities, clocks and scheduler barriers. For every refusal, assert zero binding/User creation/session issuance except where expressly allowed; no raw nonce/code/password/token/profile/URL/native error in output or diagnostics. Separate simulated unit/handler checks from actual owned-PostgreSQL concurrency and installed-NextAuth flow checks.

| ID | Adversarial trigger | Required observable outcome / layer |
|---|---|---|
| G01 | Qualified Google callback claims an existing verified password or legacy OAuth-only email; vary sub and providerAccountId. | No email upsert, automatic binding, User mutation, bootstrap or session. Only a browser-bound pending intent for the fixed candidate id/version; existing account is never reselected by email. Service + handler. |
| G02 | Existing binding sub A now reports another verified email, including an email already owned by user B. | Canonical id/email/workspace remain user A; B untouched. account.providerAccountId remains A's Google sub. No email-derived workspace switch. Auth callbacks. |
| G03 | Missing/wrong issuer, sub/account mismatch, nonboolean email_verified, invalid/mapped-email mismatch, oversized subject; caller body supplies replacement claims. | Refuse before any User/binding write; body cannot supply trusted claims. Exact allowed issuer normalization only. Claims + callbacks. |
| G04 | New Gmail / Workspace exact hd-domain versus third-party email, hd mismatch, gmail.com.evil.invalid or lookalike. | Only exact authoritative claim path may atomically create User+binding. All other new-email paths require fresh mailbox proof; no suffix or caller-hd authority. Service. |
| G05 | No-user intent created, then another signup creates that email before confirmation. | Existing signup remains unchanged; pending intent cannot adopt its id. Fixed restart, no merge/session. Real DB concurrency. |
| G06 | Existing candidate deleted/recreated at same email; email, password hash or updatedAt changes during proof await. | Original candidate snapshot never maps to replacement. No binding on stale password/version; fixed restart. Unit barriers + DB. |
| G07 | Pause confirmation after User read but before consumption; concurrent password/email edit commits, then resume. Reverse lock order as companion case. | Candidate version/password premise must have a clear atomic winner. Conditional User write/row lock or equivalent prevents edit-winning stale proof; read-only SERIALIZABLE comparison alone is not assumed sufficient. DB two-connection test. |
| G08 | Two browsers/transactions confirm same subject; two subjects compete for same candidate; another binding appears while proof awaits. | Exactly one unique subject/user binding, at most one count1 intent consumption; losers restart, no subject replacement or partial User. Actual unique constraints + DB race. |
| G09 | Binding insert or User create fails after intent CAS; serialization conflict/deadlock. | All User/binding/consumption writes roll back together. No success response/mail-code consumption or unbounded retry. DB rollback + service fault injection. |
| G10 | Two valid confirmations race on one intent/proof; consumed replay. | One winner only. Other response cannot mint a session or replay provider code; final flow still requires normal fresh Google callback. DB CAS + handler. |
| G11 | Fifth wrong-proof update races another wrong proof or valid confirmation; resend after four/five failures. | Atomic attempts never exceed5; the winner determines admission. Attempts5 invalidates all confirmation/send paths; resend never resets attempts. No read-then-write lost increments. DB barriers. |
| G12 | Concurrent resend A/B, old-code delivery after new-code delivery, mail send failure/unavailable, rate limiter unavailable. | Only current stored proof is valid; no raw code at rest/API. No false “sent”; retries bounded by intent/email/browser/IP; attempts/intent expiry retained. Service + mail mock + DB. |
| G13 | Intent expires during async password comparison or while acquiring the intent lock; email code expires earlier; token expiry is shorter than15min. | Capture fresh time after lock/await and reject expired intent/proof. createdAt/expiresAt share one mint-time observation; code expiry <= intent expiry. Actual lock wait + injected clock. |
| G14 | Missing/wrong nonce, swapped browser cookie, cross-intent CSRF, expired nonce, signup/email-verification token used as link proof. | No target proof-counter/mail/link mutation before browser+purpose-CSRF proof. Uniform outward response before possession. Correct nonce alone cannot replace CSRF. Handler. |
| G15 | Wrong Host/Origin, sibling-origin POST, GET/code-link scanner, unsafe callback URL or desktop pairing already expired. | Canonical Host + same Origin required. GET never mutates/link/sends. Safe stored path only; desktop capability lifetime never extended. Handler + callback parser. |
| G16 | Parallel Google callbacks produce different users; delay A while B completes; mutate email fields/order of JWT/event callbacks. | Module-private object attestations remain request/object specific. A's JWT/audit can never use B's canonical id. No global email/sub-keyed attestation cache. Actual installed callback object flow. |
| G17 | Clone provider-user object with identical fields, missing/wrong provider/sub attestation, or mutate canonical id after attestation. | Initial JWT refuses without the exact matching canonical object/proof. token.id/sub/email derive from attested canonical values, not a second email lookup. No session cookie on failure. Callback tests. |
| G18 | JWT and signIn event run in either order/repeatedly; account object still contains provider subject. | Canonical audit id/email stay correct; JWT attestation use cannot erase event proof prematurely. No Google-sub-as-User.id audit. Installed NextAuth flow. |
| G19 | Subsequent signed legacy token has no canonical version/id, ID-less email-only token, deleted/invalid canonical id, or user undefined. | Reauthentication/failure per explicit policy; no email-based promotion or account switch. Preserve existing authorization/session gates. JWT/session. |
| G20 | Credentials unverified user/wrong password; GitHub/Cognito initial sign-in; denied enterprise/seat or membership bootstrap failure. | Existing security gates preserved and canonical attestation equivalent where required. Pending Google recovery cannot bootstrap an unauthorized account. Existing regression suites. |
| G21 | Recovery confirmation succeeds, then no fresh OAuth callback, or old provider code is replayed. | Only “linked—Continue with Google”; no custom JWT/session mint or callback replay. Cookie cleared; normal provider state/PKCE path remains authoritative. Handler + installed flow. |
| G22 | Missing migration/DB unavailable; malformed/unique/FK/check violation contains SQL/error/profile data. | Fixed unavailable/restart result, no email-upsert fallback. Allowlisted diagnostics only; no native error cause/raw URL/token leakage. Service + handler. |

Minimum real DB matrix: G05/G07/G08/G09/G10/G11/G13. Minimum installed-framework boundary: G16/G17/G18/G21. Handler tests must exercise actual route AsyncLocalStorage isolation and cookie response append: simultaneous success/pending/refusal cannot attach another request's nonce cookie or redirect; Secure/HttpOnly/SameSite/path/loopback exception remain exact.

Implementation coordination: author accepted G13 (intent row lock then fresh time). G07 candidate-row atomicity was sent as a concrete review question; no implementation finding is claimed until code/real concurrency evidence establishes behavior. No new production trust, account selector or provider grant is introduced by this matrix.
