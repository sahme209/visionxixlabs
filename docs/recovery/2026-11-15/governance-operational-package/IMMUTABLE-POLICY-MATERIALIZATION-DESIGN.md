# Proposed immutable policy and original runtime acceptance

Design only. The current one-file JavaScript capsule is locally built/syntax-checked; this proposal does not change native code, create acceptance, build/run/install a daemon, access credentials/accounts, provision resources, enable Governance or spend. It needs the explicit validation-first authority decision below before implementation.

## Concrete dependency

The current owner freezes `/etc/axiom-operational-time/profile` against `AXIOM_OPERATIONAL_PROFILE_SHA256`, then decodes that file as `AXIOM_ACCEPT_V1`. Its boot ID and generation-directory device/inode must match the actual selected host before the daemon starts. Those facts are unavailable when making a reusable pre-host owner binary. The owner copies that original acceptance into its exclusive accepted file. No current materializer supplies a separate late-bound acceptance.

This is a host-late compilation/delivery dependency, not an intrinsic cryptographic cycle. Keeping it would require an actual selected target-compatible compiler and owner rebuild after observing the host facts, either on the host or via a separately qualified external build/delivery path. Saved evidence establishes neither path. Do not claim it is free, already installed, feasible within the current lifetime, or equivalent to the existing immutable package.

## Recommended source contract

Separate **immutable semantic policy** from **the original root owner's once-captured runtime acceptance**. This retains the accepted AWS/Linux operational-root trust model and the existing acceptance/status wire protocol; it does not create a physical UTC guarantee or qualify the root owner automatically.

| Item | Exact proposed behavior |
| --- | --- |
| Immutable policy | New closed `AXIOM_OPERATIONAL_POLICY_V1` ASCII/LF format. Explicit operational assurance/source, revision1..9007199254740991 and exact reader UID/GID in1..4294967294 (exclude root and the reserved no-change sentinel). No boot ID, directory device/inode, runtime generation or embedded self-hash. Closed field order/length/integer ranges; no unknown fields, duplicate fields, extensions, CR/NUL or trailing bytes. |
| Compiled identity | Keep the exact policy-file SHA256 compiled into the same original owner's frozen-file table. Daemon/Node/worker/closed-main/addon keep the other five existing expected hashes. No runtime path/hash selector or generic signature/JSON qualifier is added. |
| `profile` in acceptance | For newly qualified packages, derive from the verified immutable policy SHA256. The owner assigns it after validating the held original file, rather than accepting an unrelated64hex label from input. This meaning is an explicit new package binding; do not silently reinterpret old receipts or enroll a profile on that basis. |
| Runtime facts | After policy validation, the owner captures original boot ID and held generation-directory `fstat` device/inode, root publisher UID and the policy's reader identities. Verify exact fixed directory path/mode/owner/GID/ACL and unchanged boot/suspend around capture. Construct once through existing `axiom_operational_accept_encode`; never copy policy bytes as acceptance. |
| Per-start generation | After verifying policy/held setup and before daemon launch, make exactly one `getrandom(nonce,32,GRND_NONBLOCK)` call into a fixed32byte buffer. Accept only return32 with a nonzero aggregate byte value; short, zero-vector, EINTR/EAGAIN or any error refuses without retry, entropy wait, fallback or source substitution. Encode lowercase64hex and derive exactly `host_<hex>` / `source_<hex>` (distinct domain prefixes). No caller JSON/CLI selector. These are per-start generation labels, not AWS identity attestation. This operation does not wait for entropy readiness; no mathematical scheduler/syscall latency bound is claimed. The old post-daemon30second deadline is not presented as covering this earlier operation; the whole-host external deadline remains required. |
| Nonreuse | Keep exclusive accepted-file creation and fixed original generation path; no internal retry, unlink/repair, recapture, nonce reuse or revision increase. This local collision marker exists only after creation and is volatile across reboot; failures before creation leave no consumed marker. It does NOT provide durable cross-start/reboot attempt consumption. An external original-attempt consume-before-start controller, original resource IDs and one-host lifetime remain UNIMPLEMENTED qualification prerequisites; do not enable/qualify the package without them. Random generation relies on trusted Linux, not a mathematical global uniqueness proof. |
| Original channels | Preserve exclusive protected accepted file and exact original FD8, CHECK/STATUS and daemon update/ACK channels. Native type tags/owner identity remain mandatory. No public constructor, generic FD loader, structural boolean, synthetic native profile or provider runtime is introduced. |

## Invariants and source integration

- Keep `all_current()` immutable-artifact/policy checks, original daemon PIDFD, exact boot/suspend and directory identity, competing-service exclusion, reader UID file checks and no-ACL checks. Preserve the original reader-UID file only with strict equality to the immutable policy's chosen UID; it must not become an alternative identity selector.
- Every daemon update/CHECK must still match the once-constructed original acceptance, revision/generations, monotonic sequence/publication/transition and Ready state. Any withdrawal/disruption/unknown state remains sticky for this original generation.
- The binding still authenticates exact FD8 bytes/metadata, original boot, directory/worker resources, exact GID and current owner checks before/after sampling. Existing AXIOM_ACCEPT_V1 has no reader UID: the binding checks UID merely nonzero, not exact equality. Exact UID authority stays with the original trusted owner: immutable policy==reader-uid file, followed by setresuid/setresgid of all real/effective/saved IDs and explicit getresuid/getresgid equality checks before filtering/exec. This is trusted-owner provenance, not independent UID authentication by the binding. Adding a UID field/peer attestation would be a separate contract, not hidden in this change. Preserve the existing `AXIOM_ACCEPT_V1` wire fields for the daemon/binding; update only source consumers that currently assume the *policy file itself* uses that wire format.
- Do not reinterpret strict publications, old synthetic operational receipts, old profiles or historical compiler/native packets. The future package qualification record must separately bind the immutable policy digest, exact final owner/package bytes and observed real host/custody/runtime evidence. It cannot include its own digest recursively or be minted from this new parser.
- Keep current runtime limits, role-free network denial, unqualified standalone supplier receipt, owner withdrawal/exit/cleanup behavior and all production flags unchanged in this unit. Administrative lifecycle acceptance remains separate; a sampled value does not establish successful parent shutdown.
- Pure codec/derivation helpers may accept explicit test inputs; only the fixed root owner may compose actual kernel/filesystem facts into a live acceptance. No exported JS factory or general acceptance CLI is allowed.

Implementation files: `time_operational_status.{h,c}` (closed semantic policy codec and acceptance derivation inputs), `time_operational_owner.c` (verified policy/original capture/nonce/exclusive encoded acceptance), any directly affected original binding/daemon parser consumers identified by a complete caller scan, their existing pure/source/simulated tests and package preparation docs/demo. No ABI/native result is inferred from these tests.

## Required local regressions

1. Missing/malformed/duplicate/changed semantic policy, invalid assurance/source/revision/reader identities and unknown fields refuse before startup/admission.
2. Changing a policy byte changes its expected profile binding; a64hex claim supplied in policy cannot choose the new runtime profile digest. Historical acceptance wire parsing remains separate and cannot act as a policy fallback.
3. Wrong boot/directory/mode/owner/GID/UID/ACL, replacement or mutation across capture/daemon/binding and lost/uncertain original resource checks refuse. Preserve Unknown-before-Ready and original fd ownership.
4. Pure/source tests cover exact single-call nonce flags/count/labels; simulated short/zero/error/EINTR/EAGAIN refusals; generation substitution, accepted-file collision and no internal repair/retry after startup failure/withdrawal. They do not establish durable original-attempt consumption across a pre-marker failure, restart or reboot. That controller and its real persistence/unknown-response tests remain a later explicit gate.
5. Actual source caller mapping remains complete across owner→daemon→binding→native bridge. No synthetic test may claim kernel-random, host, native ABI, provider/custody/fleet or physical-clock qualification.
6. Full current ordinary tests/types and one independent source review after local implementation. Preserve initial failures and source-supported corrections. New native/build/host/resource/credential effects require their separate exact qualification decision.

## Owner decision

Approve the recommended **local contract implementation and simulated tests only**, accepting that once-only boot/directory/generation facts are supplied by the trusted fixed root owner after immutable-policy verification instead of being precommitted in a host-specific compiled-hash file. A faulty or compromised trusted owner could supply wrong facts; actual qualification must test the implementation and trust premise. This does not waive custody/fleet/people/provider/coverage/security or production acceptance, change credential expiry rules, enable Governance, authorize target execution or spend.

Alternative: retain the current precommitted host-specific profile contract, and prepare an explicit target-compatible late-compilation/observation/delivery plan before any build or resource decision. Do not implement either branch silently or install a compiler to discover feasibility.

## Independent design review and corrections

Fresh reviewer operational_capsule_final_review identified three important clarifications before this decision: volatile accepted-file collision is not durable attempt consumption; nonce semantics/bounds must be exact; and the current binding has exact GID but only nonzero UID checks. The contract above now states the external durable-controller gap, exact single nonblocking32byte call/labels/refusal and trusted-owner exact-UID postconditions. Root incorporated these corrections without claiming a new reviewer CLEAR or any implementation/native evidence.
