# Private generated-site deployment credential composition — local proposal

## Why this next change is required

The local decision timing integration now checks the actual people/source/action interval. However, `lib/deploy/provider.ts` still obtains `VERCEL_TOKEN` or an options credential before its original `beforeSend`, with a timeout signal separate from the authenticated request. The present native qualification port cannot bind a held credential's actual supported lifetime/currentness to final authorization. Full Governance cannot be accepted with that gap.

Owner approved this changed private credential/authorization boundary for local implementation and simulated tests in call_dcfc565c33fe4740a2f1c4cb6fffaed7. Real qualification and execution remain unavailable. Proposed grant: source, ordinary compilation/typechecking and simulated/owned-memory tests only. No actual SQL, real credential/provider/clock request, native runtime/library experiment, installation/signing, workflow/configuration change, production operation, enablement or spending.

## Chosen composition and alternatives

Extend the existing exact child coordinator and original locked authorization owners; do not introduce a parallel approval ledger or a second final authorization transaction. Keeping the environment/options credential fallback cannot establish private admission/custody. Adding an unrelated interval check outside the final owner would allow authority/expiry to change while it waits. Both alternatives are rejected.

1. Add a server-private deployment runtime attachment to the existing opaque execution binding. It is created only by the actual authenticated request composition using its captured bearer-guarded clock and original request signal, and a private, qualified native transport factory. Missing or mismatched runtime refuses **before parent claim** in prepared HTTP. No request JSON, cookie, API key, workflow/environment variable or caller-supplied credential can configure this attachment. The default remains unavailable and routes stay unregistered.
2. The real child coordinator retains original claim/proof/outcome handling. It provides separate one-use acquisition and final-send callbacks. Acquisition authorization uses the exact already-claimed child without spending the final send proof. Its original locked transaction must first acquire the physical target lock, perform existing target admission and durably reserve that exact target/action/child/plan/source before invoking the supplier. The supplier is called only after acknowledged commit. Final authorization consumes the original send proof and rechecks this SAME held reservation rather than reserving a second time. Both require the exact native time callback and execute inside their original transaction owners. No transaction escapes to a transport and no nested final transaction is added.
3. Extend the actual store's final authorization to consume the native time callback at its end, joining current exact action/people/lead bounds. Repeat source/role/target checks after native waits and require commit acknowledgement before dispatch. Preserve durable unknowns and permanent target liability. A lost acquisition/commit acknowledgement leaves the already committed target held even if no usable in-memory proof or receipt was returned; never fabricate a provider request receipt for that uncertainty. A lost acquisition/send/ack cannot be reset, retried or transferred to another action. Qualification must establish that copied credential material cannot escape this fixed private transport.
4. The fixed native transport validates the exact prepared effect and serialized body. It checks its qualified profile and original action before credential acquisition. The private supplier may only read/copy a credential already held inside the qualified private custodian; it cannot mint, renew, exchange, create access or change grants. It must return that held credential with explicit supported valid-from/expiry evidence and an independent currentness/custody check. Any future native issuance requires separately designed source-intent and credential-liability admission and is outside this proposal. Do not invent expiry from local time, requested duration, an operator label or a static environment token. Unknown native lifetime/custody refuses. Structurally matching synthetic metadata remains test-only, not a real qualified supplier.
5. Construct the exact provider request, then pass one check through the original final owner. The joined window can only tighten to the credential/action/source/people deadlines. The callback fence covers the **entire** post-clock native profile/credential checks, not just primitive clock completion. Omitted, duplicate, late or unawaited checks cannot authorize dispatch. The captured request cancellation and fixed transport timeout govern acquisition, fetch and bounded response handling. No fresh clock I/O after commit acknowledgement; real validity through dispatch remains a qualification requirement.
6. `deploySite`/`deploySiteFromPlan` preserve their exact file/effect/body generation and result semantics but obtain transport authority solely from the private opaque binding. Remove the Vercel environment/options token fallback. Preserve explicit supported-provider refusal, physical target scope, one request, response size/identity/state checks, accepted-vs-ready distinction and original outcome recording/result release. No deployment or native-read action is performed by constructing a binding.
7. Prepared HTTP uses the actual service-created execution binding, verifies the exact approved one-effect lead-backed source, and preserves current native-profile checks and metadata-only result. Private source/runtime contracts remain unavailable by default. Metadata inspection and reference recovery stay resource-free and do not revive authority.

## Design-review correction

Independent review identified that the previous final-send-only reservation left uncertain acquisition without cross-action physical liability. This revision moves the original target reservation into acquisition authorization and requires acknowledged commit before the held-credential copy. Final send checks that same reservation. It also explicitly excludes native issuance/renewal/exchange; neither a method name nor structural credential metadata supplies that authority. Test lost acquisition and lost reservation acknowledgement separately, including a cloned action. This correction was reviewed before the owner approved local implementation; the subsequent implementation/tests must retain this reservation ordering.
