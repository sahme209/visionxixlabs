# First real runtime prerequisite — role-free diagnostic preparation

Status: NOT SELECTED as a standalone implementation. A bare diagnostic image would not exercise the actual compiled Axiom consumer and would need repeating after the final runtime changes. Retain its safe observations as requirements inside the connected full-runtime qualification image/plan; do not build or run a separate substitute. The proposed local source/test scope below is historical design exploration only. No new trust issuer or production default. This stage exists to check real Linux platform facts before spending on a full custodian/DB/deployment topology or claiming any credential authority. The whole Governance objective remains unchanged and incomplete.

## Why this stage, before cloud credentials

The approved public research establishes configurable platform controls, not that Axiom's real process receives them. The current Mac package cannot substitute for a Linux runtime. Preparing more simulated `assertQualified` callbacks would not fill that gap. A fixed role-free diagnostic is the smallest real task that can test native protection without acquiring source/target AWS credentials or touching business data. Actual container build/pull, resource setup and its eventual run are excluded from this local-preparation decision.

## Fixed source to prepare

One Node-builtins-only executable entrypoint and a pure result/compiler module; no packages, generated dependencies, credential SDK, shell, dynamic imports, child processes, user code or inference. Ordinary tests use intercepted filesystem, HTTP and time only. Default execution of the entrypoint is not part of local testing.

The future frozen entrypoint would:

- Read only its exact packaged source/fixture, effective UID/GID, selected /proc status/mount fields and the AWS-injected task-metadata address. Parse the address as an untrusted candidate; permit only literal HTTP169.254.170.2, default port, no credentials/query/fragment, bounded single v4 identifier path plus `/task`. It must never contact a credential path, DNS-selected host, proxy, alternate origin or redirect.
- Refuse before metadata I/O if any application credential-source URI or credential material variable is present. Presence checks must never print or save values; this task deliberately has no application task role. Managed image-pull/log execution-role behavior is not relabeled as application access.
- Make at most one bounded native task-metadata GET (3seconds,64KiB); no retry/redirect. Retain only explicit task/image/status/container-count observations and nonsecret digests. Discard all unrelated metadata. An external actual control-plane observer must later compare these; the process cannot qualify itself.
- Observe UID/GID, effective capabilities and root/scratch mount state. Do not assert undocumented operating-system behavior. Attempt exactly one write to a fixed disposable canary under the packaged read-only fixture directory; success is an adverse observation and stops. No user's file, host directory, database or existing fixture is touched. This actual write attempt belongs only to a later expressly authorized cloud run, never ordinary local tests.
- Record clock values only as UNQUALIFIED observations. Neither current wall time nor a metadata timestamp becomes the required trusted interval.
- Emit one bounded, fixed-schema, secret-free JSON result. It must always contain `executionAuthorized:false`, `identityQualified:false`, `custodyQualified:false` and `governanceEnabled:false`, even when the expected protection observations occur. A zero exit status means only that the diagnostic completed, not that Governance can execute.
- Use one overall15second diagnostic deadline and bounded cleanup; no lingering sockets or late success after timeout. The later cloud task/controller must independently limit the complete image-pull/run lifetime and stop only its confirmed-owned task. No infinite process, auto-restart, service, credential acquisition or cleanup of existing resources.

Do not expose a public selector, allow caller endpoints, return raw errors/stack/environment, consume or initialize the canonical issuer identity, or convert a saved result into an allow callback.

## Local tests and review

Prove with intercepted pure/mock tests: valid bounded candidate observation; application-role presence refusal before HTTP; credential/full-URI/DNS/redirect/oversize/malformed substitution refusal; source/canary/protection mismatch; deadline/cancellation and late-result refusal; cleanup uncertainty; bounded output and invariant false authority fields. Preserve unknown/adverse results. No real HTTP, /proc read, canary write, OS restrictions, native/module loading, database, signing, installer, AWS account, credential or provider call is in this preparation.

Independent source review must confirm actual native I/O is confined to that later fixed entrypoint and no test result qualifies a runtime. Syntax checking is permitted; no actual entrypoint execution or artifact build/pull is proposed.
