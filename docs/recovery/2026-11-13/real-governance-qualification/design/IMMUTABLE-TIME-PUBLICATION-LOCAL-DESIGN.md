# Native time observation — cooperating publication design

Status: proposed design/local preparation, NOT implementation approval or native qualification. Owner previously delegated mechanism judgment; this recommendation preserves the existing security requirement rather than silently accepting the vendor's16-bit no-wrap assumption. The completed five-file source audit is the evidence base. No new source, account, build, native call, resource or spending authority follows.

## Decision and alternatives

Recommend one trusted-producer publication adapter with complete fresh-file replacement and a bounded read-only consumer. It receives the authoritative V2 value directly at the inspected ShmWrite hook. It does not reread mutable vendor SHM. This removes the consumer's dependence on mapped atomic memory ordering and16-bit sequence equality. It is a change to trusted producer code and a new explicit format, with matching build/license/provenance and failure qualification; it is not merely a reader patch or a claimed smaller total effort.

A fresh bounded mapped worker preserves the upstream synchronization pattern, but its eight-attempt/time limits do not establish absence of a wrap/reset ABA. That alternative would require an enforced writer bound/cooperation or a separately accepted vendor-risk assumption. Descriptor-only concurrent copying is not established. No alternative is silently enabled.

Trusted producer ownership is explicit: no claim that chmod makes a file immutable against its owner/root. The fixed qualified producer must never reopen/modify a published inode. Malicious host root/administrators remain outside the selected trial's threat model, as in ISOLATED-LINUX-EVALUATION-DESIGN.md.

## Publisher contract and failure ordering

The source supports the hook concept: ShmWrite.write(&mut self,&ClockErrorBound) and Shm0's boxed implementation; public getters expose the V2 integer/time/status/disruption fields. Actual constructor wiring is not established by those interfaces alone. The exact pinned daemon build must show every initialization, regular V2 update and disruption path uses this adapter, and that startup Unknown publication finishes before any clock adjustment. No compatibility or live adoption is claimed now.

For each invocation:

1. Accept V2 only and validate the exact finite raw domain. Read values directly from the authoritative argument, not mapped SHM. Capture the protected producer's native lifecycle generation and a non-reusing, checked publication counter; overflow refuses. Neither is caller JSON or self-attestation.
2. Serialize a fixed versioned record of explicit integers/closed status values, at most4096bytes. Preserve as_of/void_after, bound/drift, disruption marker/support and layout identity; never serialize Rust enum/padding/native TimeSpec bytes. Clock sampling remains a separate exact observation contract below.
3. Create one fresh regular staging file exclusively under the fixed generation-specific protected directory. Complete the bounded write, required persistence and read-only-mode transition; close all writable handles. Replace the fixed latest name atomically within that same qualified local filesystem. Never modify/reuse an earlier published inode. The native implementation must define file/directory persistence ordering; rename alone is not crash durability.
4. This channel is authoritative for Axiom time input. Stock SHM publication is compatibility-only and cannot be an alternate reader fallback. Perform required Axiom publication before permitting the corresponding delegate/caller continuation.
5. Any encoding/write/sync/close/rename/identity error is fatal to this producer generation. The adapter must not log-and-return through the upstream void-returning ShmWrite API, throw an exception that a caller may swallow, or continue a clock-adjusting path. Use a fixed nonreturning process-failure path in the eventual native implementation. A source consumer must verify the actual bound producer generation is live and not failed before and after capture; an old synchronized file is never eligible solely because it exists or has an unexpired timestamp. Stopping a process is not by itself evidence that consumers made this check.

A full crash table is mandatory for actual acceptance: before staging, partial write, after data persistence, before/after rename, before/after compatibility publication, before caller continuation, during startup Unknown and during disruption. Failure after a new file exists still refuses when its producer generation is failed. Disruption can precede notification: preserve separate actual native disruption-marker/currentness checks; the file protocol cannot prove detection efficacy or eliminate that interval. Actual constructor/adjustment/native-lifecycle wiring must be reviewed before any real qualification, not inferred from the hook or a mock.

## Bounded consumer and ownership

One fixed supervised worker receives only read-only directory/source descriptors, fixed native artifact/profile binding and result pipe. No request path, environment source, credentials, network, database or arbitrary file access. Proposed engineering limits remain4096bytes, one capture with no retry/cache,500ms parent result deadline plus at most100ms owned termination/reap. These are proposed limits, not measured Linux guarantees; missing confirmed cleanup refuses and remains visible.

Open the fixed latest name relative to the protected directory with no symlink following. Check actual descriptor type/size/owner/access and path ancestry against native context; hold the descriptor throughout bounded reading. After capture and at the final source-currentness point, require latest still resolves to the held identity, the original producer/lifecycle is current, and the disruption evidence is unchanged. Replacement, disappearance, partial/malformed input, wrong generation/status or unknown lifecycle refuses. Never reopen by pathname to repair an old read.

Bound concurrent worker count, staging files and record sizes in the exact run profile. Atomic replacement retires the old directory entry; an existing reader may retain its old inode until close. Qualify that filesystem/descriptor behavior rather than claiming immediate physical deletion. Retire only confirmed-owned new temporary publications under the specifically approved retention policy; no existing source history, database, backup or unrelated file is deleted. Disk-full/cleanup uncertainty cannot preserve an apparently live synchronized source. Producer liveness/failure and consumer refusal must be tested together.

## Conservative observation contract

Publication consistency does not establish truth of B/drift, clock synchronization, time scale or source lifetime. Keep those as actual native qualification requirements. Initially refuse Unknown, Disrupted, FreeRunning, missing disruption support, V3 and unknown conversion/rate premises. No constants or error padding are invented.

For a qualified precise monotonic reference P, bracket realtime R with P0 then P1 and declare the observation instant P2. Express clock samples and the coarse reference A/expiryV as qualified monotonic intervals. Require P0.low>=A.high, P2.high<V.low, ordered samples and all stricter status/freshness bounds. Let deltaR=P1.high-A.low. Under qualified base bound B and drift D, E=B+ceil(D*deltaR/1e9). With qualified rational UTC/monotonic rates lambdaMin/lambdaMax, deltaMin=max(0,P2.low-P1.high), deltaMax=max(0,P2.high-P0.low), the conditional interval atP2 is [R-E+floor(lambdaMin*deltaMin),R+E+ceil(lambdaMax*deltaMax)]. Use exact checked integers/rationals and outward millisecond conversion; reject invalid rates, backwards readings, overflows and unsupported scales.

These are premises, not fields accepted from a model/client or a proof of the current daemon. Validate conservative upstream bound/drift rounding and actual coarse/precise clock relation and rates. A result describes P2, not an arbitrary later return/commit instant. If private transport delay requires a later observation, re-age under the SAME qualified monotonic/source lifetime premises using a fresh native observation; otherwise refuse. The accepted original-commit/same-proof dispatch boundary and its scheduling limitation remain; this design grants no stronger physical-receipt promise.
