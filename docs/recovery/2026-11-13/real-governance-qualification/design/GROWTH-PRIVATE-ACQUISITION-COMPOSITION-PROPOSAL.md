# Growth acquisition and original cancellation — proposed local composition

November 13. Concrete follow-up to finding 3 in JOINED-TIME-WHOLE-SOURCE-AUDIT.md. This is design preparation, not permission to widen the existing Vercel-only private attachment, access a credential or publish/delete a post. Existing historical attempts and genuine approvals retain their exact meanings.

## Actual gap and consumers

`posting.ts` and `platformDeletion.ts` read the selected OAuth credential row and decrypt it before `beforeSend`. The row wait is outside a fresh credential-acquisition authorization. Their native fetches use detached 15-second cancellation rather than the controlling request. `executionHttp.ts` checks original cancellation around final authorization but constructs a generic `bindPlatformExecution`, which carries no original private timing/native attachment. The existing `beforeEffectCredential` and `bindPlatformDeploymentExecution` are specifically deployment.vercel-only; relabeling a growth effect as Vercel is forbidden.

## Proposed connected implementation

1. Introduce a separate private growth attachment for **post publish and delete only**, carrying the original captured runtime clock, request signal, synchronous possession assertion and a fixed native transport/credential-reader profile. An opaque instance-bound brand must be required; request JSON and a generic execution binding cannot construct it. Schedule changes remain in their original transaction and acquire no OAuth credential. No new token source, environment fallback, refresh or renewal.
2. The original paired request composition constructs it using the actual current authority service and the same captured clock/signal used by that service. The prepared execution HTTP command captures it before claiming. Missing qualified attachment refuses before new action/child/credential access; defaults stay unavailable. Keep deployment-specific acquisition behavior unchanged.
3. Extend the exact admitted-child acquisition gate with an explicit growth branch, not an arbitrary effect-kind bypass. The original child must be committed before private credential-row access. Check exact parent/source/people/connection revision, current posting policy, immutable post/image/deletion lineage, original possession and joined time immediately before the read. Record no credential or secret-dependent digest. Preserve ONE `credentialUsed` transition: the initial `beforeEffectCredential` consumes admission permanently. It must not be invoked again or reset after a later wait.
4. Introduce a DISTINCT private `assertEffectCredentialCurrent` owner callback for the already admitted exact child. It resolves only the original instance's observation proof, requires credential admission granted, send not consumed and that same claimed parent/effect/source, and repeats the currentness/window checks without claiming, reserving or issuing another credential capability. After the credential-row await, invoke that callback **before decrypt**; invoke it again after decrypt before native preparation. This callback remains lexical to the private transport and cannot be reconstructed from JSON, used on another child or used after the final send slot is consumed. Preserve the selected connection and revision across waits; never choose the latest account. The existing vault operation is the only decryptor. Any denial retains the original consumed child/unknown result and performs no HTTP. Decrypt failure preserves existing conditional reconnect bookkeeping without changing a known provider result.
5. The branded native transport captures immutable exact endpoint, method, API version and body/post URN. It uses the original signal combined with one bounded native deadline. Its final callback is one-use, awaited to completion and retired on every result; it passes native restrictions into the original locked owner and requires commit acknowledgment. Omitted, repeated, pending or late callbacks never send. The final original clock intersection includes current requester/reviewer, original action/source/connection/credential-profile bounds. Post-check fact validation cannot introduce a contradictory independently scoped clock decision.
6. Keep response/body limits, redirects refused, fixed error categories, exactly one physical attempt and durable unknown/no replay. Link the original signal to response decoding too. A known remote post/deletion confirmation remains known if best-effort bookkeeping fails or the caller disconnects afterwards; canceled/unknown responses never fabricate success. Preserve original attribution and immutable successful publication/URN on deletion.

The timing bounds are not inferred from the ciphertext row. The private growth attachment requires an explicitly qualified, current source for immutable credential-reader/vault/native-transport profile identity and its `notBefore`/`expiresAt`, bound to this action, selected connection revision, current credential version and consuming runtime. Those profile windows restrict every acquisition/currentness/final-send check and are compared again after awaited owner checks. The connection's separately source-bound OAuth expiry can only tighten that intersection; it does not qualify the reader, custody or transport. Missing or changed profile/window/credential version refuses, with no process/database-clock fallback or fabricated expiry. Implement the port and synthetic fixtures locally; no real/default qualifying supplier is established by this proposal.
