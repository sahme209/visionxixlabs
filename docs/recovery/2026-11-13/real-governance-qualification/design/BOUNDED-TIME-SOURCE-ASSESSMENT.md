## Findings and selection

1. [AWS Fargate-specific task metadata](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task-metadata-endpoint-v4-fargate-response.html), ClockDrift section: exposes ReferenceTime, ClockErrorBound in milliseconds and ClockSynchronizationStatus, using Amazon Time Sync Service. The earlier generic metadata page did not establish this Fargate-specific facility. **Preferred source to qualify for the proposed Fargate profile**, rather than a second external clock or custom cryptography. This is documentation, not an actual protected observation. The inspected page does not specify sample-age limits, growth between samples, or an authenticated whole-process origin. It does not justify unchecked Date.now ± returned error.
2. [RFC 10049](https://www.ietf.org/ietf-ftp/rfc/rfc10049.html), experimental, October 2026: sections 5.2.5–5.4 require nonce/request inclusion, delegated Ed25519 signatures, certificate interval and signed midpoint/radius validation. A valid signature authenticates the server's assertion, not its correctness. Section 6 requires an assumed local frequency-error bound when advancing time. Sections 8.1–8.2 require independent operational servers and chained repeated measurements. Therefore one signed reply is not sufficient evidence for adopting this trust model. Seconds-based RFC radius must not be confused with earlier drafts' units.
3. [Cloudflare usage](https://developers.cloudflare.com/time-services/roughtime/usage/): advertises UDP port 2003 and a public key, but calls the service beta with possible root-key changes. Documented configuration is not live availability or approved trust-root provisioning. No key was added to Axiom and no server queried.
4. [Cloudflare implementation repository](https://github.com/cloudflare/roughtime): Go client/utilities, Apache-2.0 label; README reports drafts 08/11, unstable API and explicitly warns against production software. Exact current commit/maintenance cadence and RFC 10049 interoperability were not established by the rendered page. **Reject automatic production adoption**, even though reusable code exists.
5. [AWS ClockBound repository](https://github.com/aws/clock-bound): daemon plus Rust/C clients, shared-memory interval/status, Linux packages and EC2-oriented time sources; README offers MIT or Apache-2.0 licensing. **Alternate EC2 design candidate**, not evidence the daemon, PHC or protected shared memory is available in Fargate or macOS. Full license/NOTICE and exact source review remain before packaging; no dependency was installed.
6. [Cloudflare deprecation notice](https://developers.cloudflare.com/time-services/roughtime/deprecation/): port 2002/its older key retired in 2024; this does not say port 2003 retired. Preserve that distinction. No fallback to a retired endpoint or DNS-supplied unreviewed key.

## Two-page AWS follow-up — approved and consumed

The owner subsequently approved the narrow follow-up; exactly two additional official pages were opened. No linked sample repository, further documentation, real endpoint, native process or account API was accessed.

- [Fargate clock-accuracy walkthrough](https://aws.amazon.com/blogs/containers/run-time-sensitive-workloads-on-ecs-fargate-with-clock-accuracy-tracking/) describes an application consulting current metadata on demand before critical operations. It calls the clock error bound a worst-case offset, rather than merely a measured signed difference. Its separate once-per-minute monitoring example is not an accuracy guarantee or a qualification rule. The shell example uses ReferenceTimestamp, whereas the earlier reference lists ReferenceTime; do not silently accept either as a proven sample-age timestamp. The page does not state a maximum underlying sample age or an error-growth formula. Its demo's Exec/public endpoint/roles/resources are not approved Axiom configuration.
- [EC2 time-synchronization overview](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/set-time.html) explains the regional time service and distinguishes leap-smeared NTP from non-smeared PTP. It does not establish Fargate metadata refresh semantics, nor authorize accessing hardware clocks from Fargate. Do not transplant an EC2 mechanism or mix clock scales without a reviewed profile.

**Decision:** the AWS native source is supported as a candidate for on-demand critical-operation checks, but these reads do not prove the stricter protected current-interval contract. End this documentation-search sequence here; no automatic additional research requests or native probes.
