## Workstream B — website, demonstrations and support knowledge

### B1. Visible reference-site walkthrough

When resumed, open Cursor first in a visible browser, then ChatGPT/OpenAI, Claude, Codex and Grok; Apple is a secondary visual/interaction reference. Let the user see the walkthrough. Inventory every relevant public page and unique navigation/interaction: top navigation, menus, hero CTAs, downloads, product/features, demos/videos, pricing, security/trust, enterprise/contact, documentation, guides, search, support, footer and mobile layout. Follow each relevant button into its destination and inspect the content/layout there. Track visited and blocked pages in a checklist. Do not submit purchases, forms, credentials or external messages. Do not claim every page was inspected if login, plan or access prevents it. Extract principles rather than copying protected branding, copy or media.

Deliverable: comparison matrix, annotated observations and original Axiom information architecture with concrete page/interaction decisions.

### B2. Positioning and website architecture

The first screen must immediately communicate: Axiom governs deployment and connected operational changes, showing who can do what, required review, verified results and recovery. Plan Home, Product/workflows, Integrations, Security/Trust, Documentation, Demos, Download, Pricing/availability and Support. Distinguish implemented, preview and planned capabilities. Ensure each CTA has a clear destination and useful next step. Include responsive behavior and accessible navigation.

Deliverable: approved page map, content hierarchy and original visual system consistent with the app.

### B3. Record authentic Axiom demonstrations

Use the real application with the canonical transparent logo and safe synthetic fixtures. Build short homepage demonstrations and deeper workflow walkthroughs: readiness/connect, governed release, independent review, verified outcome/recovery, Bot tasks and supported app actions. Choose a presentation quality inspired by Cursor's demos without copying its assets. Capture real screenshots/video, cursor actions and captions; redact personal/company data and secrets. Never stage a successful execution that did not happen. Label simulated or local-preview sequences. Obtain genuine human decisions for protected actions.

Deliverable: reusable edited media, accessible captions/transcripts, poster images and version/source-linked capture records.

### B4. Document every supported app and website interaction

Inventory all screens, controls and states, including error/empty/disabled/expired/uncertain states. For each control document purpose, location, prerequisites, permissions, exact steps, expected result, limits and safe recovery. Include numbered screenshots and a real demo where useful. Document every website button/destination too. Organize by user goal with search, quickstarts, concepts, task guides, connector references and troubleshooting. Maintain a coverage checklist so 'every dot' means traceable coverage rather than an unsupported claim.

Deliverable: versioned documentation with stable screen/control IDs, linked media, owner and last-verified version/date; no undocumented customer-facing control in the release checklist.

### B5. Prepare the support-AI knowledge foundation

Store approved documentation as structured, versioned, searchable content with screen/control identifiers, permission prerequisites, source links, screenshots, steps and troubleshooting. Separate public/customer docs from internal secrets and tenant data. Establish retrieval tests for real support questions, citations and version matching. The future local assistant should answer from approved sources, disclose uncertainty and escalate when evidence is absent. Cloud AI later needs separate data-boundary/security review. Documentation does not itself implement an AGI support agent or grant execution authority.

Deliverable: knowledge schema, ingestion/update workflow, representative question/answer evaluation set and a reviewed future support architecture.

### B6. Implement, test and publish the website batch

Build the agreed original pages and docs, integrate authentic demos, fix the old favicon fallback/cache identity and display accurate per-platform installer sizes. Test all internal/external links and CTAs, responsive layouts, keyboard access, performance, contrast, media transcripts, documentation coverage and truthful claims. Review source/security and deploy only under a specific remaining deployment authorization. Verify the live favicon, exact installer links and critical user journeys. No repeated builds or publication without authorization.
