## Scope and authority

Settings → Integrations mounts AWS, Microsoft Azure and Google Cloud guided cards directly, before the Advanced cloud account connections disclosure. This guide inventories every control in those three cards and their direct transport/contracts, plus narrowly cited state/authority helpers. Advanced AWS/Azure enrollment, other integration cards, diagnostics, provider portal steps, service deployment/configuration, backend operations, native shell implementation, token management, database operations and deployment execution are omitted. The parent Settings Manage connections, Refresh verified status and Advanced disclosure belong to the older Settings guide; their presence does not validate a guided connection.

AWS UI management requires a `desktop_session` identity with `connections:manage`; unlike Azure/GCP its component does not separately check `workspace:read` before initial status. Azure/GCP UI reads require `desktop_session` plus `workspace:read`; management additionally requires `connections:manage`. The notice to ask an owner/administrator is guidance, not an access grant. AWS HTTP resolution requires workspace admin, forbids API keys and requests `pipeline:read` plus GET `workspace:read` or POST `connections:manage`. Azure/GCP authority helpers require an unrevoked, unexpired desktop session matching organization/user/session, accepted owner/admin membership and management capability. Displayed capabilities alone do not establish those current server facts.

No guided card accepts pasted keys, tokens, ARNs, account IDs, tenant IDs, project IDs, policy JSON or free-text configuration. There is no checkbox acknowledgement, export, download, copy, delete or deployment/run control in these cards. Review buttons and provider browser consent are separate acts. Local configuration, constructed URLs, digests, simulated receipts and locally generated grant artifacts are not provider authorization proof.

## AWS: configured choice, reviewed proposal, external setup

| Mounted control or display | Condition and effect |
| --- | --- |
| Connect {name}, account and region | Available service and management capability; excludes a matching connected choice/account/region. Disabled while busy/held. Creates a UUID `clientRequestId` and POSTs `start` with the configured `choiceId`. This creates/retrieves a proposal, not an AWS grant. |
| Review details | In `review`, displays the exact read scope, proposed role ARN and trusted broker principal. **Reviewed source** is a native details disclosure exposing template and policy digests; it does not validate hosted bytes or effective IAM permissions. |
| Review in AWS | Requires server `canReview` plus management; disabled busy/held. POSTs `review`, flow ID, literal `expectedVersion:0`, and the displayed proposal digest; opens only the returned matching flow launch URL. This authorizes the handoff, not successful external setup. |
| Open AWS | Only waiting state with launch URL and management; disabled busy. Opens that URL without another review mutation. |
| Cancel connection | Management and server `canCancel`; disabled busy. POSTs flow ID and current expected version. Cancels the attempt; no mounted role deletion or permission revocation is established. |
| Check AWS connection status | Always rendered; disabled busy. GETs the snapshot. Status checks do not create an AWS grant. |
| Recover connection request | Only management, held state and a retained start request; disabled busy. Resends the same `start` payload and UUID. It does **not** send the contract's `recover` action or repeat provider setup. |

The contractual read scope is **EC2 instance metadata; no changes**, with `deploymentAvailable:false`. Choices are administrator-installed registry data: exact organization, unique choice IDs/account-region pairs, twelve-digit account and supported US east/west region. Launch construction binds account, region, exact generated role ARN, broker principal, external ID, capability, template/policy digests and proposal digest. It requires a reviewed template descriptor and an HTTPS S3 object path ending in its digest plus `.yaml`; construction itself performs no provider write and supplies no live policy evidence. The browser destination check allows HTTPS regional AWS CloudFormation home in supported US regions with a quickcreate hash, no embedded credentials/port. The user must independently review the real AWS account and requested setup in AWS; portal instructions and administrator IAM changes are outside this guide.

The supporting state helper binds flow ownership and session, saved inputs/challenge, configuration, expected version, proposal digest, expiry and exact account/region/stack identity. Callback proof is a separate verifier port; a copied ARN, request body or CloudFormation status is not proof. The role validation helper describes one attempt each at fixed STS AssumeRole and GetCallerIdentity, matching the exact assumed-role ARN/account, under a shared deadline. These are conditional source requirements, not a claim that a deployed verifier, registry, hosted template or grant has been checked.

States shown: review; waiting for AWS; verifying; connected read-only; unknown; cancelled; disconnected; expired. Canonical connection binding includes ID/version/account/region/role/external ID. A recorded connection with a failed refresh is labeled **Last recorded connection · current access unverified**. The state helper consumes at most one callback completion attempt; uncertainty becomes unknown without replay. No UI disconnect button exists despite the disconnected state.

Initial mount, focus and four-second polling while waiting/verifying refresh status until expiry. Errors hold new starts/reviews; check saved status first. Browser failure asks for status refresh. Recovery resends only the retained start identity. A successful browser open or label never proves present access or health.

| Mounted control or display | Condition and effect |
| --- | --- |
| Connect Azure / Opening… | Idle not-connected/expired/cancelled and management; disabled unavailable, busy or held. POSTs empty `start`, saves attempt/expiry, then opens validated Microsoft authorization URL. |
| Subscription selection | In selection-required, each returned label/UUID button selects locally, with `aria-pressed`; disabled without management, unavailable, busy or held. No connection mutation yet. |
| Review {label}; Connect subscription / Connecting… | Shows exact subscription UUID and directory UUID after local selection. Explains delegated rights follow the signed-in account and are not a new Azure Reader role. Connect POSTs attempt ID and selected subscription ID, only while the selection still exactly matches returned ID/tenant/label. |
| Manage | Connected without error; toggles local details, no provider mutation. Displays auth-mode explanation and separate deployment governance. |
| Sign in again | Within connected Manage details and management; disabled unavailable/busy/held. Starts a new authorization attempt; source copy says existing connection remains until selected access is verified. |
| Check Azure connection status | Read capability; disabled busy. GETs status, with current attempt ID if present. |
| Cancel connection | Pending awaiting-consent/working/selection-required/outcome-unknown, attempt ID and management; disabled busy. POSTs attempt ID. It does not delete an existing service principal or revoke portal consent. |

The client validates HTTPS `login.microsoftonline.com`, a tenant UUID authorize path, no userinfo/hash, no duplicate query keys, exact Axiom Azure callback, code response, PKCE S256 challenge, bounded state/nonce and only openid/offline_access/profile/ARM user_impersonation scopes (required subset includes openid/offline_access/ARM). This is a delegated authorization handoff; it is not a new Reader role grant. Existing service-principal connections instead display **Connected · read-only**, while delegated ones display **Connected · Axiom read access**. Neither label proves effective account privilege limits or current health.

The narrow provider helper requires configured tenant/client/secret; this guide neither reads their values nor instructs their installation. Token checks describe signed ID-token issuer/audience/tenant/nonce/subject/lifetime binding and ARM scope validation, with configuration digest and home-account continuity. The service helper binds organization/user/session, attempt version/status/expiry, configured directory, exact selected subscription/tenant, verified token claims and stored connection ID/version. Subscription discovery is a bounded first page of at most 100; **truncated** explicitly means incomplete directory inventory. An empty list directs cancellation and use of an account with subscription access, not an automatic permission grant.

Unavailable setup directs administrators to service configuration and existing Reader connections under Advanced; no configuration fields are mounted here. Awaiting consent asks return from Microsoft; working indicates checking; unknown asks for saved status before another attempt; expired/cancelled permit a new start. Connected errors retain the last recorded subscription, without the healthy badge. Status is read on mount/focus and polled every four seconds while awaiting/working until expiry, capped at twelve minutes. Browser opening has a ten-second confirmation timeout; failure asks the user to check the browser before cancelling. Held/unknown failures block repeated start/completion; no automatic mutation retry is implemented.

| --- | --- |

| Connect {project label} ({project ID}) / Connecting… | In selection-required, one button per returned project, showing label and ID. Disabled without management, busy or held. Clicking immediately POSTs completion with attempt/resource ID; there is no second local review/acknowledgement screen. |

The client accepts only HTTPS `accounts.google.com/o/oauth2/v2/auth`, no userinfo/hash or duplicate query keys, exact Axiom GCP callback, code response, PKCE S256 challenge, bounded state and exact `https://www.googleapis.com/auth/cloud-platform.read-only` scope. Project identifiers must match the validated project-ID pattern; returned resource lists are capped at 100. Empty projects directs cancellation and choosing an account with project access; it is not proof of missing IAM roles or a grant instruction. No GCP role/policy editor, service-account key field, reconnect/manage disclosure or export is mounted.

The supporting helper describes owner/session/attempt/status/version/expiry checks, exact listed project membership, token expiry/Bearer/refresh-token and exact read-only scope checks, provider verification before persistence, capacity gating, and canonical connection ID/version/project/credential revocation checks. These describe intended source bindings only. They do not verify deployed grants, effective IAM conditions or current Google service health. Deployment permissions remain separately governed.

Awaiting consent instructs return from Google; working checks access; unknown requires status before another attempt; expired/cancelled permits a new connection. Connected errors show the last recorded project and remove the badge. Mount/focus and four-second polling while awaiting/working read status until expiry. Browser-opening failure says cancel the attempt and connect again; first resolve saved status where an outcome is uncertain. Start/completion errors hold further attempts; no automatic sign-in or completion retry occurs.

## Direct transport and evidence limits

All three desktop clients require the exact Axiom service base `https://visionxixlabs.com` and a paired `axm.desk.` session prefix, send bearer authorization with omitted browser credentials, reject redirects, use no-store requests, bounded UTF-8 JSON bodies, a 25-second deadline and schema/identity checks. AWS uses GET/POST `/api/desktop/cloud/aws/guided` with a 128 KiB response bound. Azure and GCP use `/api/desktop/cloud/{provider}/guided/{start,status,complete,cancel}` and 64 KiB bounds. Azure also observes context revisions and aborts on session/base changes. AWS/GCP check config-object ownership and abort on unmount; these are source behavior descriptions, not a blanket guarantee against every credential-change race.

Azure/GCP completion responses must match the attempt and, when connected, requested subscription/project. AWS action responses are full freshly authorized snapshots rather than standalone mutation receipts. Status reads can reconcile saved state; they are not pure local display refreshes or grants. Save/verify completion persists a connection only under the cited helper conditions; it does not authorize deployment. No standalone Validate, Save configuration, Execute, Retry provider grant, Export, or claim-binding override control is mounted. Do not infer current permission/health from account names, read-only copy, configuration presence, a URL, a version number or a successful local parse.
