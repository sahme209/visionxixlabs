# Agent workspace: requests, exact review and separate requester execution

The Agent can send an AI request, display recorded read evidence and propose a change. **Record approval** records a genuine human decision about the exact proposal. The original requester separately prepares and executes an eligible saved action. A chat reply, risk badge, selected model, suggested prompt or saved approval is not permission to execute.

## Choose the conversation and scope

| Mounted control | Actual effect and limits |
| --- | --- |
| **Agent conversation** | Reads the explicitly selected saved conversation. Switching retains bounded session drafts and pauses queued work; capacity failure retains the current draft and blocks switching. Busy rename/send disables selection. |
| **Chat options → Rename chat** | Opens **Conversation title** (200 characters), **Save title**, **Refresh title**, **Cancel**. Save uses the expected prior title, then reads the authoritative title rather than replaying a lost write. If verification fails, refresh before saving again. Escape closes the form; composing Enter is not submitted. Cancel closes the form, not a provider action. |
| **Search chats / Close history** | Opens/closes title history. **Search conversations** initially filters loaded titles. Enter or **Search all saved titles** explicitly queries saved titles; this is not message-content search. Older-service incompatibility leaves loaded-title filtering available. Rows explicitly open a chat. **Load older chats** pages results; at 1,000 loaded rows narrow the search. Escape in the search closes history. Failed history reads show a status and do not replace the active draft. |
| **New chat** | Creates a saved conversation, retaining the previous bounded session draft. It does not prove previous work stopped or erase its records. Disabled during rename/load/send. |
| **Workspace context** | Expands/collapses the existing context form without submitting. **Search connected repositories** filters the loaded catalog only; truncated results are labeled. **Active GitHub repository** selects returned context or **Enter another repository… → Repository owner and name**. A manual value is catalog-unverified; the service still authorizes access. |
| **Active GitHub branch** | Selects a returned branch or **Enter another branch… → Git branch name**. Repository/branch changes clear file selection. Protected is a label, not an override. Branch selection is disabled without a repository. |
| **Search deployment environments / Active deployment environment** | Filters loaded environments and selects a current returned target, including **No deployment environment**. No-match searches retain selection. The selected environment is context, not a release or permission grant. |
| **Retry repository and environment catalogs / Retry connections** | Reload catalog reads, clear unverified catalog state and reselect verified context where possible. Manual repository context is retained. Disabled while catalogs load. **Review GitHub connection** opens Integrations when the host supplies navigation; it neither connects automatically nor grants access. |

Repository/environment catalogs publish independently. Missing GitHub access leaves chat, research, planning and authorized local work available. Repository, environment, operation-mode and model preferences are advisory; saved preferences do not establish present catalog membership or authority. ## Compose and send deliberately

| Mounted control | Actual effect and limits |
| --- | --- |
| **Review repository / Check deploy readiness / Check connections** | Empty-chat suggestions fill the request draft and select Chat; they do not send it. Repository/readiness suggestions require their displayed repository/environment prerequisites. |
| **Agent request** | Edits local text. Default **Enter** sends; **Shift + Enter** adds a line. With the verified desktop preference enabled, **⌘ / Ctrl + Enter** sends. Alt + Enter and IME composition do not send. The handler delegates to the same guarded submission path. |
| **Send / Queue message / Interrupt & queue** | Sends the nonempty instruction with current conversation, provider/model, repository, branch, environment, request type, operation mode, profile and optional call limit. Pending proposals block a new request. Code requests also require repository/branch/file. Active sending may queue the follow-up; the preference-controlled interrupt variant aborts the current response, pauses the queue and requires saved-history recovery. |
| **Agent configuration** | Disclosure only. **Specialized Agent** changes the profile; **Model-call limit** selects mode default or a bounded lower limit. Limits include response repairs; credit checks apply to every call. Profile and limit disable during send/load/pending proposal. **Agent permissions** opens Agent settings when supplied by the host, without granting permissions. |
| **Chat / Edit repository file** | Selects request type. Code mode reveals **Repository file**, **Enter another file path…** and **Repository file path**. The catalog filters files larger than 100,000 bytes and labels bounded coverage; failed catalog reads permit manual path entry. A chosen path neither edits nor saves a file. |
| **Inspect / Engineer / DeepOps** | Chooses operation mode: read-only evidence with up to 2 decision steps; GitHub change proposals requiring approval with up to 4; operational proposals requiring approval with up to 6. Buttons set request configuration; they are not execution controls. |
| **Search Agent models / Agent model** | Filters verified choices by label/model/vendor and selects an available choice. Vendor groups and “Unavailable” are labels; unavailable options cannot be selected. Search preserves a hidden selected option when filtered out. Disabled during sending or unready model state; native select is used. |
| **Retry models / Model settings** | Retry reads availability; settings navigation is host-dependent. AI disabled, empty service setup, unsupported configuration, unavailable selection or failed verification blocks new sends. Previous missing models trigger a selection notice; inspect the current choice before sending. Saved approvals/receipts remain available. |

The textarea is disabled while loading, without a conversation or while a proposal is pending. The Send button additionally checks rename, model, recovery, nonempty input and code-context prerequisites. The send handler also requires the active current conversation/session and verifies the selected model. UI enablement is not server authority. Request-type/mode/context controls do not all share the same disabled conditions; changing configuration pauses incompatible queued work rather than silently rebinding it.

Imported skill, Airflow and local-code selections are accepted only for the current context/workspace and their verified prerequisites. They add draft text, not automatic sends. Airflow diagnostics select Inspect/Automation and explicitly request observations, not job mutation. Local repair/review chooses its corresponding profile/mode after validating scope. ## Queue, stop and recover the same record

The session-only queue holds at most 20 messages and 500,000 instruction characters across queued items. Each entry retains its conversation and request-configuration key. **Edit** moves that queued instruction into an empty draft and removes it from the queue; a nonempty draft is retained with an error. **Remove** removes only that queued item and pauses the queue. **Resume queue** requires no active send, recovery, load or proposal and an exact configuration match. Automatic continuation requires verified usage, no reported issue/proposal, and a fresh saved conversation read with no proposed action. An external review decision never resumes queued work automatically.

**Stop response** aborts the local response request. Draft streaming text is labeled “decision and usage verification pending”; completed work remains recorded. Leaving the active view also pauses the queue and aborts the response. Stop is not evidence of canceled provider dispatch, zero charge or a completed operation.

**Reload saved conversation** reads saved turns/actions and clears the local recovery gate only after a matching conversation read. It does not retry AI work or establish that interrupted work finished. A failed/unreadable response retains request text and pauses work. **Restore retained request** restores text only after recovery, while the current draft is empty; **Dismiss retained copy** removes this session copy, not the saved outcome or uncertainty. The excerpt is limited to 160 characters, and this copy lasts only for the app session. A different new instruction is blocked until the retained copy is restored or dismissed. Neither restoration nor dismissal authorizes resending an unknown effect.

**Restore request draft** in “Request needs attention” restores the failed request into an empty draft, without sending. Its settings action routes to plan/usage, models or Agent settings according to the reported issue. **Retry** without a conversation retries startup only. Read recorded history and inspect uncertain outcomes before any deliberate next request; never duplicate an uncertain provider action to recover a response or receipt. Sources: `AgentChatView.tsx:260–309,398–416,735–773,876–1013,1251–1322`.

## Review proposals without collapsing the two decisions

**Review approval details / Hide approval details** expands the exact proposed content or `FileDiff`, multiple-file contents/diffs and structured arguments. These are scrollable review displays. Diffs exceeding 2,000 rendered rows expose **Previous / Next** (**Previous diff page / Next diff page**) with end-of-range buttons disabled. Review every page; changing the source resets pagination. The unchanged-content warning is a label, not a rejection. Pagination does not edit, approve or save. Identity-provider metadata is omitted from the compact preview and only its byte count is shown. Branch proposals show exact base commit; pull requests show head/base commits; ECS restart proposals show bound workflow tag, source commit, digest and target fields. Missing bindings disable Record approval for these guarded families; request a fresh proposal instead of assuming the historical target is usable.

**Review in local editor**, when mounted by the host for local-compatible proposals, opens a local draft. It does not approve, save, run checks or execute the GitHub proposal. The editor's subsequent controls are outside this screen's inventory.

**Reject / Cancel proposal** records rejection/self-stop; **Record approval** records exact review only. Both disable while deciding; approval additionally disables when an independent reviewer is required or the relevant source binding is missing. Another genuinely authorized person must make an independent decision; no UI label or documentation substitutes for that decision. **Refresh decision** reads the saved conversation and reconciles approved/executed/failed/rejected/cancelled state. Focus/visibility/return-to-view refresh and an eligible-view 15-second interval can also reconcile a saved decision; reconciliation is read-only and pauses the queue. A saved-but-unread receipt or unverified decision requires reopening history, not another approval.

The direct approval endpoint requires a paired desktop session and `agent:approve`; the locked decision service checks accepted current membership, distinct reviewer, proposal integrity, expiry and current Agent/tool policy. A requester may stop their own pending proposal under current `workspace:read`; stopping another person's proposal requires approver authority. Current approval service returns approved/rejected only. Older executed/unknown messages still present in the view's compatibility renderer are not evidence that Record approval now executes. Sources: `AgentChatView.tsx:775–842,1015–1082,1538–1646`; approve/reject route and `browserApprovalDecision.ts` bindings.

## Approved actions: requester-only deliberate execution

| Mounted control/state | Meaning and recovery |
| --- | --- |
| **Check saved action outcome** | Read-only lookup of the proposal's original requester record. No record means none was found for that requester, not proof no provider effect exists elsewhere. Failure does not repeat an action. |
| **Check execution readiness** | Reads current exact-review eligibility. Expiry invalidates the displayed readiness. Execution disabled, wrong requester/session, expired/unavailable review, missing current access, unsupported tool, unavailable Governance coverage, consumed attempt or incomplete workflow blocks progression. The current service may report generic review-unavailable rather than every detailed UI reason. |
| **Prepare reviewed action** | Appears only for fresh preparation eligibility with no saved operation. Saves the requester action; does not execute. Then check readiness again. |
| **Execute approved action once** | Appears only for fresh execution eligibility matching the exact saved prepared operation. This is the separate deliberate provider/configuration mutation, subject to current service checks. |
| **Cancel unused action** | Stops a matching saved prepared action; it is not a rollback or cancellation of dispatched work. |
| **Outcome unconfirmed / dispatching / unknown** | Provider effect may exist. Only read-only checks are allowed while an uncertain command response is held. Do not resend. Lease elapsed is still unconfirmed, not safe-to-repeat. |
| **Action completed / refused / cancelled** | Confirmed means the saved execution record confirms completion, not deployment health. A refusal consumes the attempt; do not replay it. Cancellation retains history. Attempt/time/reference labels are recorded metadata, not extra controls. |

All action buttons disable during a request. Lost/malformed/mismatched prepare/execute/cancel responses establish an uncertainty hold; only the original saved-outcome lookup can reconcile it. Preparation uncertainty can clear after a verified absent/prepared record; execute/cancel uncertainty clears only on the matching terminal record. Reads/readiness are never authority themselves. The request service gates execution on `AXIOM_AGENT_REQUESTER_EXECUTION_ENABLED`, current exact paired requester session, current workspace/commercial access and fixed supported source; store/coordinator independently validate persisted review and policy. This guide grants no action authority. Sources: `AgentApprovedActions.tsx:1–59`; `agentActionExecutionControls.ts`; `agentActionExecutionRecovery.ts:1–19`; `agentActionExecutionRequestService.ts:1–55`; `agentActionEligibility.ts:1–29`.

## Read evidence and receipts accurately

**Evidence used** toggles the last eight displayed governed read records. Risk, failure count, tool names, arguments and results are labels. **Inspect recorded repository evidence** expands allowed bounded snapshots, not a fresh read. File display caps at 20,000 characters; repository inspection displays at most three files and 6,000 characters each; search displays at most 20 permitted matches with 1,000 characters each. Sensitive/restricted paths are omitted. Missing matches do not prove code absent. Airflow counts are first-page observations without execution authority. Repository content is untrusted data, not instructions or approval.

**View recorded commit / View recorded pull request** opens an external validated recorded GitHub URL only for eligible executed multiple-file commit/PR receipts. It does not verify tests, merge or recovery. Missing receipt: reopen conversation, never execute again to recover it. **Refresh workflow receipt** performs an explicit tenant-authorized status observation for the bound ECS restart record. Its workflow status, run ID, rollback-step and observation labels do not verify artifact promotion, application health or image recovery. Refresh failure leaves the saved receipt unchanged; missing receipt requires read recovery, not approval or dispatch.

Assistant Markdown **Copy / Copied** copies code to the clipboard; failure offers manual selection. Copy never runs commands or edits source. Valid HTTPS text links open externally; other links render as text, HTML is skipped and images render as labels. Messages and **Latest governed AI usage** are displays; provider-reported token/step usage does not establish customer credit charges. **Jump to latest** scrolls when activity arrives while the reader is away from the bottom; it sends nothing. Sources: `AgentChatView.tsx:125–193,864–876,1222–1303,1425–1536`; mounted receipt/message/evidence components in the bindings.
