## Authority and status boundaries

AWS UI reads require `desktop_session` plus `workspace:read`; AWS management requires `desktop_session` plus `connections:manage` (the UI does not additionally test read capability for that form). Azure reads require paired session plus `workspace:read`; management also requires `connections:manage`. Recovery/API-key identities cannot enroll. The AWS notice explicitly directs browser pairing and an authorized administrator when management is missing; Azure directs pairing with accepted workspace membership.

Direct request wrappers require an `axm.desk.` bearer and omit browser cookies. Azure additionally refuses any API origin other than `https://visionxixlabs.com`, has a 25-second fetch timeout, checks configuration ownership after response, maps known errors, and never echoes arbitrary provider text. AWS uses a 25-second race covering fetch and JSON-body completion, aborts/cancels afterward, and reports timed-out or unreachable outcomes as unconfirmed. AWS UI owns the configuration-context check; its wrapper itself does not impose Azure's exact-origin gate. These observations are source boundaries, not native transport acceptance.

Immediate route runtime adapters require paired desktop credentials (`allowApiKey: false`), `pipeline:read` / `workspace:read` for reads and `pipeline:trigger` / `connections:manage` for mutations. Disconnect requests permit the resolver's inactive-access recovery path (`requireActiveAccess: false`), while retaining identity/capability checks. Enrollment services recheck current unrevoked, unexpired device ownership and accepted membership; management requires owner/admin plus capability. Allowance, compatible storage, current connection versions and provider verification may still refuse an action. A visible button is not current authority.

Both panels mount **CloudOnboardingStatus**, an informational read only for paired workspace readers. It checks local prerequisite evidence, never a provider connection/grant. AWS distinguishes unavailable vault, missing broker, disabled live mode and locally present prerequisites. Azure distinguishes vault availability; ambient Azure settings do not enroll a workspace. Every readiness response fixes provider validation to `not_checked`. Loading or unavailable prerequisite status establishes neither a usable connection nor a failed provider account.

## AWS: existing role and challenge

| Mounted control/readout | Source behavior and boundary |
| --- | --- |
| **Expected AWS account ID**, **Existing IAM role ARN**, **AWS region** | Plain non-secret identifiers; defaults are empty ID/ARN and `us-east-1`. Trim before submission. ID must be 12 digits; role ARN must use aws/aws-us-gov/aws-cn partition, valid role path and matching account; region must match the contract pattern. No AWS access-key or secret-key input exists here. |
| **Prepare read-only enrollment** / **Preparing challenge…** | Calls `startAwsReadOnlyEnrollment`; guarded by management and idle phase. Clears prior challenge/confirmation/error/notice. Returned challenge must match submitted account, role and region and be unexpired. |
| **Enrollment external ID** | Read-only text field, no dedicated Copy control. Give only to an authorized trust operator using the reviewed caller principal from separate instructions. Preparing/showing it does not change IAM trust or grant access. |
| Authorized-operator checkbox | Exact attestation: an authorized operator separately configured this existing role for expected read-only access. It is local confirmation, not independent policy inspection or authorization for trust changes. |
| **Verify existing AWS role** / **Verifying role identity…** | Requires challenge, checked attestation, idle state and unexpired deadline. Sends attempt ID plus external ID. Accepts only connected/connected-status account matching expected account and enrolled region. Successful response updates service-recorded list, clears challenge, and says bounded inventory needs a separate read. |
| **Dismiss enrollment** | Present during challenge or operation; invalidates local operation, clears challenge/confirmation/error, returns idle. A server verification already started can finish; refresh account state. Dismissal is not server cancellation and does not itself expire the challenge. |

Editing any AWS identifier invalidates local pending operation and clears challenge, confirmation and messages. A one-second timer updates expiry presentation. Service source creates a ten-minute challenge tied to organization/user, exact role/account/region, existing record update time and credential version. Completion rejects missing/mismatched/expired/consumed attempts; after external validation it rechecks authority, time and immutable target/version state inside a serializable transaction, then atomically marks the unconsumed attempt consumed and persists the versioned configuration. This is one successful consumption, **not** proof that only one external validation call can ever occur: validation precedes the transaction claim, and failed pre-claim validation does not consume the attempt. Expired/used/conflicting attempts require refresh or a fresh challenge.

Verification covers expected assumed role/account identity; it does not attest the role's complete IAM permission policy. This screen creates no roles, changes no trust policies, runs no Terraform and grants no deployment permission. ARN partition support is syntax acceptance, not complete GovCloud access or governance proof.

## AWS saved records, explicit inventory and disconnect recovery

Initial authorized mount reads `desktopCloudAccounts`; **Refresh AWS account state** repeats it and is disabled while refreshing. Distinguish checking, unavailable, no records, and records returned. Rows show account ID, **Role identity verified**, **Disconnected from Axiom**, or **Connection state requires refresh**, regions, inventory not checked/unavailable, optional last validation, and disconnection timestamp/history/allowance retention. These are service-recorded identities, not fresh provider-health checks.

Connected unsuspended rows mount **Read bounded EC2 inventory** / **Reading bounded inventory…**. It requests one EC2 page in the enrolled region. Contract requires `source: live`, `complete: false`, a timestamp, truncation flag, and at most five instances with ID/state/type/availability zone. The component also matches account and enrolled region. Result shows observed time, truncation/single-page limitation and complete inventory **no**. Empty means no instances in that sample, not empty account. Failure substitutes no sample. There is no scan, deployment or pagination control.

**Disconnect from Axiom** opens an alert dialog naming the account, then **Disconnect Axiom access** / **Disconnecting Axiom access…** and **Keep connection**; after uncertain suspension the dismiss action reads **Close confirmation**. Confirmation explains local saved-configuration removal and stopping new reads; roles/trust, existing STS sessions, deployments and history are not revoked/deleted. UI states issued STS sessions may remain valid up to fifteen minutes and account allowance remains counted. Leaving while busy does not cancel the server command.

Disconnect sends record ID and expected connection version. Inventory is immediately hidden and challenges invalidated. Error or ambiguous response leaves connection use suspended until fresh post-settlement account read; a list started before/during the pending command cannot release suspension. A matching disconnect result must preserve account identity and increment the exact current version by one before replacing authoritative state. Older list/command responses cannot overwrite a reenrolled credential. Disconnected manageable rows expose **Prepare a fresh reconnection**, which fills account ID and first recorded/default region, clears role ARN, and requires a new verified enrollment.

## Azure: raw credential form, validation and records

The management-only form contains **Azure tenant ID**, **Azure subscription ID**, **Azure client ID**, and password **Azure client secret** with autocomplete off/new-password. IDs must be UUIDs and normalize to trimmed lowercase. Secret must be nonempty, at most 4096 UTF-8 bytes and contain no control characters; it is not trimmed. Existing version must be valid or null. **Validate & connect Azure** / **Working…** submits existing service-principal credentials with expected current subscription version, immediately clears the secret field even on validation failure, and disables mutations while busy. Unlike AWS, Azure has no external-ID challenge, trust checkbox, browser grant, separate review dialog, setup-copy button or expiry countdown in this advanced form.

The mounted copy says the secret goes to the backend encrypted vault, is not saved in desktop settings, and subscription read validation does not verify a Reader-only role assignment. These are implementation statements under source review, not an independently verified vault/security guarantee. No credentials or vault contents were read for this guide. Raw credential submission is distinct from creating a principal or changing Azure grants, which this form does not do.

Success requires connected result matching normalized subscription, expected version plus one and unchanged authoritative prior identity/version; otherwise refresh before retry. It replaces the saved row, clears prior inventory/suspension for that account and says service-response read access is verified while inventory is separate. Saved records show subscription ID, service status, connection version and separate-read reminder; contract excludes credentials and fixes `enabled` and `agentScanAvailable` false. **Refresh Azure connections** is disabled during mutation or catalog loading. Loading, empty ready catalog, errors with previously recorded rows and unconfirmed state are distinct.

Connected rows expose **Read first resource-group page**, disabled while reading/suspended/busy. Request requires read authority, connected record and no pending disconnect; response must match account record ID, subscription and current connection version. Contract scope is `first_resource_groups_page`, limit 100, `complete: false`, observation time and bounded limitations. Display lists group name/location and says first page only; no groups observed is not proof the subscription is empty. There is no pagination or cloud-change control.

**Disconnect Azure** directly calls disconnect; this advanced Azure form has no confirmation dialog. It uses record ID and expected version, immediately suspends row use, invalidates inventory requests and clears shown inventory. Acceptance requires exact account/subscription, disconnected status and version plus one against unchanged authoritative version. Success copy states stored credential removed while principal, grants and issued tokens remain unrevoked. Error/conflict requires refresh; suspension remains until fresh catalog reconciliation. Reconnection uses fresh form credentials and validation; no dedicated reconnect button exists.

## Context ownership and finite coverage

Both wrappers synchronously key-reset children on client configuration, organization, identity kind or capability changes. Unmount invalidates pending ownership. AWS additionally scopes inventory to record/account/version/validation time/regions/context; Azure maintains per-record request generations, version checks, pending mutation sets and catalog reconciliation that retains newer versions and suspended pending rows. Old results cannot be treated as current simply because they arrive later. These finite source guards do not establish complete end-to-end race correctness. Panel action handlers generally await result objects without their own catch/finally; this guide does not claim every unexpected thrown call clears busy state or produces clean recovery. Azure catalog refresh has an explicit catch; ordinary wrapper failures return structured errors.
