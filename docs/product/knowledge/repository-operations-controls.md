## Before acting

Choose the intended checkout and inspect the displayed repository, branch and recorded changes. A remembered status, green process result, visible button or local confirmation is not independent approval, current server permission or a source snapshot. Connected-repository metadata supplies the UI's known default branch and PR base; without matching metadata that UI comparison is not a universal default-branch guarantee. Parent view ownership checks retire obsolete callbacks/configuration/checkout generations, but do not undo native work already submitted or cancel Git/check processes. [workspace-context, workspace-status]

Existing access and provider prerequisites must already be authorized. Pull and push request purpose-specific credentials; push and PR require current server write authority. Enrolled or unavailable Governance coverage refuses these legacy write paths; neither entering a different branch nor local confirmation fixes that refusal. No new connection, grant, credential issuance, command or publication is authorized by this source guide.

## Separate local checkouts with Workspaces

Expand **Workspaces** under the selected repository. Inventory loads when the child mounts; **checking**, verification failure, verified-empty and populated inventory are different states. Opening a worktree delegates to the existing checkout chooser; a dirty editor can require its separately documented discard confirmation. [worktree-ui, workspace-mount]

| Documentation ID / control | Purpose and expected local result | Preconditions, limits and recovery |
| --- | --- | --- |
| `repository.operations.worktree.disclosure` — **Workspaces** | Shows managed checkout inventory and operations. | Opening it is not a native create/remove action. Displayed count is verified inventory, not isolation/security qualification. |
| `repository.operations.worktree.branch` — **New worktree branch** | Enter a new branch name for a separate checkout. | Input maxLength 200; disabled when parent-disabled or busy. Native validation additionally checks UTF-8 byte length, trimming, leading hyphen, valid ref and that the branch is new. |
| `repository.operations.worktree.create` — **Create worktree** | Creates a managed sibling checkout at the selected checkout's captured committed HEAD and a new branch. | Requires nonblank name, verified inventory and idle/enabled state. Uncommitted edits stay in the source checkout; creation does not open it, install dependencies or run tests. Native creation can succeed before a later size check reports failure: inspect refreshed inventory before retrying. |
| `repository.operations.worktree.refresh` — **Refresh workspaces** | Deliberately reloads recorded worktrees and size metadata. | Disabled while parent-disabled or busy. Read failure empties rows and marks inventory unverified; it is not proof that existing folders disappeared. |
| `repository.operations.worktree.open` — row **Open** | Selects that recorded checkout in the parent. | Current checkout cannot be reopened from this button; disabled while busy/unverified/parent-disabled. Follow any unsaved-editor prompt; switching is not command cancellation. |
| `repository.operations.worktree.remove` — row **Remove** | Opens the exact checkout-removal dialog. | Same row guards as Open. The current checkout cannot be removed from here. This button alone does not delete files. |
| `repository.operations.worktree.cancel` — **Cancel** | Dismisses the removal dialog. | Cancels only the pending local choice, not an already submitted native removal. |
| `repository.operations.worktree.confirm-remove` — **Remove clean checkout** | Requests removal of the reviewed recorded checkout folder; branch/commits remain. | Native code refuses changed/untracked/ignored files, unusual index exclusions, foreign ownership and locked worktrees; it does not force/prune/delete the branch. Unconfirmed results require inspecting refreshed inventory and preserving files, not blindly repeating removal. |

Native limits are 25 managed checkouts and `50 * 1024^3` combined file bytes, excluding shared Git objects. Managed paths must be real recorded sibling directories with matching Git common-directory ownership. Worktree-specific Git calls disable hooks/fsmonitor/submodule recursion and neutralize configured checkout filters. These finite measures do not establish general OS isolation, safe repository code or the same behavior for every other Git command. [worktree-native]

## Run only trusted repository checks

The checks toolbar lists detected definitions, or **No supported checks detected**. Current detection offers configured npm `build`, `typecheck`, `lint`, `test` scripts, Cargo check/tests when `Cargo.toml` exists and Swift tests when `Package.swift` exists. These names are not a guarantee of what arbitrary scripts do: even a “typecheck” script can write files or access network/secrets. No dependency installation is promised or authorized. [verification-native]

| Documentation ID / control | Steps and result | Limits and recovery |
| --- | --- | --- |
| `repository.operations.check.run` — detected check button | Inspect the shown description/command, then the **Run …?** confirmation and deliberate **Run check** action. | Disabled while another view operation is busy. Save/discard unsaved editor content first: checks run disk files. Consent/source epoch and root are rechecked around native preparation. Local confirmation is user consent to this process, not independent approval or a sandbox. |
| `repository.operations.check.stop` — **Stop check (direct child only)** | Requests cancellation of the current owned run; the UI marks the attempt canceled/stale and never accepts its result as passing. | Offered while a prepared run is executing. Accepted stop, already-completed response and unconfirmed stop have distinct messages. Descendants remain unverified; navigating away/closing a view is not a stop action. Do not start replacement work assuming all descendants stopped. |
| `repository.operations.check.output-toggle` — **Last check passed/failed** or **Previous check result (stale)** | Shows/hides the recorded result/output panel. | Display is historical process evidence, not current working-tree certification. Stale local edits prevent using the receipt as current repair context. |
| `repository.operations.check.output` — focusable output | Read check ID, duration, exit code and captured stdout/stderr; empty output has an explicit message. | Output may contain private data or credentials. This guide does not authorize exporting it. Invalid native receipts are refused; absence of a result is not success. |
| `repository.operations.check.agent-output` — **Prepare check output for Agent** | Opens a local confirmation with at most the first 8,000 characters; review it before preparing an unsent Agent draft. | Requires output, idle state and a host handoff callback. Confirmation rechecks source epoch/verification generation and has a once-only local handoff guard. Preparing does not call a model or execute commands; redact the unsent prompt before any separately authorized Send. |
| `repository.operations.check.agent-repair` — **Prepare repair with Agent** | Opens an unsent repair-draft review bound to the selected file/repository/branch and failed receipt excerpt. | Requires non-stale failed result, usable exit code/target, selected clean file and valid prompt context. Confirmation rereads status and disk content and refuses changed source/target/receipt ownership. It does not save, apply a fix, rerun checks or approve changes. |

Native preparation binds canonical root, check ID, manifest bytes and window, expires after 60 seconds and is claimed once; registry capacity is 32. Manifest reads are capped at 1,000,000 bytes. Actual check execution clears inherited environment, supplies PATH, HOME, CI=1 and NO_COLOR=1 (macOS filters PATH to absolute entries and adds known tool directories; other platforms retain inherited PATH), and uses no UI-supplied shell command. It remains unsandboxed user-level repository code. A 300-second process/output deadline and combined 1,000,000-byte output limit are not whole-process-tree security. On Unix, owned process-group cleanup is attempted before reaping, with a bounded direct-child fallback; deliberately detached descendants can escape and remain unverified. The UI's conservative stop wording must not be upgraded to guaranteed descendant termination. [verification-native, receipt-parser]

## Branch, Pull and Push

| Documentation ID / control | Steps and result | Preconditions and recovery |
| --- | --- | --- |
| `repository.operations.git.disclosure` — **Branch & sync** | Expands these controls in compact presentation; initially open when not compact. | Disclosure does not run Git. |
| `repository.operations.git.branch-name` — **new branch** | Enter the desired new local branch name. | UI trims it; native checks nonempty/up-to-240-byte name, rejects leading hyphen and uses Git ref validation. |
| `repository.operations.git.branch-create` — **Branch** | Creates and switches to a new local branch, then refreshes status and clears the field. | Requires selected checkout, nonblank name and idle state. It does not push. Native failure may occur after some local Git effects; inspect branch/status before another attempt. |
| `repository.operations.git.pull` — **Pull** | Review **Pull remote changes?**, then **Pull changes**. On confirmed completion, status refreshes and the UI reports fast-forward synchronization. | Requires recorded GitHub target and idle state. Native requires matching canonical remote/reviewed branch and clean tracked/untracked state, fetches the reviewed branch, rechecks origin/branch/clean state, then merges fast-forward-only. Fetch can have updated remote-tracking state even if a later merge refuses; inspect before retrying. |
| `repository.operations.git.push` — **Push** | Review **Push branch to GitHub?**, then **Push branch**. | Disabled on the UI-known default branch. Native checks target/origin/current branch and pushes an explicit same-name branch refspec, not late-resolved HEAD and not force push. It does not open/merge a PR or prove CI/deployment success. Lost/unconfirmed responses require read-only inspection of the original branch, not automatic resend. |

The Git credential is obtained through `/api/desktop/github/clone-token` with exact repository/purpose and, for push, branch. The selected server path preserves scoped installation/current actor/connection/Governance checks and real push credential lifetime accounting; clone/pull use the existing contents-read profile. The bearer itself is repository-wide, not branch-bound, and remains usable until provider expiry or revocation. Exact native refspecs, local invocation completion and lease accounting do not narrow or revoke that bearer. A returned credential URL is an internal transport input, not a user-editable alternate remote. Native scoped Git uses a canonical credential-free URL plus child-only authentication configuration and disables redirect/credential-helper reuse for that request; this is not proof that all memory/descendant/custody lifetimes are qualified. The helper waits for child output; this source provides no corresponding Git Cancel control or check-style five-minute deadline. [credential-route, git-native, client-methods]

PR creation uses `/api/desktop/github/pull-request`, current paired `github:write` authority and the existing fixed transport guard. Enrolled/unavailable legacy coverage refuses before token/write. UI default-branch/clean-status checks are not a universal server invariant or a lock against external Git changes. The existing local push followed by PR creation has no durable combined operation locator or automatic rollback promised by this guide. ## Shared confirmations, stale ownership and unknown outcomes

`repository.operations.confirm.cancel` is the existing shared **Cancel** choice; `repository.operations.confirm.execute` is the operation-specific confirmation button (**Pull changes**, **Push branch**, **Run check**, **Publish and open PR**, or Agent-draft preparation). The parent clears the dialog before awaiting its callback. The existing nested-dialog guide owns backdrop/Escape/discard details. Local dialogs neither create independent review evidence nor cancel submitted native/provider work.

Busy/error/notice state is owned by the view's current mounted/configuration/context/checkout generation. A late result can be ignored without proving the command did not run. Recorded status/default branch/check output may become stale through external tools. Save/commit/push/PR/worktree failure is not automatically effect-free. Preserve the original target, inspect supported disk/status/history/provider readback, and do not automatically retry unknown work or use a different path/account as a refusal workaround. Preparation for Agent remains an unsent local handoff; actual AI/provider activity has its own authorization and cost boundaries.
