# Homepage illustrative deployment model — controls and limits

**INTERNAL SOURCE GUIDE — unpublished and customer ineligible.** Author: Codex draft; genuine human editorial owner unassigned. This describes the current local presentation source, not an installed/released version, a live deployment or complete Governance. ## Location and purpose

Home `/` places **How a governed deployment moves through Axiom** after the main purpose/availability introduction. The model explains a fictional release from request through evidence/recovery, including refusal and uncertainty. It precedes the separate deployment-record assembly and the later product-media/scripted presentation. These three surfaces have different controls; this guide covers only `GovernedDeploymentModel`, its pure scenario data and the immediate scene contract.

No sign-in, selected workspace, provider connection, approval or payment is required to read this public explanatory model. Its controls do not connect an integration, access an account, call an AI model, approve a change, deploy, retry, reconcile or roll back anything. Loading a public page and its compiled code/assets can involve normal browser requests; this is not a claim of zero network activity.

The persistent **Illustrative model · not a live deployment** label applies to every scenario. Readouts explicitly say **Illustrative scenario values · sample AI usage, credits and status · not your workspace activity**. Terms such as Approved,100%healthy or Rolled back belong to the selected fictional example, not a result observed in your infrastructure. Statements shown under “Guarantee” explain the model's intended rule; they do not establish qualified runtime enforcement or current feature availability.

## Scenario controls

The **Scenario** group contains five ordinary buttons. Tab/Shift+Tab focuses them; Enter/Space activates a focused button. `aria-pressed` identifies the selected scenario. No arrow-key scenario-selection handler is defined here.

| Proposed documentation ID | Button | What this example shows; what it does not do |
| --- | --- | --- |
| `website.home.flow.approved` | Approved release | Example progresses through Audit and recovery with sample approved/healthy readouts. No real approval, run or health check occurs. |
| `website.home.flow.failed-scan` | Failed scan | Policy and scans is blocked; later stages are not reached. The example caption describes stale security evidence and no approval request. No actual repository scan runs. |
| `website.home.flow.rejected` | Rejected | Approval gate is blocked; later execution does not start in the example. No person’s decision is recorded. |
| `website.home.flow.unknown` | Unknown outcome | Execute is uncertain and later stages are not reached. The example says reconciliation is required; this control cannot inspect, reconcile or retry a real uncertain action. |
| `website.home.flow.rollback` | Rollback | Example health regression and a separately governed restoration narrative, with different sample usage. It does not request or perform rollback. |

Selecting a scenario changes local model/readout/audit-example state. It does not change the currently inspected stage in the inspector, reload a workspace or renew any approval. The component starts with **Approved release** selected, **Approval gate** inspected and playback state enabled; those defaults are illustrative, not recommendations or production intent.

## Inspect a stage

The **Inspect a stage** group has eight ordinary buttons, each with a visible number/name, supplementary state dot, pressed selection and a screen-reader state label. `aria-controls` targets the generated inspector ID. Tab/Shift+Tab and Enter/Space use native button behavior; this group has no custom arrow/Home/End navigation handler. Do not confuse it with the separate assembly's keyboard controls.

| Proposed documentation ID | Stage button | Inspector question |

| `website.home.flow.intake` | 01 Intake | Which source/request/target facts frame the example? |
| `website.home.flow.ai` | 02 AI analysis | What summary and model-usage information does this example describe? |

| `website.home.flow.review` | 04 Approval gate | Where does the independent-review narrative fit? |

Selection changes the inspector's summary, ordered internal steps, data-in/out, stated rule and failure explanation. It does not advance the scenario, unblock a failed stage or change a real result. In3D mode, deliberate selection asks the existing scene to move toward that stage; no camera motion is required to read the HTML inspector. The same stage names and textual states remain in the no-WebGL list. Stage labels wrap rather than hiding the name behind truncation.

## Conditional playback and camera controls

| Proposed documentation ID | Control | Availability and exact scope |
| --- | --- | --- |
| `website.home.flow.playback` | Pause / Play | Offered only after a3D scene is active and the component's reduced-motion state allows animation. Accessible names are Pause model / Play model. Toggles local scene playback; does not cancel/revoke a real operation. |
| `website.home.flow.overview` | Overview | Offered only in3D mode. Requests the scene's overview camera, leaving the selected inspector/scenario intact. It is not a data refresh or reset of a real workflow. |

The component checks WebGL and reduced-motion support, lazy-loads its existing scene near the viewport, tracks section visibility, and disposes the scene/listeners on cleanup. Unavailable WebGL/observer support, rejected scene loading or the renderer's slow-device callback use the2D path. The pending/2D stage list has natural height; scenario controls, caption and stage selectors participate in normal document flow outside the canvas. Source contains no explicit load-error message distinguishing these fallback causes. This is not verified performance or live preference-change behavior.

## Readouts and audit stream

The definition list shows **Stage**, **AI tokens**, **AI credit held / AI credit settled**, **Approval**, and **Rollout / health**. The example audit stream is explicitly marked **sample · illustrative ids**. These readouts are derived from scenario data and animation progress. They do not read billing, debit credits, reserve money, report actual model usage or establish provider health. Both readouts and audit text have live-region semantics in source; practical screen-reader announcement frequency remains to be tested.

If a sample is confusing, choose another scenario or inspect its stages. Reloading/remounting starts the model's defaults; there is no persistence, real recovery action or account state to restore. A real unknown operation must be handled in the supported authenticated workflow with its original evidence and genuine approvals; never infer authority from this illustration.
