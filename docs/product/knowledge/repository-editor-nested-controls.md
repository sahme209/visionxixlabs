## Opening or switching with unsaved edits (families 7–9)

Start in the mounted Repositories workspace with an existing loaded file and a buffer different from its loaded/saved baseline. Selecting a file row opens **Discard unsaved changes?**, including when the same dirty file is selected again. The shared dialog offers **Cancel** and **Discard and open**. Preserve wanted draft text before confirming. Confirming calls `openFile(path)`: it clears the old loaded file, history, selection and buffer before submitting `read_repository_file`. A successful current request loads the new baseline and text; a read failure can leave the editor empty and show an error. It is not a recoverable draft stash or disk write. Inspect the selected checkout/path and correct the read problem before deliberately reopening; discarded edits have no persistent recovery here.

Choosing a different checkout while dirty opens **Switch repositories?** with **Cancel** and **Discard and switch**. Choosing the already selected checkout returns without a dialog. Confirmation changes checkout ownership/generation and clears file, history, status, checks, errors/notices and confirmation state. The selected checkout then follows the existing selection/loading effects. This is not a commit, save or remote operation. With a clean buffer these selection actions proceed without this discard confirmation. Checkout acquisition and available choices remain the acquisition guide's scope.

**Cancel** dismisses the pending dialog without running its callback. The backdrop's mouse-down handler also dismisses; mouse-down inside the alertdialog stops propagation. Escape dismisses via a window listener only while this pane is active and a confirmation exists. Cancel has `autoFocus`; source markup supplies `role="alertdialog"`, `aria-modal` and a title association. These facts do not establish native focus trapping, focus restoration or a completed keyboard/accessibility review.

All these workflows use the same inline dialog, not separate confirmation components. `confirmAction` captures the current action, clears the dialog, then awaits its callback. No pending-state button or post-confirm Cancel is defined here. The owner wrapper checks mounted state, desktop config/context revision and checkout generation before invoking a captured callback. It can suppress an obsolete callback; it cannot recover a discarded buffer or prove native work stopped. Cancel before confirmation prevents this pending callback; closing a prompt or changing UI ownership after a submitted read/write is not native cancellation. In particular, an uncertain prior Save must be reconciled by inspecting current disk content before retrying. A discard/switch does not prove that Save rolled back.

## Preparing selected code for Agent (family 27)

Prerequisites: active mounted editor, loaded file/editor ref, current owner, an `onAskAgent` callback, no busy operation, and 1–8,000 selected JavaScript string units from an accepted relative path. The entry button's disabled state uses selected length and path screening; the handler repeats validation against the actual selected excerpt. The helper rejects invalid paths and known sensitive environment, credential and key paths using `repositoryEvidencePolicy`. This is path screening, not content scanning; review credentials and private data yourself.

**Ask Agent** / **Ask Agent about selection** captures the file object, complete buffer snapshot and selected excerpt, then opens **Prepare selected code for Agent?**. This dialog contains descriptive text and the shared **Cancel** / **Prepare Agent draft** buttons. The code-selection branch supplies no preview field; do not claim the dialog displays the selected excerpt. Cancel, backdrop and active-pane Escape dismiss without preparing a prompt.

**Prepare Agent draft** rechecks that no operation is busy, the loaded file object is identical and its buffer still equals the captured snapshot. Otherwise it reports **The file changed while reviewing this selection. Select and review it again.** The ownership wrapper also applies; an obsolete owner can be suppressed without this error. Prepare again from the current file/context if no draft appears; do not assume an earlier selection survived a context change. Moving the selection alone does not replace the captured excerpt; cancel and select again if different text is wanted.

The mounted `App.tsx` callback stores selection plus current desktop context/workspace and navigates to Agent. Agent's request effect waits for an active, available conversation without loading, sending, pending proposal or decision; it rejects a different sign-in/workspace or invalid selection. For ordinary code it selects Inspect / Code Review, chat composer mode, and appends the generated prompt to existing input with a blank line. It does not replace existing input or invoke Send in this path. Review the entire resulting composer, including earlier text. Preparation does not save the editor, execute code, grant target authority or send code to a model. Later Send/provider approval remains a separate boundary; this guide neither exercises nor qualifies it.

## Reviewing more than one diff page (families 24–25)

Open **Review changes** / **Review local changes** for the current loaded file. The mounted unsaved-review call passes `savedContent` as `before`, current `content` as `after`, label **Local unsaved file diff**, and **No unsaved content changes.** as the unchanged message. This compares the draft to the last loaded/saved baseline, not HEAD or the whole repository. Agent proposal call sites also reuse FileDiff; they do not change this editor baseline.

`FileDiff` first computes the shared `createLineDiff` result and addition/removal counts. With no additions/removals it returns the unchanged message. Pagination appears only when the resulting rendered-row array exceeds 2,000 entries, including context and omitted-line markers; it is not a 2,000-file-line or byte threshold. **Previous** / **Previous diff page** decrements the page and is disabled on page one. **Next** / **Next diff page** increments it and is disabled on the last page. The status states the page count and asks review of every page. Each page slices at most 2,000 diff rows. A changed `before` or `after` resets pagination to page one; it does not preserve a review receipt.

Paging changes display state only: no save, approval, undo, network request or operation cancellation occurs. There is no pagination Cancel button. Close the review using its existing toggle; this does not undo edits. If edits change the diff, review again from page one before deliberate Save. The source does not require visiting every page before enabling Save or issue proof that all pages were reviewed.

The diff algorithm retains nearby context and inserts **… unchanged lines …**. Above 300,000 old/new line pairs it uses a coarse common-prefix/suffix comparison. Pagination does not make that comparison a minimal edit sequence. No pending native pagination operation or uncertain write outcome is introduced by these buttons.
