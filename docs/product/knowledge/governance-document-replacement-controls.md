## Current-head metadata and review meaning

The UI shows fixed target name/scope, current saved head version/digest, original last-update time, completeness and recognized fact count. It displays whether the selected historical **content digest** equals the saved head. Equality can also occur after later versions return to the same bytes; it does not make the old snapshot fresh or identify its old version as the current version. The timestamp is not renewed observation time, expiry or provider freshness. `complete` concerns recognized policy clauses, not complete security coverage, compliance, baseline acceptance or activation.

Head response validation binds artifact ID/digest, organization, original target name, exact scope and selected source digest to the deliberately loaded saved artifact. Boolean equality must agree with the two content digests. Metadata version999 remains inspectable but explicitly read-only; no increment1000 or alternative creation path is offered.

The backend reads the stored historical artifact and current head/blob/history in one transaction, checks current reader authority before and after, validates stored bytes/history, and returns metadata/counts only. It does not save a new observation or renew evidence expiry. A valid head-read request with missing, foreign, corrupt or non-document storage refuses generically409; malformed request input400, feature-OFF503, absent desktop session401 and rate-limit429 remain distinct outer gates. Client metadata failure leaves save disabled, with a deliberate-load-again message and no file dispatch.

## CAS, uncertainty and context changes

Upload is a private source-storage write. The server derives tenant/actor/session from current authority, checks policy-management permission, and uses a head compare-and-swap under the existing transaction/lock. A changed head or storage uncertainty is not permission to overwrite. The component holds after any unavailable save result, including a conflict response, and offers only the original lookup; it does not classify every409 as safely unwritten or infer rollback. A validated receipt must match fixed name/scope, exact byte digest and expected next head version.

A confirmed save or original lookup clears parent saved-evidence/facts/selected initial scope and asks for deliberate evidence reload before fact review or a baseline proposal. Source storage is not a baseline proposal, genuine independent review, policy activation, executor enrollment or provider operation. Existing original lookup can confirm the request's history even after the head advances; that does not upgrade the record to current-head authority.

While replacement is busy or held, parent saved-evidence/fact/baseline reads and target/scope controls are disabled or guarded; the parent also prevents source callback replacement from discarding the pending tuple. Replacement is disabled while a parent read is busy. Context revision/config and identity remount ownership checks discard stale responses; active controllers abort on unmount/context switch. This suppresses old-context UI updates and clears private in-memory pending data, not a promise that a dispatched server write was undone. No raw bytes are persisted to localStorage or a restart-recovery store. Closing/restarting/switching context can lose the in-memory lookup tuple; do not promise cross-session recovery.
