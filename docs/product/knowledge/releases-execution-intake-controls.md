## Prepare the intended request

Open a new or revised release intake and reach Execution after recording the source. Workflow discovery needs exactly one explicit HTTPS repository URL on the `github.com` host (this host rule does not distinguish public from private repository visibility) in the repository field, a nonblank source ref and, for reading fields, a supported workflow filename/path. Multiple repository URLs, credentials, query/fragment or a non-GitHub URL do not yield a discovery target. A bare YAML filename is converted to `.github/workflows/<filename>`; a supported full workflow path is also accepted. The separate workflow-source-ref field uses its trimmed value, otherwise the trimmed source branch. A restored observation is used only when its repository/path/ref/blob shape matches. Source keys: `source-selection`, `intake-context`, `intake-mount`.

The controls' local enablement does not establish current membership, an active GitHub installation, Airflow access or provider permissions. Server reads can refuse. Connection setup and grants are outside this guide; use the existing [Settings](settings-workspace-controls.md) and [Batches](batches-airflow-controls.md) guidance. Never reconnect, grant access or rerun a batch merely to make an intake selection available.

Declared-field descriptions/default hints are informational text; a workflow declaring no inputs has an explicit empty state. ## Read requests and finite server refusal boundaries

The selected clients use GET `/api/desktop/github/workflows` and GET `/api/desktop/github/workflow-inputs` with encoded repository/ref and, for fields, path. Both selected routes require a desktop session with `pipeline:read` and disallow API keys; current server identity/access resolution remains authoritative. These handlers may resolve an installation token under an existing tenant connection, but do not return that token or grant a new permission. Invalid source returns 400, missing session 401, unavailable tenant token 409 and unavailable catalogue/schema 502. Source keys: `read-clients`, `catalogue-route`, `definition-route`.

The field route's bounded file read uses a 200,000-byte response cap. Separately, the YAML parser permits at most 100,000 UTF-8 source bytes, uses strict YAML 1.2 with unique keys/no aliases, and bounds declared fields to 25, choice options to 100, and descriptions/options/default text to 2,000 JavaScript string code units. Unsupported types/structures and expression-shaped defaults are refused; this is a finite parser, not all GitHub workflow semantics. The caps refer to different representations and must not be treated as interchangeable. Source keys: `definition-route`, `definition-parser`.

The selected Airflow clients use GET `/api/desktop/airflow/connection` and GET `/api/desktop/airflow/dags/<encoded DAG>/runs`. Their selected GET handlers require `pipeline:read` and `workspace:read`, disallow API keys and use existing server read responders. Adjacent save/disconnect/trigger methods are not used by these intake controls. No current access, credential validity or live observation is established by inspecting these routes. Source keys: `read-clients`, `airflow-connection-route`, `airflow-runs-route`.

## Repair or enter manual workflow inputs

The manual editor appears when no usable definition is selected, or when the input object cannot be parsed. It is disabled by the field reader while that read is pending, and by the enclosing intake fieldset while saving. When a valid definition and object are available, the declared-field interface replaces it. Source keys: `manual-editor`, `definition`, `intake-save`.

| Documentation ID / control | Purpose, steps and result | Limits and safe recovery |
| --- | --- | --- |
| `execution-intake.manual.add` — **Add input** | Adds a blank local row for a workflow input. | Disabled for malformed/non-string-valued JSON. A new blank name creates an issue; no new object is emitted until all row names are valid. Repair the JSON first if disabled. |
| `execution-intake.manual.name` — **Name** | Names the corresponding input row. | Every name must be nonblank, have no leading/trailing spaces and be unique. Invalid row edits remain local while the last valid parent object is retained; advancement is blocked by the issue. |
| `execution-intake.manual.value` — **Value** | Records the row's text value. | Manual values are strings, including empty text. This lane does not discover declared types/defaults or check required provider fields. |
| `execution-intake.manual.remove` — row **Remove** | Removes that local name/value row. | Remaining invalid rows still block emission. Removing a draft row does not delete anything in GitHub. |
| `execution-intake.manual.advanced` — **Advanced JSON** | Expands/collapses the raw editor, with `aria-expanded` state. | Initial invalid input or externally supplied invalid content opens the editor automatically. It is not a separate saved version or approval. |
| `execution-intake.manual.json` — **Advanced workflow inputs JSON** | Edits the parent draft immediately, then reparses it into rows when possible. | Must be a non-array, non-null JSON object containing only string values. Invalid text remains available for repair; existing parent text is not silently discarded. Duplicate object keys follow ordinary JSON parsing and are not a separate duplicate-key detection guarantee. |

An empty valid object shows **No inputs recorded**. Row-name issues and invalid JSON have alerts; field reading remains disabled while the manual issue is reported. Correct the actual recorded text/rows rather than assuming that a previously valid object means current edits are accepted. This source description is not browser/IME/assistive-technology acceptance.

## Record exact required Airflow batches

This panel selects observed run identities as release dependencies. It does not start, rerun, stop or approve a DAG. It does not establish batch success, current freshness, release readiness or release approval. Source keys: `batch-selection`, `batch-schema`, `read-clients`.

| Documentation ID / control | Purpose, steps and result | Prerequisites, limits and recovery |
| --- | --- | --- |
| `execution-intake.batch.connection` — **Read Airflow connection** | Reads current workspace connection metadata. Successful read records its ID/revision and clears displayed runs/current candidate selection. | Disabled during the owned read. Missing/disconnected/invalid metadata clears the active connection and reports unavailable. It does not clear already recorded dependency rows. Re-read deliberately after restoring access. |
| `execution-intake.batch.dag` — **Batch DAG** | Enter the DAG identifier to inspect. Changing text clears the candidate selection. | Disabled during an owned read. Read requests trim the DAG value. This is not a DAG creation or discovery control. |
| `execution-intake.batch.find` — **Find batch runs** | Reads observed runs for that DAG from the active connection. | Requires a verified local connection and nonblank DAG; disabled while busy. Duplicate run IDs, wrong DAG or schema-invalid identities/dates clear observations and report verification failure. A thrown read reports an error; previous observations may remain, so an error is not a freshness confirmation. |
| `execution-intake.batch.select` — **Exact batch run** | Choose one displayed run ID; options also display observed state. | Rendered after an observation for the current key, disabled while busy. An empty returned list leaves only the placeholder. No local success-state filter is applied; state text is not approval. |
| `execution-intake.batch.use` — **Use selected batch** | Appends the exact DAG/run/logical-date tuple to the recorded dependency. | Requires selected run, same connection, no duplicate tuple and fewer than 25 recorded runs; busy also disables the button. The handler additionally refuses a missing logical date. Same-connection rows are retained. |
| `execution-intake.batch.remove` — recorded row **Remove** | Removes that exact DAG/run tuple; removing the last row clears the dependency. | A local draft edit only. This button has no panel-level busy disable, although the enclosing save fieldset can disable it. It does not cancel an Airflow run. |

Selected run identities require bounded nonblank/trimmed IDs, valid timestamp strings, connection revision, unique tuples and at most 25 rows. A changed connection requires removing previously selected batches before using the changed connection. Existing selections whose connection cannot be matched to the currently read one block advancement. Re-reading the connection alone does not silently rebind old dependencies. Displayed observation state and logical date do not replace later readiness/evidence checks.

## Context, saving and recovery

- **Source ownership:** catalogue responses are accepted only for their captured repository/ref/context revision/config object; definition reads additionally bind path and ignore results after their effect cleanup. Changing selection does not cancel a provider read or prove remote quiescence. The catalogue itself has no equivalent unmount-cleanup assertion in this finite source.
- **Batch ownership:** runs are associated with DAG/context/config and connections with context/config/revision. Results whose captured owner no longer matches are ignored. Changing DAG hides the previous run list; recorded dependency rows remain until removed. Some status text or the empty candidate selector may persist across configuration changes; this is not current provider evidence.
- **Advancement:** while fields/batches are loading, or a child reports a manual/declared-input/connection issue, Continue in Execution refuses and shows the issue. Continue also validates the parent's step fields. Final submit checks child issues again, validates every intake step, parses string-valued input JSON and validates deployment-window instants. UI guards do not prove backend admission.
- **Save ownership:** the parent captures its mounted config/revision, refuses duplicate submission/edit updates, disables the whole intake while saving and ignores completion/error state for an old context. It includes workflow inputs, optional matching source observation and optional selected batch dependency in the request payload. Source evidence matching is not a new read or freshness renewal.
- **Outcome:** create saves a workspace request; revise sends the existing request ID/version. Neither action dispatches a workflow or grants independent approval. An unsuccessful response retains the form with its error. An unconfirmed thrown save tells the user to check saved requests before submitting again. Leaving does not cancel a save; there is no automatic resend or guaranteed unsaved-draft recovery across contexts.

Source keys: `catalogue`, `definition`, `batch-selection`, `intake-context`, `intake-payload`, `intake-save`, `intake-navigation`. Parent fieldset/Continue/submit controls are boundaries referenced here, not newly counted imported controls. See the existing Releases guide for subsequent plan/review/execution/evidence paths.
