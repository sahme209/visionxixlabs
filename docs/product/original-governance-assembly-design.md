# Original Axiom Evidence Assembly — selected design

November6,2026. Design/research only, before product code. User now explicitly requests substantial visual improvement using actual Hairline/Teardown and delegates choices; this supersedes the older diagram brief's wait-for-selection instruction. Applied local superpowers:brainstorming, including its opt-out exception. Root reviews this concrete design before implementation. No change to frozen1369/Lab4, native image or emission packet.

## What changes visibly

Replace Product's small flat workflow rail with a large original **Evidence Assembly**: a physical-looking inspection folio, drawn as thin-line rounded solids in isometric depth. Five keyed record plates sit over a grounded base. The rest pose is already slightly separated; the proposal/review gap is the focal point. Each plate has a distinct constructed feature (repository-sheet slots, proposal revision cuts, paired review leaves, separate requester lever recess, three-channel outcome ledger), not five identical generic cards or copied upstream geometry. Labels/readout stay outside the object. Keep canonical Axiom triangle unchanged in existing chrome; do not stamp or redraw it as machinery.

Product:600–680px-wide scene plus a readable record explanation, five stage controls and a quiet Inspect/Assemble toggle. Home: reuse the same component/data with a compact stage beside the existing purpose/CTA block, then retain real media or clearly scripted tour as a separate section below. This is a substantial new focal composition, not another foreground-token adjustment. Demo retains its explicit scripted status; avoid two competing interactive heroes on Product.

Select a record: that plate separates from the folio, its near edge brightens, remaining plates recede, and its record explanation updates. **Inspect** exposes how review and requester intent remain separate; **Assemble** restores the resting stack. Bounded camera angle/orbit may follow a fine pointer only as optional inspection aid; named camera/reset buttons provide the same useful view without dragging. No cursor follower, custom scrolling, automatic traversal or simulated execution.

No look/setup/build command will run under the no-install boundary. Kernel source received a bounded static capability scan (DOM/SVG/events/visibility/frame lifecycle); this is not complete third-party security qualification. No upstream runtime copied/executed yet.

**Teardown — adapt construction/inspection architecture; reject direct runtime adoption for this batch.** Read pinned SKILL/LICENSE/package/paths/build/runtime. Its concrete model→geometry→stage→console separation and shared-state inspection inform the assembly, rather than generic decorative3D. Those defaults do not fit embedded Axiom sections without broader adaptation. Its fixed-size console, automatic tour and “always alive” preference are deliberately replaced with responsive reading, explicit interaction and static reduced motion. No claim that Teardown's WebGL runtime/models were used when only its reviewed technique/architecture is adapted.

## Alternatives and selected implementation

1. Direct Three/Teardown runtime: most literal machine simulation, but adds dependencies, GPU/asset/font work and embeds global behavior. Reject for this bounded website increment.
2. Vendor Hairline kernel and deliver its exact bench figure: genuine upstream engine, but integration/adoption/security review plus bench constraints exceed the current no-package-execution phase. Defer; do not pretend a native figure is this artifact.
3. **Selected: original projected SVG/CSS3D in existing React**, implementing the reviewed Hairline construction discipline and Teardown common-state/exploded-inspection technique. No new dependency, external asset or global handler. If the user's phrase “actual tools” means imported upstream engines rather than these explicitly named adaptations, root must resolve that distinction before claiming fulfillment. Design alone does not satisfy that runtime expectation.

## Single source of visual truth

Pure scene model: selectedStage0–4, view assembled/inspect, bounded camera orientation. `deriveScene(model)` supplies all plate poses/active edge/selected record; both SVG scene and semantic explanation read that same result. No independent timers, fake metrics, account lookups, permission states or inferred reviews. Optional view orientation never advances a stage. Existing five record texts are retained/expanded carefully, including where-supported/current-version limits.

Always-visible caption: “Conceptual illustration · no actions are performed.” Keep installed-version/workflow qualification and incomplete-Governance limits next to the visual. Independent review is not execution. Requester intent is separate. Final ledger presents **confirmed evidence / refused / unknown** as possible categories with equal semantic weight; unknown stays unresolved and routes explanation to read-only records. No green completion chain, fabricated reviewer, signature, connected provider, policy pass or health/rollback guarantee.
