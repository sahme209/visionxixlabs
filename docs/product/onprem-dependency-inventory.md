## Decisions and execution order

1. **Core Governance first.** Finish real executing identity, same-artifact admission and the covered executor paths; retain current refusals while qualification is missing. On-prem architecture does not authorize enrollment or activation.
2. **Separate deployment identity from arbitrary endpoint input.** A customer deployment needs an authenticated, versioned origin/trust configuration spanning browser, native buffered/streaming and computer-authority paths. The current configurable endpoint is only one seam.
3. **Define offline authorities before adapters.** Tenant, execution/source identity, real reviewer identities, locally current source/evidence, entitlement policy, key custody and audit retention must have explicit owners and recovery rules. Hosted credentials or cached old approvals cannot substitute.
4. **Specify the orchestrator contract, then migrate Airflow.** Preserve existing behavior. Test Airflow and Temporal against the same contract and document a real custom adapter. Report unsupported capabilities instead of simulating them.
5. **Prepare reproducible disconnected delivery.** Pin application, Node/native/runtime, database/schema, model, engine and operating prerequisites; include licenses and signed provenance. Define upgrade/rollback compatibility and customer backup/restore before claiming an installation package.
6. **Qualify the complete system, not isolated components.** A real customer-controlled installation must complete a governed deployment with internet connectivity disabled, with audit integrity, approvals, rollback and recovery evidence. Simulated provider/engine tests and successful local builds remain explicitly narrower evidence.

## Remaining verification

This inventory does not enumerate every network call, webhook/email path, telemetry/library default or deployment lifecycle. Before A9 acceptance, perform an owned full-process egress/dependency exercise covering startup, sign-in/recovery, discovery, approval, execution, evidence, export and updates. Resolve every observed dependency through a reviewed local authority/adapter or explicit unsupported feature. No on-prem migration, endpoint relaxation, infrastructure purchase, schema operation or provider run is approved here.
