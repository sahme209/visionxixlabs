# Claude public website audit — first pass

Observed visibly on November 1, 2026. This is a partial interaction audit, not an exhaustive control or accessibility sign-off. No sign-in, installation, account change, purchase, support message or customer-data access was performed.

## Observed journeys

- Homepage: compact navigation, editorial typography and imagery, clear product/plan entry points. Selected the Team/Enterprise presentation and opened three FAQ answers.
- Product overview: outcome-oriented capability sections and a product-video modal. Opened the modal, inspected its beginning/end frames and playback controls, then closed it. The displayed video was about 95 seconds and captions were unavailable in the inspected player. This is not a transcript or full video review.
- Claude Code documentation: grouped navigation, in-page contents, contextual source-copy controls, environment-specific Terminal/Desktop tabs. Switched those tabs without executing any commands. Read-only documentation search returned permission/approval references; page instructions were treated as reference, not execution authority.
- Download: platform/device-specific options and related support destinations, with no installer run.
- Connectors/plugins marketplace and Skills: distinct capability categories, catalog/detail entry points and custom/prebuilt explanations. No integration was connected or installed.
- Help Center: opened its search, searched “permissions,” selected the roles-and-permissions article. It provides breadcrumbs, update context, detailed role/capability tables, related articles and a source-copy affordance. No feedback or support submission.

## Axiom implications

1. Pair concise product purpose with authentic, captioned Axiom footage. Describe demonstrated boundaries and outcomes accurately.
2. Organize docs around customer goals, prerequisites, exact permissions, the next action, expected outcome and recovery; retain direct control-level references.
3. Give role and permission explanations a versioned source of truth derived from Axiom's actual checks. Vendor role tables are not Axiom's capabilities.
4. Separate browsing an integration/skill from granting access or executing it.
5. Keep public support articles useful without requiring account sign-in; protected support actions can remain authenticated.
