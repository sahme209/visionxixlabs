# ECS restart receipt correctness

This source-only milestone preserves the installed four-input ECS workflow and authorized restart dispatch behavior. No workflow, schema, credentials, provider actions or production state changed.

The bundled template restarts the existing service task definition. Installed workflow contents are not attested by a filename. Current execution rows persist neither protocol nor artifact evidence, so serialized historical records report `evidence.operation: unknown` and false source-artifact, application-health and rollback-image verification. Actual four-input dispatch/preflight paths add server-owned `requestedOperation: service_restart`: intent, not certification of installed execution. Raw GitHub workflow conclusion is retained separately and never converted into image or health proof.

Agent proposal/tool instructions, dispatch and replay responses, execution lists, desktop preflight/dispatch, Airflow receipts, dashboard dispatch and observation audits expose these limits. The shared GitHub exact-run observer no longer calls completed rollback steps recovery success/failure: the bundled rollback script deliberately exits 1 even after restoration, and custom step names/conclusions cannot prove image recovery. In-progress/skipped/unknown workflow-step information remains available.

The shared branch-policy guard accepts a server-owned legacy ECS capability flag from actual ECS callers. A supplied promotion or promotion-required policy fails with `branch_policy_promotion_artifact_unverified` before reservation/dispatch; a successful same-source prior workflow is insufficient. Explicit desktop emergency bypass cannot turn a restart into artifact promotion. Ordinary authorized no-promotion restarts preserve tenant, high-risk approval, branch checks, quota reservation, idempotency and uncertain-outcome handling. Generic policy callers retain existing semantics; this is not a global claim that every provider uses ECS. Emergency desktop deploy/preflight and the dashboard legacy release endpoint also read the applicable tenant/environment promotion policy before side effects; omitting a prior execution ID cannot evade this requirement. Emergency branch/CI bypass semantics remain separate. The dashboard compares its default-branch, release-tag and recorded-commit references conservatively, since its old ref contract is ambiguous. Storage failures deny rather than silently skip this check.

Remaining work is documented in `ECS_IMMUTABLE_RELEASE_PLAN.md`: durable verified artifact/provenance, approved target/baseline binding, separate versioned workflow, real health/recovery receipts, and separately authorized sandbox acceptance. Dashboard full branch/CI/approval/quota parity is not established, and lifecycle eligibility is still transitioned after dispatch; these remain separate correctness dependencies; this patch does not claim to close that transaction boundary. No current successful restart is accepted as a verified source/artifact release or image rollback.

Behavioral regression coverage includes actual policy evaluation denying successful same-SHA restart promotion, normal four-input Agent dispatch with explicit evidence, historical success/rollback rows retaining unknown proof, desktop emergency promotion denied before quota/provider work, and opaque rollback-step completion remaining unknown. These are local composed/provider-mocked tests, not live AWS acceptance.
