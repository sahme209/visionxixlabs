# Owned local website visual verification protocol

Status: source-only candidate for independent review. No server, browser, external request, preview or production deployment has run from this harness. The previously reviewed UI commit is c5c2577df862602b8706bcac5b442bb61d50ceb2; its whole-web TypeScript check passed with an 8192 MiB heap before these fixture-only files were added.

## Entry and ownership

The coordinator reviews a clean source commit and the source-only tests before any launch. `scripts/run-owned-website-visual.mjs --prepare /tmp/axiom-website-review-<id>.json` only captures the clean commit, pinned framework identity, executable hashes and hashes of every launch/guard/capture script. It creates no listener or process. Execution requires an explicit `--execute-reviewed` invocation with that manifest path and its reviewed SHA-256; preparation is not launch authorization.

The trusted parent spawns one fixed Next Node entry, the installed Chromium ELF and the fixed manifest-pinned capture driver, each in a new process group. Every returned handle enters a pending ledger synchronously before logging, awaiting spawn or reading `/proc`. Registration records canonical executable, PID, group and `/proc` start identity; a failed registration never grants signalling authority. Cleanup checks those identities and every group member before signalling, escalates only within those owned groups after five seconds, and verifies the groups are empty. It never scans for or kills unrelated Next processes. Failed ownership checks retain artifacts and fail completion. Every spawned handle requires a positive exit event plus an empty process group (or a spawn failure with no PID); registration failure cannot certify cleanup. Unregistered live children remain recorded and prevent artifact deletion, without unsafe signalling. The parent window is bounded to five minutes, server readiness to 150 seconds and the capture driver to an absolute 120 seconds covering configuration, HTTP, WebSocket setup and commands. The parent additionally waits for the owned driver’s positive exit (125-second allowance), not merely its receipt. The child has its own five-minute expiry. Output logs are capped at 512 KB per owned process; a five-second disk poll stops the run after 400 MiB across the owned profile/dist/output trees (a polling bound, not a filesystem quota).

The dist directory is a unique ignored `.next/visual-*` child. Only that child is deleted. No existing `.next` root or output is deleted. The temporary TypeScript config extends the exact tracked `tsconfig.next.json` so Next's generated include updates do not alter tracked config. Ignored generated `next-env.d.ts`, if created, is retained and reported rather than removed without provenance. Profile, HOME, XDG directories and TMPDIR are private per run. Tracked source equality is checked at exit.

## Framework exception and application boundary

`ownedWebsiteFramework.cjs` adapts the reviewed Agent helper's exact four source pins and six cached dependency pins, canonical Node executable hash/version/platform/architecture checks, placement before Next consumers, sole `useTypeScriptCli` default true-to-false change, explicit override precedence and restoration. Its purpose is explicitly `owned-website-visual`, role `website-server`; Agent context is refused. Every report says `productionEquivalent:false` and `owned-website-typescript-api`. No Agent fixture mode or permission is borrowed.

The child first binds exactly its random, parent-selected loopback port with an empty preparation response. It installs the deny-all guard before importing Next or application code, then loads the actual pinned Next config, overriding only the owned distDir and the temporary extending TypeScript config path. All outgoing fetch/HTTP/HTTPS/socket/TLS/DNS/UDP calls, new listeners, subprocesses and Workers are denied. Lower native TCP/pipe/DNS/process entry points also block previously captured public functions. This is a trusted Node process guard; it does not claim containment of arbitrary native code, addons or operating-system calls. No unsupported worker/subprocess is automatically granted: startup fails and needs a separately reviewed correction.

Only GET/HEAD `/`, `/product`, `/docs/approval-workflow`, enumerated local public files, Next static chunks and tightly limited local-image optimization requests reach Next. All API routes, mutations, CONNECT, upgrades and alternate pages are refused before application dispatch. The server's HMR transport is intentionally unavailable. No database, model, provider or real authentication action is needed for these captures. Ambient `.env` files cause preflight refusal. Child environments use a small allowlist retaining supported managed proxy/CA selectors opaquely, including `NODE_USE_ENV_PROXY`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE` and `AWS_CA_BUNDLE`, then fixed fixture flags/private paths; provider credentials/configuration are absent. Unsupported inherited Node options/preloads/CLI arguments, trust overrides and linker settings refuse before any subprocess rather than being silently removed. Only heap-size Node options are accepted; unsupported guard configuration requires a separate review, never bypass. This website-specific adaptation follows the frozen billing `newTestChildEnvironment.ts` at b7ff/781, SHA-256 `3bec9efa59f74176884354ed133307df37c374b923b266d95a83c512e9ac82b0`; its Vitest preload exception is not borrowed. AWS credential files are `/dev/null` and metadata discovery is disabled.

## Browser and capture boundary

Chromium has a private profile, loopback-only CDP and a browser-specific owned loopback HTTP proxy. Its default loopback proxy bypass is disabled. The proxy allows only the same fixed local GET/HEAD page/asset policy and strips incoming credentials and unneeded headers. CONNECT, WebSockets, external destinations and all mutations are refused. QUIC, DNS resolution except the literal loopback address, background networking, extensions and sync are disabled. Managed global proxy/CA configuration is not changed; no certificate verification bypass is added. Chromium's `--no-sandbox` is explicit, so this is not an OS/browser sandbox claim. CDP interception supplies an additional per-request deny boundary, not the primary outbound policy.

The parent launches only the fixed `scripts/capture-owned-website.mjs <owned directory>` after registration and listener proof. Before any CDP HTTP/WebSocket connection and again before every command, the driver verifies a unique exact IPv4 loopback TCP LISTEN inode is present in the recorded Chromium leader’s descriptors, with stable PID/start/group/executable before and after inspection. Wildcard/IPv6 collisions, foreign inode ownership, permission failures and PID reuse refuse without probing that endpoint. This is repeated read-only ownership evidence, not an atomic OS capability or arbitrary native sandbox. The driver also checks the manifest-bound capture bytes and exact CDP origin. It renders the real homepage, product page and linked documentation. It exercises playback, keyboard/branch selection, sample decisions, replay, offscreen/hidden-tab pausing, Terraform's held state, 360-pixel overflow and reduced motion. It captures at most eight PNGs, each at most 1440×2400 and 8 MiB, with a combined 24 MiB cap. The current sequence requests six captures. Runtime exceptions and blocked request counts remain evidence, not silently claimed clean.

The absolute deadline or socket close rejects every pending operation, closes the socket and prevents new commands/screenshots; the final nonce-bound receipt is the only post-stop output. Setup failures after validating the directory/nonce also write failure receipts. After final evidence writes, the fixed owned driver exits explicitly so an incomplete WebSocket close handshake cannot outlive the window. The driver writes a nonce-bound success/failure receipt; the parent requires success before reporting driver completion. Completion still does not mean visual acceptance: the coordinator must inspect every captured image and report any clipping, missing assets, console errors or font fallback. Since external font requests are denied, actual Next/font fallback behavior must be recorded. These are integrated local website screenshots, never native desktop/provider screenshots or proof of production login, cloud health, rollback, customer acceptance or a production-equivalent runtime.
