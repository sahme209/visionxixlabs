# Owned local website visual verification protocol

Status: source-only candidate for independent review. No server, browser, external request, preview or production deployment has run from this harness. The previously reviewed UI commit is c5c2577df862602b8706bcac5b442bb61d50ceb2; its whole-web TypeScript check passed with an 8192 MiB heap before these fixture-only files were added.

## Entry and ownership

The coordinator reviews a clean source commit and the source-only tests before any launch. `scripts/run-owned-website-visual.mjs --prepare /tmp/axiom-website-review-<id>.json` only captures the clean commit, pinned framework identity, executable hashes and hashes of every launch/guard/capture script. It creates no listener or process. Execution requires an explicit `--execute-reviewed` invocation with that manifest path and its reviewed SHA-256; preparation is not launch authorization.

The trusted parent spawns one fixed Node entry and the installed Chromium ELF, each in a new process group. The parent records canonical executable, PID, group and `/proc` start identity. Cleanup checks those identities and every group member before signalling, escalates only within those owned groups after five seconds, and verifies the groups are empty. It never scans for or kills unrelated Next processes. Failed ownership checks retain artifacts and fail completion. The parent window is bounded to five minutes, server readiness to 150 seconds and the capture driver to 120 seconds. The child has its own five-minute expiry. Output logs are capped at 512 KB; a five-second disk poll stops the run after 400 MiB across the owned profile/dist/output trees (a polling bound, not a filesystem quota).

The dist directory is a unique ignored `.next/visual-*` child. Only that child is deleted. No existing `.next` root or output is deleted. The temporary TypeScript config extends the exact tracked `tsconfig.next.json` so Next's generated include updates do not alter tracked config. Ignored generated `next-env.d.ts`, if created, is retained and reported rather than removed without provenance. Profile, HOME, XDG directories and TMPDIR are private per run. Tracked source equality is checked at exit.

## Framework exception and application boundary

`ownedWebsiteFramework.cjs` adapts the reviewed Agent helper's exact four source pins and six cached dependency pins, canonical Node executable hash/version/platform/architecture checks, placement before Next consumers, sole `useTypeScriptCli` default true-to-false change, explicit override precedence and restoration. Its purpose is explicitly `owned-website-visual`, role `website-server`; Agent context is refused. Every report says `productionEquivalent:false` and `owned-website-typescript-api`. No Agent fixture mode or permission is borrowed.

The child first binds exactly its random, parent-selected loopback port with an empty preparation response. It installs the deny-all guard before importing Next or application code, then loads the actual pinned Next config, overriding only the owned distDir and the temporary extending TypeScript config path. All outgoing fetch/HTTP/HTTPS/socket/TLS/DNS/UDP calls, new listeners, subprocesses and Workers are denied. Lower native TCP/pipe/DNS/process entry points also block previously captured public functions. This is a trusted Node process guard; it does not claim containment of arbitrary native code, addons or operating-system calls. No unsupported worker/subprocess is automatically granted: startup fails and needs a separately reviewed correction.

Only GET/HEAD `/`, `/product`, `/docs/approval-workflow`, enumerated local public files, Next static chunks and tightly limited local-image optimization requests reach Next. All API routes, mutations, CONNECT, upgrades and alternate pages are refused before application dispatch. The server's HMR transport is intentionally unavailable. No database, model, provider or real authentication action is needed for these captures. Ambient `.env` files cause preflight refusal. Child environments are built from a small allowlist retaining managed proxy/CA settings, then fixed fixture flags/private paths; credentials, arbitrary Node options, linker injection and provider configuration are absent. AWS credential files are `/dev/null` and metadata discovery is disabled.

## Browser and capture boundary

Chromium has a private profile, loopback-only CDP and a browser-specific owned loopback HTTP proxy. Its default loopback proxy bypass is disabled. The proxy allows only the same fixed local GET/HEAD page/asset policy and strips incoming credentials and unneeded headers. CONNECT, WebSockets, external destinations and all mutations are refused. QUIC, DNS resolution except the literal loopback address, background networking, extensions and sync are disabled. Managed global proxy/CA configuration is not changed; no certificate verification bypass is added. Chromium's `--no-sandbox` is explicit, so this is not an OS/browser sandbox claim. CDP interception supplies an additional per-request deny boundary, not the primary outbound policy.

The separately invoked `scripts/capture-owned-website.mjs <owned directory>` checks the current process identities, manifest-bound capture bytes and exact CDP origin before connecting. It renders the real homepage, product page and linked documentation. It exercises playback, keyboard/branch selection, sample decisions, replay, offscreen/hidden-tab pausing, Terraform's held state, 360-pixel overflow and reduced motion. It captures at most eight PNGs, each at most 1440×2400 and 8 MiB, with a combined 24 MiB cap. The current sequence requests six captures. Runtime exceptions and blocked request counts remain evidence, not silently claimed clean.

The driver writes a nonce-bound success/failure receipt; the parent requires success before reporting driver completion. Completion still does not mean visual acceptance: the coordinator must inspect every captured image and report any clipping, missing assets, console errors or font fallback. Since external font requests are denied, actual Next/font fallback behavior must be recorded. These are integrated local website screenshots, never native desktop/provider screenshots or proof of production login, cloud health, rollback, customer acceptance or a production-equivalent runtime.
