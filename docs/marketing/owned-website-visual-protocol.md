## Entry and ownership

The coordinator reviews a clean source commit and the source-only tests before any launch. `scripts/run-owned-website-visual.mjs --prepare /tmp/axiom-website-review-<id>.json` only captures the clean commit, pinned framework identity, executable hashes and hashes of every launch/guard/capture script. It starts no service, server or browser; its source checks use bounded local git reads. Execution requires an explicit `--execute-reviewed` invocation with that manifest path and its reviewed SHA-256; preparation is not launch authorization.

The trusted supervisor spawns one fixed Next Node entry, one fixed private-config proxy child, the installed Chromium ELF and the fixed manifest-pinned capture driver, each in a new process group. Every returned handle enters a pending ledger synchronously before logging, awaiting spawn or reading `/proc`. Pending, registered and exited states (including capture role/PID) are synchronously written to a nonce-bound ledger before launch progresses, using a bounded 64 KiB/four-child flushed temporary file and atomic rename. Persistence failures cancel the supervisor, preserve in-memory ownership, retain artifacts and prevent clean completion. Registration records canonical executable, PID, group and `/proc` start identity; a failed registration never grants signalling authority. Cleanup reads `/proc/<pid>/stat` first and inspects executable metadata only for live members of the exact owned group, rechecking PID/group/start after that read. Unrelated protected executables are never inspected; unreadable relevant metadata or stat of unknown relevance still refuses. Cleanup checks those identities and every group member before signalling, escalates only within those owned groups after five seconds, and verifies the groups are empty. It never scans for or kills unrelated Next processes. Failed ownership checks retain artifacts and fail completion. Every spawned handle requires a positive exit event plus an empty process group (or a spawn failure with no PID); registration failure cannot certify cleanup. Unregistered live children remain recorded and prevent artifact deletion, without unsafe signalling. The parent active window is bounded to five minutes before identity-checked cleanup, server readiness to 150 seconds and the capture driver to an absolute 120 seconds covering configuration, HTTP, WebSocket setup and commands. The parent additionally waits for the owned driver’s positive exit (125-second allowance), not merely its receipt. The child has its own five-minute expiry. Output logs are capped at 512 KB per owned process; a five-second disk poll stops the run after 400 MiB across the owned profile/dist/output trees (a polling bound, not a filesystem quota).

Coordinator SIGINT/SIGTERM handlers are installed before any execution-path subprocess. The first signal and failure are preserved; repeated signals do not bypass cleanup. Cancellation immediately wakes registration, readiness and driver waits, prevents further launches and forces a failed signal-status receipt even if capture had completed. On entering cleanup, the supervisor first stops and awaits the owned proxy through the same identity-checked ledger path, before waiting for capture, browser or Next cleanup. The proxy sets its stopping flag before closing connections/listener; its request handler refuses further forwarding once that flag is set. Signal delivery crosses a process boundary, so this is not instantaneous cancellation of forwarding: requests may proceed until the child receives shutdown. If identity or exit cannot be verified, cleanup records failure and retains artifacts rather than claiming admission closure. Cleanup itself is not cancelled: pending registration gets at most two seconds to establish identity, then closes its registration window; unresolved handles retain artifacts and cannot later become certified owners. Existing owned-group stop/exit bounds still apply. Handlers remain installed through cleanup and result writing, then are removed. SIGKILL, native crashes and host termination cannot execute JavaScript cleanup; there is no universal OS cleanup guarantee or extra watchdog process.

The dist directory is a unique ignored `.next/visual-*` child. Only that child is deleted. No existing `.next` root or output is deleted. The temporary TypeScript config extends the exact tracked `tsconfig.next.json` so Next's generated include updates do not alter tracked config. Ignored generated `next-env.d.ts`, if created, is retained and reported rather than removed without provenance. The explicit Chromium --user-data-dir profile, XDG directories and TMPDIR are private per run. Current integration source preserves inherited HOME exactly, including an empty string, or leaves HOME absent when absent; it does not mutate the parent environment or assign a synthetic HOME. Historical 1f21b4e3 and its three attempt records used the prior synthetic HOME policy and are preserved unchanged. This later source correction has not been browser-executed. HOME and accessible filesystem credentials are not isolated by these environment choices; the existing AWS config/credential paths remain /dev/null and all transport/process guards remain unchanged. Tracked source equality is checked at exit.
