## Entry and ownership

The coordinator reviews a clean source commit and the source-only tests before any launch. `scripts/run-owned-website-visual.mjs --prepare /tmp/axiom-website-review-<id>.json` only captures the clean commit, pinned framework identity, executable hashes and hashes of every launch/guard/capture script. It starts no service, server or browser; its source checks use bounded local git reads. Execution requires an explicit `--execute-reviewed` invocation with that manifest path and its reviewed SHA-256; preparation is not launch authorization.

The trusted supervisor spawns one fixed Next Node entry, one fixed private-config proxy child, the installed Chromium ELF and the fixed manifest-pinned capture driver, each in a new process group. Every returned handle enters a pending ledger synchronously before logging, awaiting spawn or reading `/proc`. Pending, registered and exited states (including capture role/PID) are synchronously written to a nonce-bound ledger before launch progresses, using a bounded 64 KiB/four-child flushed temporary file and atomic rename. Persistence failures cancel the supervisor, preserve in-memory ownership, retain artifacts and prevent clean completion. Registration records canonical executable, PID, group and `/proc` start identity; a failed registration never grants signalling authority. Cleanup reads `/proc/<pid>/stat` first and inspects executable metadata only for live members of the exact owned group, rechecking PID/group/start after that read. Unrelated protected executables are never inspected; unreadable relevant metadata or stat of unknown relevance still refuses. Cleanup checks those identities and every group member before signalling, escalates only within those owned groups after five seconds, and verifies the groups are empty. It never scans for or kills unrelated Next processes. Failed ownership checks retain artifacts and fail completion. Every spawned handle requires a positive exit event plus an empty process group (or a spawn failure with no PID); registration failure cannot certify cleanup. Unregistered live children remain recorded and prevent artifact deletion, without unsafe signalling. The parent active window is bounded to five minutes before identity-checked cleanup, server readiness to 150 seconds and the capture driver to an absolute 120 seconds covering configuration, HTTP, WebSocket setup and commands. The parent additionally waits for the owned driver’s positive exit (125-second allowance), not merely its receipt. The child has its own five-minute expiry. Output logs are capped at 512 KB per owned process; a five-second disk poll stops the run after 400 MiB across the owned profile/dist/output trees (a polling bound, not a filesystem quota).

Coordinator SIGINT/SIGTERM handlers are installed before any execution-path subprocess. The first signal and failure are preserved; repeated signals do not bypass cleanup. Cancellation immediately wakes registration, readiness and driver waits, prevents further launches/proxy forwarding and forces a failed signal-status receipt even if capture had completed. Cleanup itself is not cancelled: pending registration gets at most two seconds to establish identity, then closes its registration window; unresolved handles retain artifacts and cannot later become certified owners. Existing owned-group stop/exit bounds still apply. Handlers remain installed through cleanup and result writing, then are removed. SIGKILL, native crashes and host termination cannot execute JavaScript cleanup; there is no universal OS cleanup guarantee or extra watchdog process.

The dist directory is a unique ignored `.next/visual-*` child. Only that child is deleted. No existing `.next` root or output is deleted. The temporary TypeScript config extends the exact tracked `tsconfig.next.json` so Next's generated include updates do not alter tracked config. Ignored generated `next-env.d.ts`, if created, is retained and reported rather than removed without provenance. Profile, HOME, XDG directories and TMPDIR are private per run. Tracked source equality is checked at exit.

## Browser and capture boundary

Chromium has a private profile, loopback-only CDP and a browser-specific owned loopback HTTP proxy. The proxy now runs in a fixed, manifest-pinned child with only the existing private config and literal app/proxy endpoints; it imports no application, provider or process-launch code and accepts no generic IPC/command capability. The launcher is its external supervisor and directly owns every service child; the fixed proxy source creates no descendants. The supervisor opens no HTTP listener. A proxy crash or unexpected Next/browser exit immediately cancels the driver wait and runs the same identity-checked cleanup of all direct-child handles. Its default loopback proxy bypass is disabled. The proxy allows only the same fixed local GET/HEAD page/asset policy and strips incoming credentials and unneeded headers. CONNECT, WebSockets, external destinations and all mutations are refused. QUIC, DNS resolution except the literal loopback address, background networking, extensions and sync are disabled. Managed global proxy/CA configuration is not changed; no certificate verification bypass is added. Chromium's `--no-sandbox` is explicit, so this is not an OS/browser sandbox claim. CDP interception supplies an additional per-request deny boundary, not the primary outbound policy. Each owned proxy connection/CONNECT/upgrade socket, client request/response and upstream request/response has scoped reset/error/abort/close handling that idempotently closes only its associated streams and prevents late writes. Supervisor-owned child stdout/stderr errors cancel the run. There is no global uncaught-exception swallow or continuing a failed transport; uncaught proxy errors terminate that child and are observed externally. A native crash/SIGKILL of the supervisor still cannot promise universal cleanup.

The parent launches only the fixed `scripts/capture-owned-website.mjs <owned directory>` after registration and listener proof. Before any CDP HTTP/WebSocket connection and again before every command, the driver verifies a unique exact IPv4 loopback TCP LISTEN inode is present in the recorded Chromium leader’s descriptors, with stable PID/start/group/executable before and after inspection. Wildcard/IPv6 collisions, foreign inode ownership, permission failures and PID reuse refuse without probing that endpoint. This is repeated read-only ownership evidence, not an atomic OS capability or arbitrary native sandbox. The driver also checks the manifest-bound capture bytes and exact CDP origin. It renders the real homepage, product page and linked documentation. It exercises playback, keyboard/branch selection, sample decisions, replay, offscreen/hidden-tab pausing, Terraform's held state, 360-pixel overflow and reduced motion. It captures at most eight PNGs, each at most 1440×2400 and 8 MiB, with a combined 24 MiB cap. The current sequence requests six captures. Runtime exceptions and blocked request counts remain evidence, not silently claimed clean.

The absolute deadline or socket close rejects every pending operation, closes the socket and prevents new commands/screenshots; the final nonce-bound receipt is the only post-stop output. Setup failures after validating the directory/nonce also write failure receipts. After final evidence writes, the fixed owned driver exits explicitly so an incomplete WebSocket close handshake cannot outlive the window. The driver writes a nonce-bound success/failure receipt; the parent requires success before reporting driver completion. Completion still does not mean visual acceptance: the coordinator must inspect every captured image and report any clipping, missing assets, console errors or font fallback. Since external font requests are denied, actual Next/font fallback behavior must be recorded. These are integrated local website screenshots, never native desktop/provider screenshots or proof of production login, cloud health, rollback, customer acceptance or a production-equivalent runtime.
