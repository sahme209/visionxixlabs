# Native desktop credential backend readiness

## Confirmed defect and change

The pinned keyring 3.6.3 crate explicitly has no default native features. Its source selects the entry-local mock backend on macOS, Windows and Linux when platform features are absent (`src/lib.rs` platform cfgs; `src/mock.rs` documents that mock values do not persist). The previous bare `keyring = "3"` declaration and lockfile containing only keyring's `log`/`zeroize` dependencies therefore did not configure durable storage. A successful mock write is not proof of persistence, even inside a compiled native package.

Target-specific Cargo dependencies now select:

- macOS: `apple-native` (Keychain).
- Windows: `windows-native` (Credential Manager).
- Linux: `sync-secret-service`, `crypto-rust`, `vendored` (persistent desktop Secret Service using vendored libdbus). This deliberately avoids session-only Linux keyutils and does not require a separately installed libdbus development package to compile. An actual unlocked Secret Service session is still required at runtime.

The native storage entry boundary rejects the mock builder before reading a legacy value or writing/removing a credential. Tests inspect builder types and reject the mock without connecting to any OS vault. The Cargo lockfile is regenerated by Cargo, preserving keyring 3.6.3.

## Existing upgrade behavior and risk

The existing legacy migration code is retained: native read first, then legacy lookup only when no native entry exists, native write, and only then legacy deletion/save. Native write errors return before legacy deletion. This patch does not run migration, read a user's credentials, delete stored data or access a native vault.

Earlier builds may have reported successful entry-local mock writes and removed a legacy value. Missing persisted credentials cannot be reconstructed from source or an account email. Recover through an authorized new browser pairing or a verified administrator recovery key; never manufacture a token, grant privileges, clear unrelated credentials or restore obsolete plaintext automatically. Legacy cleanup failure and partially written session token/metadata remain separate recovery risks.

## Acceptance gates

Backend selection tests and compilation verify configuration, not actual Keychain/Credential Manager/Secret Service acceptance. Before release, on each supported target: install the exact signed artifact, pair with a permitted isolated account, restart the process and verify durable hydration, deny/lock vault access and verify safe recovery without legacy deletion, exercise an authorized legacy fixture upgrade, and explicitly sign out/restart to verify deletion. Preserve required commercial/pilot entitlement and workspace identity checks throughout.

A clean macOS host and an authorized website/provider account are needed for real Keychain and browser pairing acceptance. Linux CI without an unlocked Secret Service may compile/test builder selection but must not claim a successful vault write. No production database, cloud infrastructure, credentials, routing, billing or installer publication is authorized by this source change.
