# Checked ECS provider/context inputs — bounded implementation plan

Approved scope: an inactive, server-only read composition. This is the FIRST input prerequisite for the later immutable executor design. It does not admit an execution, create a packet, claim durable authority, manufacture ReviewFacts, establish a reviewed executor/runtime closure, consume quota or approve a deployment. No route, workflow, catalog entry, trust default, schema/dependency change or provider mutation is included.

## Result and authority

The API accepts only cloned bounded selectors (repository/environment/connection/task-definition identities and exact expected build binding), plus a paired principal supplied by server context. Server options supply Prisma, explicit reviewed trust and download policy; callers cannot supply authority callbacks, credentials, endpoints, policy facts, roots or provider observations. Existing canonical Github installation token resolution and scoped AWS credential decryption remain the production paths.

A read-only bounded Serializable transaction captures session issued/expiry/revocation and principal identity, accepted owner/admin membership and current connections:manage capability, exact tenant Github repository, active deterministic installation including account type/selection, selected approval policy and all enabled branch policies (maximum100), allowed non-production environment tier, and existing target/connection/credential metadata through the v3 snapshot projector. Ciphertext and heartbeat timestamps are excluded. Selected policy digest comes from this transaction, never a request field.

The existing Github reader continues its exact metadata/crypto/context checks. Its success adds a precisely versioned checked-binding record retaining only the already verified source ref/workflow path and canonical current snapshot digest. Existing pure crypto verifier semantics and reusable/direct trust profiles remain unchanged. The actual AWS reader retains its canonical AEAD/current-authority/version fences. Both accept an optional parent abort signal without relaxing their30s/45s limits. Common composition lifetime is60s; final delivery requires identical complete context and explicit server trust/download configuration before/after IO, unexpired session, equal inner Github snapshot digest and equal AWS target/connection identities. No build proof can carry across repository/environment/session/config contexts.

The result union distinguishes `checked_provider_context_inputs` with exact subject coverage from `checked_provider_inputs_subject_mismatch`. Both contain independently checked evidence only; the mismatch explicitly says `not_usable_for_admission`. Matched coverage says `inputs_only`, never ready/authorized. Exact set comparison includes every OCI subject name AND sha256 against the observed proposed task image set. Genuine GHCR provenance cannot cover ECR by aliasing. Source ref is retained from actual verification; no caller ref or raw post-await value is substituted. Policies are returned as current context, not asserted to have satisfied PR/tests/codeowner/ticket/promotion facts. This slice makes no full matcher claim without an actual reviewed executor.

## Deferred requirements stay mandatory

The parent executor design remains mandatory later: real immutable reviewed runtime/action closure, full matching and policy-fact proof, durable transactional claim/quota/review-voter/current-target/GitHub-OIDC/run binding, append-only attempts/events, replay/recovery/uncertainty semantics, owned deployment stabilization and health, rollback ownership checks, and explicit external-writer race handling. This input reader supplies none of those permissions and cannot activate them.
